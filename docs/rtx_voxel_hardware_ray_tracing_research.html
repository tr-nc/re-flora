Deep-module seam

为什么基线并未启用 hardware RT

固定基线虽有 crates/re-flora-vkn/src/rtx/acceleration_structure::{build_or_update_blas, build_tlas, AccelStruct}，但 production 没有 caller；device 只额外请求 deferred-host-operations，没有请求 AS/ray-query/ray-pipeline 扩展和 feature chain；默认 descriptor pool 也没有 AS descriptor。类型名和 dead helper 不是 dispatch 证据。Khronos 将这些能力定义为需显式启用的扩展，并要求 shader 执行 traversal 指令：Vulkan Guide — Ray Tracing、Vulkan Ray Traversal。

AABB false candidates
2.1–80.1%

实测候选拒绝率很高，但最终 false hit 为 0；这正是 broad phase + exact intersection 的职责分工。

Vulkan 允许实现扩大 AABB bounds，因此会向应用返回 conservative false-positive candidate；规范随后要求应用验证 AABB candidate，只报告真实几何范围内的 hit。ray query 的 candidate 与 committed 状态相互独立：candidate determination、AABB confirmation。

Update / compaction / synchronization

  • Vulkan UPDATE 不能改变 geometry、instance、primitive 数或 active/inactive 状态；本实验清空一个宏块后 primitive count 减一，所以明确执行 BLAS BUILD + TLAS BUILD。Vulkan AS Update Rules
  • 固定槽位的 degenerate AABB 可在 update 中变化，但 degenerate AABB 仍可能调用 intersection shader；它把 topology 成本换成常驻 traversal 成本。Inactive / Degenerate Primitives
  • BLAS 必须在引用它的 TLAS 使用期间有效，build scratch/input 只能在完成并正确同步后复用。Building Acceleration Structures
  • compaction 需要 size query、copy、同步和延迟释放；NVIDIA 认为更适合不常 rebuild 的 BLAS，因此本轮 editable synthetic BLAS 不做。NVIDIA AS Compaction

Default-off 的真实 hardware experiment

选择 inline ray query 是为了用最小改动回答 AABB candidate 争议。Khronos 指出 ray query 可在更广 shader stage 使用，但显式 traversal code 也可能限制驱动调度优化；结果不能外推为 ray-tracing pipeline 上限：Khronos Ray Query。

Capability proof

device.rs 仅在 feature-on 请求 VK_KHR_acceleration_structure、VK_KHR_ray_query、deferred-host-operations，并把 AS/ray-query feature 链到 device create。build_aabb_blas_profiled / build_tlas_profiled 调用 vkCmdBuildAccelerationStructuresKHR；Slang shader 声明 RaytracingAccelerationStructure 并执行 TraceRayInline/Proceed/CommitProceduralPrimitiveHit。

Default boundary

feature-off 不请求扩展、不扩大 descriptor pool，并拒绝实验 CLI。feature-on 的 synthetic snapshot 在 production renderer 前 drop，不监听 terrain edits。

Go / No-go 与下一道门

  1. AABB semantic feasibility：GO。候选误报可正确过滤。
  2. 当前 AABB macro query 替换 production tracer：NO-GO。0.848×–1.769×不足以承担新 lifecycle。
  3. 立即投入 full-world triangle/greedy backend：NO-GO。fixed-function 可能更快，但当前 Amdahl 与 consumer 价值没有先成立。
  4. 保留 default-off capability seam 和 benchmark：GO。它不改变默认行为，并为后续垂直切片提供共同基线。
若继续：只选一个真实高占比 consumer，优先隔离测量 tracer.shadow_prepass 中的 terrain visibility；在一个 dirty chunk 上让 AABB 与 triangle/greedy 共用 production atlas、rays、reference 与 VisibleTerrainPublication revision。先证明 consumer 级收益，再谈全世界集成。

未验证风险

  • 未接入 512³ production atlas、真实 streaming/edit publication、multi-BLAS overlap。
  • 未测 triangle/greedy、RT pipeline/SBT、compaction、async compute build。
  • 未测 glass/transparent hit semantics、真实材质 cache 或非 NVIDIA KHR 设备。
  • 每个 local cell 只有 4 个 timing 样本；0.9×–1.1×只应视为无明确收益。
  • 整帧 B 不执行 integrated RTX traversal，不能称作 production RTX speedup。
