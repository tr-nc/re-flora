## 范围与开关

`Debug → Grass / Flower Inertia (C)`：开启为新响应，关闭为原来的直接风响应与解析细摆。默认开启，方便后续验收。两种效果切换时新响应仍在后台推进，不重置其位移和速度；关闭草花显示也一样。树叶、树叶阴影代理、落叶粒子和果实的运动模型没有改动。

普通高草、矮草共用一张世界 XZ 网格，节点保存位移、速度和四个离散姿态。当前 512×512 voxel 世界是 33×33 节点，间距 16 voxels；草根对同一发布时间的四个相邻节点做双线性插值，不混合不同时间的节点，也不在时间上插帧。没有逐株草状态。新草从环境响应中出现，不把某一株旧草的对象状态交给它。

薰衣草、Ember Bloom、Kochia 使用每株独立的 C 状态。生命周期编号独立于位置、绘制顺序、增长进度和出生时间戳。绘制列表变化时通过旧编号映射 GPU 状态；删除后重种得到新编号，从零位移/速度起步。GPU 状态是密集存储，不保留被删除植物的洞位。

同一风输入不等于同一响应。草采用第二轮网页默认的 1 Hz / 阻尼比 0.24；薰衣草是 0.65 / 0.30，Ember Bloom 0.52 / 0.34，Kochia 0.85 / 0.40。它们在游戏中的参数仍需要用户观看后调整。新模式替代旧的解析细摆，Kochia 的旧 Branch Jelly / Body Wind 参数仍属于旧模式；自然静态弯曲保留。

## 代码与生命周期

- `src/tracer/vegetation_response.rs` 集中管理世界网格、花株映射、帧缓冲、连续状态和渲染描述信息。
- `shader/slang/vegetation_response.comp.slang` 复用现有 `sampleProceduralWind`，不是 CPU 侧不同噪声算法的 Wind。使用恒定力解析阻尼振子步进，正常帧风采样步长不超过 1/120 秒。
- 仍使用既有 World Tick / 四桶发布节奏：默认 0.05 秒更新一个桶，每株 5 Hz。内部积分与显示分离。加载或编辑造成长帧时保留状态，采用较粗风采样补进全部时间，只发布最终仍可见的四个桶；倒放时间轴或新建世界才清零。
- 网格按完整世界范围分配，支持非零世界原点，地块接缝共享节点。当前游戏是固定范围，不是无限流式世界。重建草、改变 LOD 或显隐不改变网格。卸载的花株不再进入下一帧映射，再出现会从新状态开始。
- 近景、远景、花草光照缓存使用同一个姿态采样。树叶走原函数入口，保持原运动。PushConstantFlora 复用既有对齐空隙，仍是 128 字节；实例仍是原来的 8 字节。
- 每份有效状态 80 字节；1089 个草节点约 85 KiB。实际 GPU 分配有容量取整、双缓冲和在途帧副本；另有每项 32 字节的输入。不能把 85 KiB 宣称为总显存。额外 pass 已挂入 `vegetation_response.pass` 的 GPU 计时。

### 短程 GPU 耗时

上述固定近景使用 C → 旧模式 → C 的三个 200 帧区段，各跳过前 30 帧；日志每 30 帧取样。这不是停止后台惯性计算的完整旧版本基线：切回旧视觉时 C 状态仍继续演进，以便再次切回来。

| 区段 | 有效样本 | 整帧 GPU 中位数 | 响应计算中位数 | 草花绘制中位数 |
| --- | ---: | ---: | ---: | ---: |
| C 第一次 | 5 | 4.247 ms | 10 μs | 294 μs |
| 旧视觉 | 6 | 4.102 ms | 9 μs | 290 μs |
| C 再次 | 6 | 4.060 ms | 9.5 μs | 291.5 μs |

整帧样本范围有 3.500–5.311 ms 的波动，包含 DDGI、阴影和水等其他工作，不能据此宣称 C 整体更快或满足某个百分比门槛。本轮只记录成本、继续视觉评审，不启动优化项目。

## 继续验证

复跑正常后台启动：

```sh
cargo run --release -- --hidden --mute --auto-exit 0.5
```

然后运行可重复的 GPU 与场景检查（不会改游戏实际风源）：

```sh
RUST_LOG=info RE_FLORA_VEGETATION_RESPONSE_VALIDATE=1 cargo run --release -- --hidden --mute --authored-flora-bench --perf
cargo run --release -- --tail-latest-log 250
```

GPU 检查使用生产 shader 读回位移/速度，断言停风反摆和衰减、快速换向、不同显示频率下的轨迹一致性、帧间姿态保持、状态重排和新生归零。另对当前风参数计算 16-voxel 网格与 1024 个精确中点响应的 RMS / 最大误差。

同一环境变量与已有 authored-flora benchmark 组合时先做 100 帧场景重放：三种代表植物及普通草生成、地块重建、Kochia 外观修改、移除/同一画笔位置重种、切换旧效果、草花显隐、近远 LOD；随后 600 帧做 C/旧视觉/C 对照，最后恢复开关、外观与 LOD 配置。它验证执行路径与生命周期，不等价于人眼确认外观无跳变。不要在资源不足时反复运行。

用户要体验时再从此工作区用普通 `cargo run` 打开可见游戏；先比较快速改风向、静音所有风源后的反摆与余摆，再比较草与三种花，以及近景/远景。默认 World Tick 不用改。

## 网格尺度限制

16 voxels 比现有风体积约 25.6-voxel 的采样间距更密，但这不代表能解析所有 GUI 风参数。当前 Source 1 的基频尺度约 500 voxels，第二 octave 约 250；Source 2 约 187.5，最高 octave 约 83.3。

真实 GPU 对照在 512×512-voxel 范围内取 1024 个网格中点，使用当前 2 个风源设置演进 2 秒，再比较逐点 C 与四邻点 C 插值：每轴 RMS `0.010260 voxel`，归一化 RMS `0.008629`（约 0.863%），最大单轴误差 `0.040364 voxel`。两次回放相同。这只是这组风源、时刻和采样位置的结果，不是全参数上界。

GUI 仍能把 pattern scale 调得极小、提高 octave 和 lacunarity，届时小尺度风会被漏采；没有偷偷限制 GUI 或声称网页原型已解决这个问题。未来若加入局部窄风源，需用最小源尺度与网格间距约束或另行设计局部采样。本轮不扩大为风场重构或额外优化项目。
