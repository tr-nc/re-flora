# Contree GPU build optimization plan

Purpose branch: `agent/contree-optimizations`.

## Baseline evidence

Measured in release hidden mode with perf/debug logging.

- Initial startup contree rebuilds: 50 chunks, avg `contree_build_and_alloc_total` about `828µs`.
- Non-empty startup chunks: 25 chunks, avg about `0.936ms`.
- Empty startup chunks: 25 chunks, avg about `0.720ms`.
- 8-chunk tree rebuilds: mesh rebuild avg about `30.17ms`; surface about `23.85ms`; contree about `5.03ms`; scene texture about `1.20ms`.

Conclusion: contree is not the largest rebuild cost, but empty chunks still pay a fixed full-build cost and multi-chunk rebuilds pay repeated submit/fence overhead.

## Phase 1: skip contree build for empty surface chunks

Use `SurfaceBuildResult::active_voxel_len` / `SurfaceBuilder::build_surface` return value. If it is zero, avoid submitting the GPU contree build for that chunk.

Required behavior to preserve:

- deallocate any previous contree allocation for the chunk;
- clear CPU chunk cache and shared ray-query cache;
- clear contree scene chunk metadata;
- publish a CPU chunk source update with `is_present=false`;
- clear the scene texture entry for the chunk;
- keep perf logs and benchmark counters clear enough to compare against baseline.

Expected win: empty chunks avoided previously cost about `0.72ms` each in contree build time, plus reduced queue/fence pressure.

## Phase 2: add pass-level GPU timing before shader rewrites

Fence timing currently measures total submitted command latency, not individual passes. Add optional timestamp-query instrumentation around contree passes before changing shaders.

Targets:

- buffer setup;
- leaf write;
- per-level tree write/update passes;
- concat.

Do not use pass-level guesses as evidence until timestamps are available.

## Phase 3: batch multi-chunk contree rebuilds

Current rebuild paths submit/wait one contree command buffer per chunk. Explore a batched path that records or dispatches several chunk builds together and waits once.

Constraints:

- preserve per-chunk allocation confirmation and scene texture offsets;
- handle empty chunks and stale deferred rebuilds safely;
- avoid blocking interactive work more than current deferred behavior.

## Phase 4: reduce full-volume scanning for sparse chunks

`leaf_write.comp` scans the full chunk volume. Explore building leaves from active surface voxels or active bricks instead of all `256^3` voxels.

Possible inputs:

- surface active-voxel list generated by surface pass;
- brick occupancy metadata;
- compacted sparse surface buffer.

This is the most invasive phase and should follow Phase 2 timing.

## Validation ladder

After each implementation phase:

```bash
cargo fmt --check
cargo check
cargo test
source ~/.zshrc
cargo run --release -- --hidden --auto-exit 0.5
cargo run --release -- --latest-log
cargo run --release -- --tail-latest-log 200
```

For performance comparisons, use release hidden runs and log-derived counters; debug builds and unit tests are not performance evidence.
