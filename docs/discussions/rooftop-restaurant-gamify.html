01 / Direction

我赞同的核心：不是加一堆系统，而是给照料一个去处

用户提出 现在更像沙盒模拟器，希望变成游戏：玩家经营一个 homegrown 餐厅，主要在平房屋顶种植，为楼下提供食物；供给、售卖、收益和再投入让行动相互连接。

我的建议 把主体验定义为“经营一座能端上餐桌的私人屋顶花园”，而不是先做完整餐厅模拟器。餐厅是花园的回声：楼下亮起暖灯、菜品使用了自己的收获、收益让屋顶多一种可能。经营信息要让人有方向，不应抢走种植本身的乐趣。

这次方向带来的价值

  • 从“我能种什么”变成“我想为餐厅种什么”。
  • 裸屋顶提供明确的前后对比和空间作者感。
  • 有限资源让铺土位置、种植组合产生选择。
  • 楼上劳作、楼下营业形成鲜明且容易传播的主题。

需要守住的张力

  • 任务引导 vs. 自由种植。
  • 自给餐厅 vs. 基础资源耗尽后的软锁。
  • 经营反馈 vs. 倒计时、债务和重复打卡。
  • 可编辑土壤 vs. 不可挖穿的模型建筑。

docs/game_direction.md 已记录用户确认：受众与 Restorative Garden 的低压力约定不变，餐厅供给是温柔邀请；初期苹果单链路、现有编辑镜头、混合场景与不可挖屋顶。本轮先做无限资源屋顶 PoC，不要求购买、正常资源平衡或旧存档迁移。ROADMAP 与 First Garden Moment 已明确本轮优先级，旧的花卉首循环／近地镜头假设不再阻塞屋顶实验。
02 / Brief & scope

主题用户已提出的内容本方案的处理方式
世界背景平房餐厅；方块形的建筑体量，俯视轮廓不一定规整；食物 homegrown；主舞台在屋顶。保留。楼层、屋顶可用面积、外部环境与餐厅室内是否可玩尚未定。
开局没有任何土，只有裸天台；玩家一开始有资源；可以加土、播种和种树。把“无土”作为明确目标。“零可编辑体素”与“零土壤体素”分开确认，不擅自等同。
工具与背包沿用 Grow Item；Dig 临时重命名 Edit，能加能删；底部栏和交互逻辑先不变；没有对应材料不能继续添加。沿用已有交互骨架；材质选择与空库存提示需后续设计。现有库存逻辑不是从零开始。
开发者模式所有方块无限量，方便调试和造景。建议作为显式模式，而不是伪造巨量库存；与正常资源循环分开，标注作弊状态。
经营循环蔬菜供给任务 → 餐厅售卖 → 钱 → 买幼苗、种子、营养土。属于目标构想；任务强制性与收益规则未定。购买系统明确后做。
大物体餐厅、外围造景、通风管等用传统 modeling 与光栅化，加入 Pixelize 风格化处理。以大模型独立流程讨论，不自动转成体素建筑，也不保证一个后处理就能统一风格。
小物体苹果、花头、蝴蝶沿用现在的链路。保留用户的复用意图；当前链路准确含义见现状调查，不把语音里的“贴图”简化成静态贴图。
远期装置／工具可以买并添加通风管，热风可能带来机制；营养土大袋倾倒动画，之后把土弄匀；vintage 风格除草机。全部保留到后续 Plan 不因出现在方案里而获得实现授权。

架构建议：建筑是稳定的模型对象，土壤是可编辑体素，植物沿用自己的生命周期。三者通过明确的支撑／局部环境接口关联，不让建筑为了被种植而必须变成可挖体素，也不绕过现有地形发布、修订与碰撞边界。

建议

经营最小信息，不是模拟所有顾客

第一版只回答三个问题：“餐厅现在想用什么？”“我交了多少？”“这次换回了什么？”初期用一个稳定菜品与固定换算，先不做厨师排班、桌位周转、复杂配方、市场波动和供应链。

闭环试验可以先让供给直接触发销售反馈；若没有真实营业系统，必须标为原型规则，而不是伪装成顾客模拟。

建议

把收益反馈放回世界里

一篮收获送到屋顶门口／传递点，楼下窗里有暖光，菜单上出现这次收获的菜，轻量提示说明产物与收益的关系。

这些是候选演出，不是本次新增要求。无需先做可进入、可点菜、可服务的餐厅室内才能表达主题。

低压力方向已确认：供给是温柔邀请，受众不变，不用强制期限、债务或离线惩罚制造压力。基础种子再获得、缺货时停卖以及首轮土量等具体安全网仍是后续正常模式建议；本轮直接无限开发资源，不实现库存管理与经济平衡。

不建议用来“游戏化”的东西：为了让数字上涨而增加重复点击、必须每日完成的订单、没资源只能挖餐厅的开局、以及在无限模式下假装正常经济已经平衡。

05 / Space & rules

裸屋顶，是一个清楚的起点

候选空间安排

一个屋顶，四种读图信息

  • 工作区：平整基底，允许自由铺土与种植，不预画强制种植格。
  • 边界：女儿墙、屋沿、排水口，让可用面积一眼可读。
  • 连接：楼梯／屋顶门或供给点，解释楼上楼下的联系。
  • 特色：通风管、旧工具、餐厅招牌；先作为气氛，机制后置。
候选规则

土可编辑，房子不等于土

  • 第一笔土能落在模型屋顶，而非虚空。
  • Edit 删除优先只影响可编辑层，不挖穿餐厅。
  • 添加越界、无库存、无支撑时给清楚反馈。
  • 土被删后植物如何移动／失效需定义，不能悬空。
  • 树的大小、所需土厚与屋顶关系先用简单可读限制，不急做结构承重模拟。
模式资源与编辑阶段边界
本轮开发者 PoC进入实验场景直接启用无限资源，不管理材料数量；先验证添加、删除和种植手感。显式提示“无限资源／实验不保存”；仍限制无效区域和不可挖屋顶。不要求正常／无限模式切换，不伪造巨量库存。
后续正常模式有限资源、初始资源量、对应材料库存与扣除／回收规则后续再做。从本轮实现范围移出；无限模式结果不证明经济平衡。

若后续新增 Debug 控件，仍遵循 GUI settings 规则 的声明式／saved-field 绑定；本轮不因旧方案写过开关就额外实现资源管理或模式切换。

后续机制候选 热风管可以使邻近土壤更快变干，形成需要观察的小环境，或只做蒸汽与声音；这不等于模拟真实油烟化学，也不宣称热风普遍有益。先确认视觉可读性和温柔后果，再考虑热量／湿度耦合；装置购买与放置另立阶段。
06 / Art direction

像素化的是视觉语言，不是建筑的存在方式

用户提出 大物体使用传统模型与光栅化，风格化后贴近现有 vibe；苹果、花头、蝴蝶等小物体继续沿用现有链路。我的建议 用同一套轮廓、色阶和像素密度规则连接两者，而不是要求两种对象使用同一技术表示。

暖白旧绿叶绿土棕砖红暖灯

建议场景气质：旧而被照料

浅色灰泥平房、朴素檐口、绿色旧金属管、暖色招牌；地面和器物有使用痕迹，但不是废墟。植物轮廓比装饰噪声更重要，远景只提供街区与生活感。

参考 Rosemary’s 的楼上种植与楼下餐厅联系，而不是复制其真实建筑；真实农场的整齐排布不应自动变成玩法网格。

建议先做一个“像素风样板角落”

用一段屋沿＋管道＋土＋一株植物＋一个苹果，在目标镜头下比较：轮廓是否融洽、材质是否抢戏、相机移动是否爬像素、阴影与暖灯是否统一。

可见效果先评审，再独立测 Release 性能。若未来请求 A/B，需要 Debug 运行时复选框保留原版与实验版，不能只靠截图或 CLI。

混合大场景流程 · 本轮只做必要样板，完整流水线后置

步骤交付目标避免误区
1. 灰盒与镜头在目标上帝视角验证屋顶面积、厚度、边界、楼下可读性；确认正交或透视。不要先制作完整室内或周边城市。
2. 模型与材质简单清楚的体量、足够宽的轮廓、克制贴图频率；碰撞／支撑代理分离。glTF 三角模型加载能力不等于大场景所需的全部管线已接通。
3. 风格化样板评估目标像素密度、色阶、边缘高光／描边、材质分区；保证 UI 保持清楚。只把屏幕降分辨率不能自动解决稳定性、细线丢失和小物体像素大小不一致。
4. 世界语义拾取、种植支撑、人物／果实碰撞、水阻挡、太阳阴影与 DDGI 遮挡分别验证。Raster Consumer 读取光照，不意味着它自动成为 DDGI Occluder。
5. 移动与合成验收平移、缩放、旋转时比较细节抖动，确认透明／水与描边关系；与原有土和植物同框检查。外部 Godot／Unity 做法仅作参考，不能承诺直接套到本项目 Vulkan／Slang 链路。

复古除草机 用户提出 vintage 风格。“手推滚刀割草机”只是候选理解，不等于已确认机器类型。建议先明确用途：整理自生草、收集草屑，还是替代 Trim？若误伤蔬菜会破坏低压力体验，可优先考虑只影响野草／草坪的可读作用区域。未确认前不做购买、操控、刀具动画或复杂草屑物理。

06 · 本轮直接无限开发资源，不管理经济
