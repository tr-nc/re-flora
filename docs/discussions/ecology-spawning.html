一片没有被重新种植的草地，也应该在之后的某个时刻，从另一个位置，迎来一只蝴蝶或一声蝉鸣。

讨论稿 · 尚未实现草 / 特殊植物 / 树冠均可供给共享生成，分别表现
体验规则交互讨论实现方案开销与验证一起决定

先确定三个不变的前提

01 / EXISTENCE

依赖现存植被

所有草、特殊植物和真实树冠都具有生成机会。没有任何有效植被的位置，不凭空生成动物。

树冠独立有效；不再要求树下必须另有草。
02 / TIME

由时间产生机会

新种植、初始加载和存档恢复都进入同一套规则。植被变化更新栖息地事实，动物出生由独立的随机时钟安排。

种下一片草不立即爆发，也不只生成一次。
03 / VARIETY

位置持续重新抽样

每次生成机会都重新选择区域与真实植被位置。长期不变化的花园，也能持续出现不同的出生点。

不用永久固定的少量采样点代替整个草地。

密度增加时，花园应该怎样回应？

试着调一调

推进使用固定种子的随机抽样。每次生成位置变化；结果允许某一分钟没有事件。仅模拟生成尝试，不模拟动物寿命、并发占用和可见性。

共用一套生成机制，保留两种动物的性格

① 植被发布已提交的草、植物、树冠
更新数量、范围和版本
② 栖息地索引按空间区域组织
保存权重，引用现有数据
③ 共享调度器随机到期 → 检查预算
选区域 → 抽真实位置
④ 行为接收方蝴蝶：出生、飞行、寿命
蝉鸣：播放、停歇、宿主清理

按区域组织

草地和特殊植物利用已有地块；跨区域树冠按覆盖范围归属，避免重复计数。记录稳定身份、版本和可用量，而非为每株草维护一个计时器。

按机会取位置

先选有效区域和植被类别，再从其真实实例中随机取位置。为零生长、已删除或不适合的位置做有界拒绝；失败后跳过机会，不无限重试。

分别配置动物

共用抽样、随机时间和预算机制；蝴蝶与蝉鸣可有不同偏好、感知范围、最大数量和休息时间。共享机制不意味着同时出生或同一密度。

为什么不直接把全部草加入现有蝴蝶列表？

当前蝴蝶定期读取非草植物并汇总树叶位置，生成期望与来源数量成正比；蝉鸣另外读取草的稀疏样本与树冠声学样本。把海量草实例直接接入前者，会增加列表读取和复制，也会把原有生成速率放大。

建议替换两个调用方的来源维护，统一交给栖息地索引。树冠采样以真实叶片数据为依据；不让动物生态依赖声学专用采样布局。

三种方案的取舍
方案优势代价 / 局限
每株植被一个生成器直观，位置天然精确计时状态与遍历随植被总量增长，不建议
固定少量候选点读取少，容易限量位置长期固定；若采用，必须轮换并处理代表性偏差
区域索引 + 按机会抽实例静态花园持续变化；生成工作可设预算需要核实实例读取的同步安全，并准确维护区域权重；建议方向

低开销要靠限制工作量，再用实机证明

阶段建议约束必须核实的地方
植被发生变化只更新受影响区域；大量变化分批发布，旧版本及时失效接在已提交的植被发布之后；不能发布一半的新状态
普通帧无生成机会时仅推进时钟；满额时不抽样、不积攒补发区域选择避免每帧扫描所有区域；权重索引可随变化增量更新
有生成机会全局限制每帧候选数和重试数；只取少量真实实例映射内存不等于可以随时安全读取；核实 GPU 写入完成及可见性，不添加等待设备空闲
大世界 / 远处按空间查询玩家附近区域，远处暂停生成机会靠近后重新安排时间，不能积攒后集中爆发；是否需要远处生态延续应单独讨论
植被删除失效区域不再生成；依附它的蝉鸣停止并释放蝴蝶已经飞离后继续自然寿命；不要因一个局部编辑清空整张地图
世界替换旧索引、待处理机会和旧世界动物统一退场异步结果携带世界版本，旧结果不可落到新世界

固定候选预算只限制“生成”部分。现存蝴蝶的模拟、碰撞与渲染，蝉鸣的空间音频仍需各自数量上限。植被索引维护也不是零成本。

行为验收

空世界、纯草、纯树冠、纯特殊植物、混合花园分别运行；静置期间持续获得机会并更换位置，删除和重复加载后无残留。

成本验收

同相机、同植被、同动物负载下，在 release 实机比较基线与方案。记录生成 CPU p50 / p95 / p99、尖峰、读取字节、候选次数和内存稳定性。

体验验收

另做可见、非静音试玩：蝴蝶密度和出现位置是否自然；蝉鸣是否温柔、有停歇。静音 smoke 只用于正确性验证。

我们先讨论这三件事

01

茂密花园，是更热闹，还是更均匀？

建议：总机会逐渐封顶，同时限制局部密度，让新增植被主要扩大分布范围。避免只要草多，就出现成群蝴蝶和连续蝉鸣。

02

三类植被要不要有不同偏好？

建议：全部都有非零机会；蝴蝶可略偏爱特殊植物，蝉鸣可略偏爱树冠。草株数与叶片数先分别转换成有效栖息地量，再加权，不能直接比较原始数量。

03

走进一片已有草地，应多快感受到生命？

建议：进入后随机等待，允许较早遇见一次，但不要立即集中生成。持续停留后保持较疏的自然节奏。具体等待时间、上限和偏好强度留到试玩调整。
