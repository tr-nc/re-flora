02 / Motion is a separate problem

稳定 seed 解决主因，不等于消除运动方差。

最终二进制关闭新 A/B 时，17 灯有风测试仍失败：某接收点直接光变化约 7.33%，全灯参考只变约 0.45%。另有一些“误差变化”主要来自合法阴影变化，不能一概叫闪烁。

因此量测的是超额变化

对同一真实接收点，排除灯和几何版本改变后，比较直接光亮度的变化幅度与当前全灯参考的变化幅度：

max(0, |ΔY_render| − |ΔY_ref|) / max(Y_total_old, Y_total_new, 1e−5)

2% 是本次诊断回归线，不是产品画质规格。该指标不是屏幕像素误差，也不保证所有场景或每个像素稳定。参考独自跳变时，不把一个平稳的实际输出误判为闪烁。

最终采用：自适应精确照明

  1. 新接收点用全灯参考校准；误差高的点直接使用精确路径。
  2. RIS 选中连接或 RGB 衰减指纹发生变化时，保守升级为精确路径。
  3. 只保存质量分类；精确路径每帧重新计算当前位置、法线和可见性。

根位置 / spawn generation / 完整灯版本 / 几何版本验证分类。不依赖屏幕历史；不使用旧颜色平滑合法编辑。

本花园分类缓存累计分配约 198 MiB；不是 GPU 峰值驻留测量。分类可随运行保守增长，最坏退化为精确照明加 RIS 开销。本阶段不在视觉确认前继续隐藏或优化这些成本。

灯预算 64 ≠ 实测 64 盏灯。所有本次“大灯数”花园运行实际上传 17 盏。结果不能外推为 64 灯性能，也不能拿 macOS 绝对耗时直接对比 Linux / RTX。

新选项接入声明式设置与统一保存；默认关闭。既有灯预算、风参数、相机和其他已存设置未改动。切换路径无需重启。

复跑关键场景

cargo build --release

node scripts/validate-light-ris-temporal.mjs \
  --motion wind --light-budget 64 \
  --stability on --seconds 30 \
  --output target/NEW-stability

node scripts/validate-light-ris.mjs \
  --case perf --light-budget 64 \
  --stability on \
  --output target/NEW-perf

每个输出目录必须是新目录；串行运行，勿叠加 GPU 负载。脚本在 finally 中精确恢复输入配置。

没有自动打开可见游戏。需要人工体验时，从此工作树执行 cargo run --release；普通试用不带 --perf。数值闭环不是替玩家确认了“看起来完全不闪”。
