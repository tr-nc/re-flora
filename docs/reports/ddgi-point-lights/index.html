01 / 怎样写进去

不等射线撞上点光，直接算它的贡献

理想点光是 delta 光源。普通随机方向命中它的概率为零；增加普通 DDGI 射线也解决不了。正确做法是显式光源采样／解析连接。PBRT 原理与代码 ↗

01
探针连接到灯

得到光照方向、距离衰减，以及一次遮挡／RGB 透光结果。

02
展开方向响应

把该贡献乘以各法线方向的余弦，累加到现有八面体图集。

03
草只查询合成场

按位置与法线插值，不再为这些光源逐灯做可见性查询。

E(p, n) = Σ 透光率 × 光强 / 距离² × max(0, n·光照方向)

公式使用物理光强；游戏的范围窗、近场钳制与亮度单位需要沿用并校准。探针没有实体表面，注入不会凭空增加一次物理反射。

无需换成球谐。Unity 用 SH，我们已经有八面体 irradiance atlas，两者都可以表示漫反射方向响应。昂贵的遮挡应每条探针—光源连接算一次，再让多个方向 texel 复用。

02 / 路线比较

先解决“能否正确表示”，再解决“很多灯”

首选 · 直接注入

每个更新中的探针，连接相关光源

当前有效 GPU 灯列表上限为 8，先全量计算最易建立正确参考。没有漏选点光的采样噪声，但更新成本仍随灯数增长。

第二步 · 重要性采样

每个探针只采固定数量的灯

按光强／距离／空间分布挑灯，并以正确概率加权。可以借鉴 PBRT 的 light BVH、RTXDI 的 ReGIR；代价是噪声、更新与收敛压力。

不是等价转换

把点光做成有限大小发光球

能复用 emission 路径，但改变近场和半影。小而亮的球依然可能漏采。只有确实想改变光源形状时，才应这么做。

ReGIR 是“帮你选灯”，不是“照明已经算好”。NVIDIA 明确把 RTXGI 探针命中面着色列为用例，也明确说明采样函数不算阴影。把它用于探针中心的直接光注入，是这里提出的组合方案，不是现成 SDK 功能。

03 / 最重要的质量边界

解析注入解决漏采，不解决空间分辨率

近场

灯很近，亮度和方向变化很快

探针之间可能有一块很亮的区域，但探针本身都没采到它。增加角度分辨率不能恢复缺失的空间峰值；需要局部更密的探针或明确的混合策略。

遮挡

探针能看见，不代表草能看见

薄墙、灯底座和地面附近的草可能处于另一侧。DDGI 的可见性插值有帮助，但不能恢复每片草到灯的精确阴影边界。

动态

灯关掉，直接光不能慢慢残留

灯移动和挖墙都会让连接失效。直接光需要明确的失效／重算／发布规则，不能只依赖用于间接光收敛的历史混合。

玻璃

必须保留当前透光语义

这里的昂贵路径包含玻璃传输。把 RGB 透光改成二值阴影会改变画面，不能算等价优化；直线透光近似也不等于完整折射焦散。

04 / 当前代码的关键接缝

比“写进图集”更重要的是：别算两次

当前 DDGI 命中面会同时读取历史光场与显式局部光。如果直接把点光注入这份历史，再保留原有显式项，同一束直接光会在下一次反弹着色里重复。

建议的逻辑分工

共享探针布局，区分直接贡献

原有传输历史＋直接光通道→最终草着色

直接通道不作为额外间接光再次喂回原有反弹计算。是否增加 atlas 由存储与发布要求决定，不需要另建探针系统。

还有两个陷阱

单位与可见性数据不能混用

现有图集的滤波量是 E/π，定向样本不能套用均匀球面的 4/N 权重。现有灯强还要做单位校准，不能机械除 π。

光源距离也不能作为普通场景距离样本写进 DDGI visibility moments。

代码名不等于物理光型。当前 PointLight 也承载 voxel emitter 的有限发光包围盒。石灯不应因为类型叫 PointLight，就在 A/B 中被无声改成理想点光；几何 emission 与代理灯的贡献也必须避免重复。

05 / 推荐的下一步 · 尚未实现

先做可解释的 A/B，不先上完整 ReSTIR

  1. 单灯基准：用无几何 emission 的解析点光，检查探针处／探针之间的亮度、法线响应、近场钳制与范围边界。
  2. 补齐困难场景：薄墙、灯底座、彩色玻璃、灯开关／移动和挖墙；记录阴影误差与响应时间。
  3. 保持可比：太阳原有直接阴影不动；Debug checkbox 未勾选为原有逐草局部光，勾选为共享场。真实石灯另测有限形状与 emission 分工。
  4. 视觉确认后量性能：分别记录草查询、直接场更新、原有 DDGI 更新和整帧耗时。先 1／8 个有效灯，再明确扩容后测 32／128。
昂贵连接次数的目标
草样本数 × 灯数 → 本帧更新探针数 × 灯数

这才是第一阶段要验证的共享收益。固定数量的草查询可以做到；整个光照系统与灯数完全无关，不能据此保证。若探针更新成为瓶颈，再增加选灯与重采样。
