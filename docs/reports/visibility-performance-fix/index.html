02 / CONFIRMED CAUSE

“没有执行审计”不等于“没有审计成本”

问题出在程序边界

此前原始、共享和审计共用 compute 程序，靠运行时标志关闭审计。重型参考追踪与统计代码仍参与编译，影响正常核的代码生成。重新测量也复现约 28 → 37 ms 的倒退。

改积分循环控制没有改善。临时编译掉审计能逆转性能，但也改变原始路径代码形态，因此没有拿那次诊断充当通过结果。

隔离，不是删掉验证

  • 原始／共享／审计分别编译，覆盖 opaque / Glass 与普通／stem-band 路径。
  • 原始核没有共享表与审计资源；共享核没有审计分支与资源。
  • 审计可选旁路 dispatch，只读正常快核输出，不替代渲染。
  • 实际优化后 SPIR-V 与布局反射均有隔离回归测试。

已确认代码生成受影响；没有硬件寄存器／spill 计数，不声称测到了各项硬件成本。

03 / VERIFY THE FAST PROGRAM ITSELF

照明没有靠关掉验证来过关

旁路审计抽取真实草接收点，对照原始有限光源传输，再在同一 GPU 帧读取正常快核 RGB。默认庭院与种子 7 都是零透射率失配、零 RGB 超差；观察到的最大 RGB 差约 4.7×10⁻¹⁰。

不是只复用零值

本次最后稳定样本，共享承担的有限光源直射亮度：默认庭院 74.8%，种子 7 86.1%。约每 1024 个接收项抽样，不是全像素保证，也不是总直接＋间接光的比例。

样本受实例顺序、风与模拟影响，不沿用上一版 90.6% 当成本次固定结果。审计摘录 ↗
