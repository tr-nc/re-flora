02 / Recommendation

Sound comes from the grass, not the camera.

Partition real grass into small 3D cells anchored to the world. Each selected cell becomes one distributed spatial loop, with a few representatives rooted in actual grass. Turning your head changes direction; it must not change which plants exist. Empty ground is silent.

Not one voice per blade

A dense lawn should not create thousands of voices or acoustic queries. Rendering detail never sets audio cost.

Not a global wind bed

Bare ground, a cleared garden and walking away must actually become quieter. Nearby grass can remain audible outside the view frustum.

Not random animal calls

The ecology scheduler handles sporadic cicadas. Grass rustle is sustained material response, so it needs coverage and wind, not spawn opportunities.

03 / What the repository already supports

Reuse the owners we have.

Real root membership is available

The surface resources already maintain ordinary-grass root sets, hydration identity and changed-root tracking. Soil cover even has a 16-voxel spatial tile index. We do not need a new authoritative grass simulation. [1]

But that index describes roots, not audible biomass. Growth, clipping and effective visible height still need a small derived acoustic publication.

Chunk counts alone are insufficient

ecology_regions() exposes species counts and chunk bounds; sample_ecology_root() reads one 8-byte root and rejects zero-growth entries. Those are useful observations, not a fine coverage field. [2]

One sound at the chunk center could land on bare ground or the wrong elevation. Random root samples can miss a tiny island.

One voice can represent an area

PetalSonic SourceExtent::WeightedSamples already represents an area/volume with normalized power weights and stable sample IDs. More samples increase worker work, not playback voice count. [3]

The canopy realization is tree-specific; reuse the engine capability, not fake tree IDs or the Tree leaves mixer bus.

Wind and playback lifecycle exist

WindFieldFrame::sample_world() gives local forcing, and SpatialFrame already prepares sources before publication and playback. The tree path demonstrates smoothed wind-driven gain. [4] [5]

Raw CPU wind is not the exact GPU blade velocity. The first version would be a perceptual wind response, not physically reconstructed friction.

04 / Proposed implementation — approval required

Keep geometry, selection and playback separate.

Publish compact grass-patch facts from SurfaceBuilder

Derive occupied acoustic cells from committed tall/short grass roots. Start with 64-voxel / 0.25-world-unit 3D cells, not camera-centered sectors or a flat XZ field. Keep vertical surfaces distinct. Each cell carries a world epoch, stable cell ID, revision, bounded representatives and estimated grass mass.

Observe the existing root reconciliation/append/restore paths; do not consume the soil-cover queue behind its owner's back. Publish one immutable snapshot or deltas after successful vegetation changes. A new acoustic projection owns only derived summaries, never a second editable root list.

Make growth and edits meaningful

Root presence alone is not enough: use live growth, tall/short species, growth potential and hydration-limited visible height. Reuse or extract the authoritative calculation from flora_vertex.slang / grass_growth_shape.slang, with matching CPU/shader contract tests. Seeds with no visible blade contribute zero. [6]

Publish membership changes immediately after successful removal/mowing/undo/load. Mark growth, competition, hydration and relevant Debug override changes dirty. Coalesce growth summaries on a bounded cadence; do not rescan every blade every frame. Missing new-epoch data means silence, not the old world's grass.

Select patches with a hard resource ceiling

Query occupied cells near the existing audio listener (the camera). Rank by estimated audible power with retention hysteresis and stable-ID tie breaks. Candidate query and summary refresh need their own bounded work queue; limiting voices alone does not bound a garden-wide scan.

Proposed start: 12 steady voices + 4 transition/retirement slots, 16 total. Keep up to four fixed spatial representatives per patch. Select representatives from real occupied subcells, not empty tile corners. Spatial extent weights describe relative power; the patch's total power is a separate gain.

Drive a gentle loop with local wind

At each representative, evaluate a bounded grass wind response. Sum area/height-weighted power, smooth attack/release and convert power to amplitude. A gust reaching one side should affect those representatives, not instantly raise the whole garden.

mass_j = occupied grass area × calibrated visible-height factor
power_j = mass_j × response(local_wind_j)²
patch_power = Σ power_j
extent_weight_j = power_j / patch_power   (only when power > 0)
amplitude = sqrt(patch_power / reference_power)

Keep representative positions stable while a cell's geometry revision is unchanged. Coalesce immutable extent/relative-weight updates at the bounded summary cadence; update scalar gain each frame without rebuilding the geometry or restarting the voice. Extent-update support on the generic source interface is a real implementation gap, not an existing free operation.

This is a proposed perceptual model, not a measured acoustic law. Density saturates locally; total output has calibrated headroom. Do not automatically normalize all voices to constant total loudness: removing grass must not boost the survivors. Do not count distance attenuation twice; the spatial renderer owns propagation.

Use one saved mixer channel and the shared spatial transaction

A focused GrassWindAudio module consumes patch facts, wind, listener and run/mute state. It owns selection, phases, fades and retirement. Extend the generic transient spatial-source interface to accept extents and smoothed gain; do not route through canopy telemetry identities.

Preload only the processed loop. Give it a stable phase per world/cell; continue phase across quiet intervals without reseeking live voices. A paused/cleared/muted world cannot retain audible or leaked sources. Add saved Audio → Live mixer → Grass rustle controls. No A/B request has been made; this is a design review, not a hidden runtime experiment.

Important seam to verify during implementation: flora instance storage is host-mapped, and the existing ecology observer reads after jobs complete. read_back_range() is a CPU copy, not an implicit fence or GPU synchronization operation. New growth-summary reads must be placed at a completed publication with appropriate host visibility; never read a live GPU-written stream from the audio callback or add per-frame GPU waits. Existing root/hydration publication can avoid many redundant copies. [7]

Why not the smaller alternatives?
  • One non-spatial bed: cheap, but produces grass sound on empty ground and loses direction/occlusion.
  • A few sound points following the listener: cheap, but grass appears to move with you; transitions can pump and sources can cross walls.
  • One emitter per chunk: coarse bounds and unrelated empty regions become audible; large chunks smear local gusts.
  • One emitter per blade: voice/acoustic cost scales with vegetation population and duplicate recordings can reinforce each other.
  • Random ecology roots: works for rare insect calls; does not reliably represent a sustained dense field, tiny islands, or removals.

05 / Before calling it finished

Prove the behavior, then listen and measure.

Behavioral checks

  • No grass, no visible blade, or zero wind → silence.
  • One small patch → audible from its actual direction; rotate camera without creating/despawning grass.
  • Dense meadow → bounded reservations, no per-blade voices or volume explosion.
  • Local gust → response arrives where the grass moves; no independent random gust envelope.
  • Mow, bury, delete, undo, regrow and reload → correct committed patch membership and mass.
  • Slopes, two elevations and occlusion → no sound from a flat phantom lawn or empty tile center.
  • Pause, mute, device change, publication failure and world replacement → no ghost loops or leaked resources.
  • Equal physical patch split into more cells/samples → approximately stable total power, not louder because the representation changed.

Release-mode + listening acceptance

  • Use deterministic empty / island / dense / mowed / overlapping-height scenes.
  • Log reserved, active, retiring and acoustic-admitted voices separately; record summary copies and candidate work.
  • Measure app-frame, audio-worker and callback cost in Release with all other sounds running.
  • Listen for the short-loop rhythm, phase coloration, hard seams, tile hopping, overly close point sources and wind lag.
  • Balance against existing tree leaves, bees and footsteps. This quiet take may need documented gain calibration; file normalization is not silently assumed.
  • Show the candidate first; performance measurement follows without inventing an unmeasured FPS guarantee.
