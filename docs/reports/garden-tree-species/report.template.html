截图复评后的修改

从层板，改成舒展的树冠。

  1. 降低中央主轴。
    让骨干枝形成分叉，而不是围着一根高直杆排队。
  2. 抬起、拉开骨干枝。
    枝条向外上方生长，长度、方向和抬升程度有差异。
  3. 把叶团放到枝梢。
    增大并圆整末端叶簇，形成错落重叠的阔叶树冠。
  4. 下移果实挂点。
    让苹果挂在叶团下方，继续使用真实苹果生命周期。

03 / Research into structure

参考植物特征，但不冒充植物学模拟。

调研影响的是生成规则，而不只是配色。当前仍沿用游戏已有的像素叶片、树皮渲染和共享调色参数。

后续架构整理：统一生成模块 + 树种规则。

树种现在集中声明树冠、枝梢、叶片附着和果实规则；统一模块输出枝干骨架、年龄可见性、粗细与叶片挂点，几何代码不再判断苹果树或柳树。旧生成器通过兼容路径保留，不改写旧树形。规则是代码内的类型化配置，不是新增的 GUI 或外部脚本系统。

重构前后 148 组固定输入的生成指纹完全一致；新增规则回归后树模块 45 项测试通过，另有 1 项显式兼容性采集默认忽略。三种树和混种的原生 Release 检查通过。本页内嵌图片保留原始交付版本，不以不同分辨率的新截图冒充像素一致性比较。

苹果树

Malus domestica · 园艺化阔叶轮廓

参考其宽展、结果的园林形态；没有宣称复刻某个品种，也没有把主要面向核果类的“开心形整枝”当作所有苹果树的标准。

  • 低主轴与上扬骨干枝
  • 枝梢末端的圆润叶团
  • 接入现有苹果生长、悬挂、掉落与交互

松树

Pinus sylvestris · 成熟松树启发

参考成熟松树较开阔、不规则的冠形，而不是把松树等同于规则圣诞树。旧 Conifer 的九层、每层四枝，不再决定新 Pine 的轮廓。

  • 有变化的节间与每层 2–4 根枝条
  • 不等长枝条、偏冠与疏密间隙
  • 下垂弧度后接上扬枝梢

实现如何保持连接、身份和兼容性？
  • 共享树轴编译器：统一负责父先子后的连接、渐细半径、稳定树轴身份和有因果顺序的年龄显现；新树种共用上限约束。
  • 种子属于单棵树：年龄改变同一个体的大小和可见枝条，不重新抽取另一棵随机树。
  • 果实归属由树种决定：即使误复制非零苹果概率，Pine、Willow 和旧 Conifer 也不会长苹果。
  • 老树不强制换形：garden_tree / conifer 仍使用旧生成器；缺失树种字段仍按旧 Garden Tree 解释。新种植选择独立默认为 Apple Tree。
  • 调参真实有效：新轴模型不显示已经不生效的递归分枝控件；保留大小、粗细、种子、细分与叶簇编辑，沿用统一保存路径。

过程中出现过的失败与警告
  • 无效混种测试场景：最初把第三棵树根放在 x=2.25，超过默认 2 单位宽的世界，导致地形发布中止。场景改为从世界尺寸推导内部位置，之后成功复跑两次。不能据此声称任意越界 TreePlacement::World 调用都受到支持。
  • 删除路径的一条警告：原有 raster smoke 尝试再次删除已不存在的树，记录了 warning；最终 smoke 合约通过。
  • 最终运行：九个单树、最终混种、raster smoke 和普通启动记录中没有 ERROR / panic / Vulkan VUID。这里没有抹去前面的无效场景失败。

05 / Try it in the garden

从 Grow 种下，而不是从 Debug 拼出一棵树。

种植

  1. 按 1 选择 Grow。
  2. 把 Type 切换为 Tree。
  3. 选择 Apple Tree / Pine / Weeping Willow；Tab 可轮换。
  4. 点击地面种一棵。每次成功种植后，下一个体获得新的种子。

调参与保存

R → Flora → Tree 保留调试树的大小、粗细、种子和叶簇控制。点击 Save 保存设置。

Terrain & Plants → Save / Load 保存与恢复已经种下的树。它与保存调参不是同一件事。

开局说明更正：默认花园自带的 4 棵景观树仍是旧 Garden Tree；改为 Apple Tree 的是调试树配置和默认种植选择。开局布局独立生成，未在本轮替换；载入旧花园也不会自动换树。

本轮没有自动开启可见游戏窗口。普通试玩使用 cargo run --release，不需要验证场景环境变量或性能面板。
