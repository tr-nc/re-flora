Re: Flora / Rendering Research2026.11.03 · 技术选型，不是实现验收
Many-light rendering · Decision report

多光源的下一步：
固定预算随机采样

不再为每株草遍历所有灯，再设法把每条可见性查询做快。改用成熟的光源重要性采样：共享候选分布，接收端只处理有上限的样本。把代价从“随灯数增长”转成“固定预算下的噪声与质量取舍”。

保留 DDGI spacing = 32不改灯光强度 / 曝光 / 间接光普通草接收端不做全灯循环本轮不修改渲染器
结论项目约束工业证据方案比较推荐路径效果取舍真实成本许可与平台后续准入资料索引
01

先把决定说清楚

选定：有预算的随机直接光采样不等于立即导入 RTXDI停止把可见性缓存当最终主线

推荐算法家族：RIS / ReGIR / ReSTIR DI。它们解决的是“从全部光源中抽取少量有用样本”，而不是把全部光源的原有积分继续搬到每个接收点。对当前按草茎层做世界空间着色、GPU 只选择八盏灯的项目，第一步应是共享光源预采样 + buffer-less RIS；ReGIR 是灯数和空间分布扩大后的升级；完整屏幕空间 ReSTIR DI + 降噪不是眼下的无缝替换。[3][4]

这不是自创新算法。RTXDI 官方文档明确提供无需 G-buffer 的世界空间采样入口，也明确说明：只有初始采样，在复杂多光源场景下往往仍然太吵，ReGIR 和时空重采样各自解决不同层级的问题。选一个已有的入口，比替草构造一套新的照度拟合、遮挡证书和大面积精确回退体系更可控。

现在应选

共享预采样 + RIS

接收点按真实位置、法线和材质重选固定数量的灯/发光面样本，只为最终样本做可见性查询。适配现有世界空间草缓存。

规模扩大后再选

ReGIR 采样分布网格

把候选分布做得更局部，减少远灯浪费。不是新的照度探针；也不能不测就照搬每格 512 个样本的默认配置。

较大的渲染升级

ReSTIR DI + 降噪

主表面的时空复用能进一步压噪，但需要草的逐像素表面信息、历史映射与重建，不能只换一个 compute shader。

“共享聚合”必须准确命名

这里共享的是带权采样分布，接收端统计估计多光源贡献的总和；不是提前算好一份任意位置、任意法线都精确的照度总和。它改变了 G × L × 12 的工作组织，但接受有限样本误差。若“共享阶段必须输出确定性的完整照度和”本身仍是独立硬条件，那么随机采样不满足这一条，不能偷换概念。

调研结论是换到成熟的采样范式，不是继续优化旧循环，也不是承诺“现成 SDK 接进来就一定更快”。

02

项目真正要解决的，不是抽象的“百万盏灯”

当前成本发生在哪里

flora_lighting_cache.comp.slang 按准备后的草茎/轴向层接收点着色，叠加 DDGI 环境光和本地直接光，再写入缓存。令 G 表示这些实际接收点的数量，而不是简单的草株数或屏幕像素数。

local_visibility_query.slang 仍有全灯循环和每灯十二点循环。共享了遮挡事实，没有共享光源选择。

八盏参与计算的灯，不等于全部发光体

LOCAL_LIGHT_GPU_CAPACITY = 8 是当前显式 small-N 选择预算；CPU 光源注册表并非只能有八盏。场景里存在更多灯笼/发光体，不表示 GPU 已经计算了它们全部。

未来验证 16、32、64 灯时，必须核实实际上传与选中数量，不能只往场景里加物体。

另外两个边界不能绕开：spacing 32 的间接光系统保持不动；灯边的近场响应不能靠提高曝光补回来。先前的无障碍诊断已经出现精确向上响应约 711.108、旧探针插值为 0 的情形。它证明那条具体插值路径不合适，并不证明所有光照场在理论上都不可行。[20]

本地代码与既有性能证据
  • 光源预算与选择 · 十二点面光积分 / 二十四个稳定源身份 · 现有缓存接收端循环
  • 世界空间草照明入口 · 草带缓存顶点路径 · 只输出颜色的草片元接口
  • 既有 M4 Pro / Vulkan–MoltenVK，三个交错 30 秒 Release 对照：草 GPU 中位数 28.472 → 22.812 ms，整段 profiled FPS 17.1465 → 18.5292。只证明旧可见性缓存有局部收益，不证明复杂度改变，更不预测新方案。

03

工业界有成熟路线，没有不附条件的唯一答案

经典栅格化路线

Clustered / Forward+

Avalanche 等引擎的实务资料展示了空间分桶、前向渲染和透明材质的适配方式。这是成熟的候选剔除手段；局部重叠灯仍需要逐个计算。

可借鉴：把不相关灯尽早排除。
不能宣称：分桶自动保证固定接收端成本。[11]

现代随机直接光路线

ReSTIR / RTXDI

2020 年原始方法之后，2021 年专门讨论生产化：降低成本、提高访存一致性、压缩射线预算、暴露质量/性能调节。持续维护的 SDK 提供了可核查实现。

可借鉴：用重采样减少昂贵着色。
不能宣称：论文倍率就是本机收益。[1][2][7]

独立的引擎级佐证

Unreal MegaLights

Epic 当前文档明确采用固定逐像素射线预算、重要性采样和降噪。灯光复杂度增加时，预算不随每盏灯线性增加，但画面可能变糊、噪声增加或出现拖影。

可借鉴：固定预算，质量承担复杂度。
不能宣称：MegaLights 就是 ReSTIR，或可直接搬进本项目。[10]

对本项目最有用的共同原则：不再追求每个微小接收点每帧确定性地完成全部光源积分，而是共享选择/重用工作，将昂贵可见性与着色限制在少量样本上。传统分桶、随机采样和缓存是不同层级的工具，并非互相排斥，更不是换一个名词就已经实现同一种算法。

idTech 8 的已发售作品也展示了世界空间光源列表、辐射缓存、照度体和最终 gather 的职责分离。但其照明缓存着色仍使用局部光列表，并存在每格 ID 上限；整套 GI 的毫秒数不能当成本项目草直接光的证明。[17]

04

八类方案：分别解决了哪一层

比较标准不是“有没有顶会论文”，而是：普通草接收端是否还枚举全部重叠灯，是否保留实际近场响应，当前接口是否承载得住，以及用什么误差换什么成本。

窄屏下表格可横向滚动；聚焦表格区域后也可用方向键。

方案接收端成本 / 退化本项目适配与局限结论

先证明相对较简单 RIS 的额外收益。
屏幕 ReSTIR DI + 降噪[1][18]固定候选和邻域预算，时空复用提高有效样本数。拒绝历史时噪声增大；复用/纠偏增加成本或偏差。主可见表面质量潜力最好；草当前输出的是缓存颜色，需新增表面/运动/历史接口。缩小分辨率还要保住细草覆盖。中长期渲染迁移

不把“更便宜的每灯”当“少计算灯”。
DDGI / 照度体 / Froxel[16][17]共享照度，接收端常数查询；以空间/角度带宽、泄漏、滞后和存储为代价。很适合间接光或体积/透明的低频近似；固定 32 的旧直接照度插值已有近灯失败。重写拟合并不能自动成为成熟方案。保留间接光用途
本轮不再以加密或补亮修直接光。
源空间可见性缓存[20]减少部分场景遍历；仍是 G × L × 12，且需要更新、内存和回退。已有本机收益，但结构性硬条件未满足。它是局部可见性优化，不是多灯聚合表示。不作为最终主线
保留独立基线，不继续叠补丁。

Stochastic Lightcuts 也证明了“用随机噪声替代层次近似的相关性伪影”是一条既有研究路线；但不能因此把它等同于已经适配本项目的平台、实时预算和草缓存。[14]本轮没有发现一个可以同时免去许可审核、接口适配和原生性能验证的现成通用库。

05

推荐路径：先用官方已有的世界空间采样入口

完整目标是成熟的随机直接光管线，而不是承诺“一条光线就够”。当前接口最自然的起点是 RTXDI 文档已经定义的 buffer-less 采样模式：与完整屏幕 ReSTIR 区分命名，不冒充已经获得时空重采样的全部质量优势。[3]

共享：准备候选分布

收集权威光源，建立全局功率预采样池或等价的已知概率分布。灯数/空间规模足够大后，再选 ReGIR 局部样本池。

输入：L 盏光
输出：ID + 权重 / PDF
不是：最终照度

草接收点：固定预算重选

每个输出读取固定 M 个候选；各候选只评估抽中的一个发光样本，按此处的距离、法线和材质重加权。不在 PDF 内重做十二点积分或阴影遍历。

固定 M × K 次候选评估
有界随机访问光源记录
不枚举 L，不扫整格样本池

最终样本：可见性 + 重建

每个接收点最多 K 条选定连接，复用现有 Contree / Glass 传输接口；正确加权后与原有 DDGI 合成，再处理噪声。

K 条最终连接
不是 K 盏 × 12 条射线
不以全灯回退填补缺样
T ≈ Tshared(L) + G · K · [M · Ccandidate + Cvisibility] + Treconstruction
若采用 ReGIR，Tshared 还包括网格槽位数 × 每槽构建候选数；共享分布的全灯处理不再乘上 G。

这是目标工作量模型，不是已实现的复杂度证明。成立前提：共享分布取样本身有界、M/K 固定、不隐藏全灯回退；可见性遍历仍随几何复杂度变化。完整 ReSTIR 的邻域验证/纠偏射线和降噪要另计，不包含在这个 RIS-only 模型里。

为什么不会重演“近灯响应插成 0”

ReGIR/RIS 存的是光源 ID 和采样权重，不是周围探针的向上照度。真正的距离衰减、接收法线和发光面方向在草的位置重算，因此不依赖“下方有一个有效暖色照度探针”。

但这只排除了旧的机制性丢光：候选分布仍可能对近处小灯给得太少，有限帧也可能没有抽中。源 PDF 和目标 PDF 不能在真实贡献非零处错误归零；统计噪声和有限样本偏差仍需测量。[4][6]

保留现有发光模型，不同时改题

现有盒状发光体有十二点参考积分和二十四个稳定源身份。接入时将其作为明确的离散采样域，保留面积权重、功率归一化、范围窗和端点所有权规则，再做概率校正。

不能只选一盏灯后继续跑十二点；也不能改成更亮的点光源来获得“差不多的暖光”。若以后采用连续面积采样，应作为单独的模型变化与参考比较，而不是悄悄混进优化。

ReGIR 不是默认必装的第二个“大场”

官方文档说明，一个格子会保留数百至数千样本；附近挤着很多灯时，它也不擅长从这些灯中替真实表面做最终选择。当前仅八盏选中灯，先比较较简单的均匀/功率 RIS 与共享预采样；只有空间分布导致的浪费明显，才增加 ReGIR。这样既遵守成熟方法，也避免把新网格的固定开销误当作免费。[3]

超出网格、尚未准备好或样本不足时：仍采用固定预算的全局功率/均匀采样，而不是回到原先的全灯积分。SDK 的实际初始采样代码也有这类有界全局采样路径。原始积分只保留为明确 A/B 基线或稀疏审计，不允许成为多数接收点的隐蔽“兜底”。[7]

06

可以退化，但必须知道在退化什么

有明确理由的取舍

用统计误差换掉重复积分

  • 有限样本噪声：原来稳定的十二点积分变成少量加权连接；空间/时间上会有亮度波动。
  • 历史与重建：降噪可能抹掉细节，时域积累可能滞后或拖影；风动细草尤其敏感。
  • 复杂度升高时质量下降：预算不变，更多互相遮挡的亮灯需要争夺样本，不可能维持任意场景下同等误差。
  • 有偏设置：ReGIR 有限池和某些复用/可见性复用可有偏差，必须把偏差计入接受结果，不能统一称“无偏”。
不属于可接受的算法取舍

不把错误包装成近似

  • 灯边持续失去暖光，再靠全局亮度或曝光补偿。
  • 源 PDF 错误归零、漏乘权重、范围错误、删除灯后仍发光。
  • 多数接收点退回全灯十二点，再宣称固定预算。
  • 换成更少的参与计算灯、更粗的草、更低的测试画质，却与原模式直接报加速比。
  • 用“生产中常见近似”豁免 NaN、无效资源、跨版本读写或存档改动。

本项目优先交换：首先允许少量可度量的采样噪声；其次才考虑受控的时间重建。不要先选择确定性 top-K 删灯、近灯能量损失或空间照度过度模糊。前者有清晰的统计误差机制和样本预算旋钮，后者可能直接改变花园的照明设计。最终噪声/延迟可接受程度仍要通过实际画面和原生测试决定，本报告不预先签发质量合格证。

RTXDI 的噪声指南明确警告：初始采样并不保证复杂场景的实时画面质量；时空重采样是重要降噪手段，历史和可见性处理又会引入各自的偏差及成本。Epic 对 MegaLights 的公开说明同样列出模糊、噪声和拖影。这些是选择该范式时应接受并管理的产品取舍，而不是接入后才发现的意外。[4][10]

为什么完整屏幕 ReSTIR + NRD 不能现在就称为“最小改动”

标准时空管线需要当前/前帧表面、运动信息和光源身份映射。NRD 需要逐像素法线、粗糙度、viewZ、motion 等引导。当前草带顶点读取准备好的颜色，草片元只输出颜色；这条接口不提供完整的草表面 G-buffer。引擎其他地方存在深度或相机矩阵，不等于细草已经有正确的逐像素历史。

风摆、弯曲、修剪、换层和遮挡暴露都必须处理历史失效。把 reservoir 改放到草的世界空间缓存并自创邻域重投影，也不是“照接标准屏幕 ReSTIR”；那会变成另一项需论证的适配工作。本轮不沿这个方向即兴发明。[3][5][18]

07

固定接收预算，不代表全系统没有成本

原始光源上传、分布构建、空间池更新、历史缓冲、同步和重建都还存在。采样也没有令几何可见性变成常数时间。以下只是从已核查结构推算的容量账本，不是新方案的本机显存或耗时实测。

结构 / 假设仅载荷估算未包含什么
ReGIR：16³ 格 × 512 槽 × 8 B16 MiB额外紧凑光源数据、常量、全局池、历史与在途资源
上述 ReGIR，每槽 8 个构建候选16,777,216 次候选评估 / 帧假定全槽更新；便宜评估不等于阴影射线，也不等于免费
DI reservoir：24 B × 2 数组 × 2560×1440168.75 MiB块线性 pitch、额外数组、G-buffer、运动/历史与降噪资源
相同假设，512×2886.75 MiB低分辨率地形画面不代表完整草覆盖；重建细草还要付代价

ReGIR 的槽位写入为 uint2；可选紧凑光源数据单独存储。DI reservoir 的被核查结构为 6 个 32 位字段。上述双数组是简化使用情形，实际必须使用 SDK pitch/布局，不能按这张表直接分配。[3][7]

目前可以确定

固定 M、K 且使用有界分布查询后，普通草无需做全灯十二点积分。选中的灯和发光点仍用真实接收项和实际几何传输。模型与代码入口都有成熟依据。

目前不可以确定

哪组 M/K 的噪声足够好、ReGIR 是否值得、M4 Pro 上是否更快、连续编辑是否吞掉收益，都没有本项目新实现的数据。论文或 SDK 的其他 GPU 数字不能填补这个空白。

08

一个会改变“直接拿来用”结论的发现

GPL-3.0 项目，不能默认直接合入 RTXDI / NRD

本项目代码采用 GPL-3.0。所核查的 RTXDI-Library 标注 LicenseRef-NvidiaProprietary，其 NVIDIA RTX SDK 许可 §4(e) 对使 SDK 承受特定开源义务的使用有限制；NRD 的已核查版本也采用 NVIDIA RTX SDK 许可。这不是 MIT/BSD 组件的常规 vendoring，未取得兼容授权与许可审查前，不应合入发行路径。[8][18][20]

算法选择，与代码许可分开

RIS/ReGIR/ReSTIR 是可以研究的成熟方法；不等于每份实现都能按 GPL 分发。可以针对公开数学方法独立表达兼容实现，但不复制受限 SDK 源码，也不把这件事当作“现在可以发明一个新估计器”的许可。

如要求直接采用 SDK，先拿到适用的兼容授权。论文、书章和 SDK 的许可不同，算法名称也不提供专利清权保证；本报告不是法律意见。

连“书里的代码是 MIT”也要核查

Apress 配套仓库说代码通常采用 MIT，除非章节另有说明；但本轮取得的目录没有找到 Chapter_23，未能确立一个可直接取用的 MIT ReGIR 实现。

作者托管的 ReGIR 书章 PDF 则标注 CC BY-NC-ND 4.0。因此报告只链接资料，不把其插图、伪代码或 SDK 源码当作可自由搬入项目的资产。[6][19]

平台也不能跳过。RTXDI 样例的官方路径是 Windows/Linux、D3D12/Vulkan，经 NVRHI 与 DXC；应用自行提供采样、表面和可见性桥接。项目则是 Rust + Slang + Vulkan/MoltenVK + 自定义 Contree/Glass 传输。算法不强制使用硬件 RT，但官方 Vulkan 样例成功不等于 macOS/Slang/MoltenVK 已验证，更不保证软件遍历后的速度。[5][9]

Cycles 的已核查 light-tree 文件标注 Apache-2.0，是值得保留的许可较清晰备选；仍须逐依赖检查，不能据一个文件推定整套移植都已过审。它的对数树选择成本也不满足严格的常数查询要求。[15]

因此，明确推荐算法路线；明确否决“未经审查直接把 RTXDI SDK 接进当前 GPL 工程”的交付方式。

09

下一轮只有这些证据齐全，才算实现成功

本轮到调研和选型为止，不启动渲染实现。以下是实施前后的准入清单，不是已完成的功能清单，也不以测试计划代替性能结论。

  1. 结构门：昂贵工作真的从全灯积分里移出生产 shader 和编译产物证明普通路径只使用固定 M/K；统计真实候选、最终射线、异常路径和全灯回退次数。常规全灯回退应为零，不以少量快样本掩盖多数草仍跑原积分。
  2. 模型门：比较同一个照明问题DDGI spacing 32、发光体、强度、曝光、间接项、草密度与几何保持一致。先验证离散源域的高样本期望与原十二点参考一致，再比较采样噪声；不能沿用旧缓存“同帧 RGB 几乎完全相等”的审计目标要求随机估计器每帧相等。
  3. 近场与质量门：双向误差，不是“够暖就通过”回放无障碍近灯失败样例；实测默认/seed 7 的真实草位置和法线。比较参考的线性 RGB/能量、区域误差分布、置信区间、静态噪声和运动拖影；暗区使用绝对误差，不能除以接近零的基线。更多灯时同时报告质量下降。
  4. 生命周期门：删灯不是慢慢忘掉在采样结构生效后执行新增、移动、强度/颜色变化、删除与遮挡编辑。光源身份和版本一致；失效历史不能继续贡献已删除光。历史丢弃后的正常收敛噪声，与使用陈旧数据是两回事。种植、修剪、风摆和显隐变化也要覆盖。
  5. 成本门：实际上传灯数 × 实际草接收点的伸缩测试以较小矩阵比较 K = 2/4/8、每输出 M = 4/8/16 作为候选预算，而非预设胜出配置。测当前八灯与真正上传的更多灯，区分候选 ALU、可见性、分布/网格构建、滤波、内存与同步。先选择质量达标的设置，再比较速度。
  6. 原生门：全程 Release，完整成本入账串行交错 A/B、同二进制/相机/配置、独立且只读的真实生产输出审计；报告稳态、冷启动和持续编辑。保留原生错误检查，不用 debug 或单测时间替代 GPU 证据。seed 7 + Glass 已知 DDGI 非有限值基线问题单独披露，不称本轮已修复。
  7. 停止门：不因路线成熟就继续叠复杂性若 RIS 在能接受的 K 下仍无法稳定近灯，或者新增 ReGIR/降噪成本抵消收益，就暂停这个具体接入方案，评估完整屏幕管线或光树的明确成本放宽。不要退回大面积精确积分后宣布固定成本，也不要重新自研一套补偿场。

结论的置信边界

高置信：旧结构未改变全灯十二点消费；成熟随机采样可以把最终可见性限制为固定预算；RTXDI 有官方 buffer-less / ReGIR 入口；当前草接口与标准屏幕降噪有明显差距；SDK 许可必须先处理。

工程判断：先用共享预采样 + RIS，比立即建设完整 ReGIR/屏幕 ReSTIR 更适合当前八灯世界空间草缓存。尚无证据：本项目最终质量、M/K、平台兼容性和新方案加速幅度。本轮没有用外部论文数字冒充这些结果。
