# 六种花头的立体造型迭代

## 范围与造型原则

此次覆盖游戏内六种模型花，不包含草、树叶或藤蔓。沿用现有原生渲染、像素采样、
光照和风响应；只调整共享花头曲面及各物种配方。保留物种 ID、顺序、茎层数、
调色板、UV 分区、单个完整花头与 socket；已有花园无需迁移，重建后使用新造型。

造型由 `assets/models/parametric-flower.mjs` 唯一生成，
`assets/models/flower-source.mjs` 只提供数据。没有物种专用网格分支。

- **野老鹳草**：比上一轮更明确的五瓣浅碗，缩窄交叠区，匙状花瓣与外翻尖端。
- **勿忘草**：紧凑圆冠，花心隆起，短瓣柔和下垂；花头尺寸为原配方的 0.9 倍。
- **滨菊**：从扁平尖瓣轮廓改为拱起的带状花瓣，花心为低穹顶；16 瓣减至 14 瓣，
  为像素化轮廓留出间隔，而非不断增加细瓣。
- **波斯菊**：宽扇形缺口瓣、浅碗与不齐的翻边；第二轮收窄花瓣，避免重新连成圆盘。
- **松果菊**：高锥形花心与长而有脊的下垂花瓣，增强上下层次。
- **郁金香**：直立杯壁与包裹的宽肩，瓣尖略张开；仍是单圈开口杯的风格化近似，
  不是多层交错的真实郁金香模型。

共用曲面新增最宽处位置与中段拱起。横向卷边沿花瓣中线的局部法线移动：
直立花瓣向内包裹、下垂花瓣向外折，不再一律沿花头固定轴抬高。根部与封闭瓣尖的
横向偏移为零；中心和花萼不受花瓣控制影响。新参数可在网页临时调试，不增加原生
Debug 控件或持久化字段。共享生成器也供五个网页专用预设使用，纳入浏览器回归。

前两轮对照同时查看原模型、32px、16px 与侧视 32px。第二轮进一步减少滨菊细瓣密度、
缩窄波斯菊和野老鹳草的交叠，同时恢复勿忘草足够突出的花心。侧面深度与物种大轮廓
优先于细小纹路。16px 下仍会损失瓣尖缺口、卷边和相邻花瓣间隙；不宣称微小细节在
所有距离可辨。原生截图的固定种植夹具有前后遮挡，网页光照也不等同游戏光照；
最终外观仍待用户在游戏中旋转观察验收。

六个默认花头合计 7600 个三角形（此前 7776），没有增加拓扑密度或新的渲染路径。
这只是几何规模记录，**不是性能提升证据或大规模种植性能验收**。

## 网页深度参考检查的误报修正

### 影响范围

本次新郁金香在 64px 正交侧视角触发测试参考值不匹配：`0.0001732782`。
确认是测试 oracle 的舍入归属问题，不是原生渲染错误；生产深度及 RGBA 未修改。
其他恰好接近子像素半格的几何也可能触发，不仅限于郁金香。

### 根因

JS 用双精度投影，GPU 用 float32。在像素 `(45.5, 27.5)` 附近，共享顶点 X 为
`45.156251585`，距半子像素阈值 `45.15625` 只有约 `1.6e-6`。
旧参考强制选择上方网格点，GPU 选择下方点，导致参考测试选错可见三角形。
诊断只改变该边界的舍入选择后，该视角最大误差降到约 `2.03e-7`。

### 引入时间

旧的确定性子像素舍入假设见 `4d81c83f`（2026-09-27）。此次造型触发了这个假设的
边界条件；不能据此推断历史所有设备或花型都出现过误报。

### 干净修正

测试参考的唯一实现移至 `tests/raster-depth-oracle.mjs`。对 float32 精度范围内的
半格顶点枚举相邻合法舍入，并仅把可能成为最近表面的歧义样本标记为不适合做精确
深度比较；被稳定前景挡住的歧义三角形不豁免前景检查。普通样本仍使用原阈值，所有
原始 RGBA 检查照常运行。回归覆盖实测郁金香案例、普通内部点、边界、遮挡与多分辨率。
这是测试参考精度建模，不是改渲染器、改花型躲测试或统一放宽误差容限。
