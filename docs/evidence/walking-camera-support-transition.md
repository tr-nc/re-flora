# 行走离地瞬间的镜头下跳

日期：2026-10-17。起点：`1e6b0ef2`。这是[小地面障碍通行](walking-ground-detail.md)体验后的独立反馈：行走中有时像瞬移一样突然下沉。

## 影响范围

已复现：下台阶或走过胶囊圆底的支撑边缘时，某帧失去 grounded，镜头瞬间消除此前台阶平滑留下的高度差。3/6/12/16体素落差、30/60/120 Hz、新旧地面障碍开关都能触发这一类问题。

固定120 Hz的真实 `Camera::prepare_walk_movement → CollisionWorld → Camera::apply_walk_movement` 测试中，3体素下降台阶的第37帧：

- 身体位移 Y：**0体素**；
- 切换前镜头高于身体锚点：**1.4208603体素**；
- 镜头当帧位移 Y：**-1.4208603体素**。

另一个确定性接口测试中，16体素下台阶的视觉缓冲尚余约10体素，下一帧仅把支撑改为 false 就全部丢弃。这是镜头切换不连续，不是这一帧身体穿进地面。

用户原始地形和路线没有轨迹记录，不能认定所有“突然下沉”都只有这个原因。实际物理落差、其他相机效果和新的具体场景仍需分别验证。

## 根因

`Camera::apply_walk_movement` 原来只在 grounded 时平滑视点；否则直接 `position.y = collision_position.y`。视觉高度修正的生命周期错误地依赖瞬时支撑标志：当 capsule 接触离开台沿，真实离地可以成立，但这不意味着已有视觉高度差应在同一帧清零。

复现命令：

```bash
cargo test walking_down_ledge_keeps_camera_continuous -- --nocapture
```

修改前失败输出包含 `(120, 3, 0.0, 37, 1.4208603, 0.0, -1.4208603)`，分别为帧率、台阶高、地面细节容许量、帧号、已有视点高度差、身体Y位移、视点Y位移。把地面细节容许量改为3得到同一结果；测试使用固定帧时间且直接观察基础相机位置，不包含 head bob。因此本例不是新落脚采样、帧时间尖峰或 head bob 导致。

上轮回归只证明能跨过凸起、不能爬墙、最终能落地，没有检查 grounded 切换瞬间的视点连续性。这是之前验证的缺口。

## 何时引入

`git blame` 和 `git show` 确认，`3f342a6f`（2026-07-20，`smooth capsule movement over voxel steps`）引入了地面高度平滑，同时加入离地后直接对齐碰撞锚点的分支。后续扩大过平滑高度范围，但该切换一直保留。

这是该不连续机制的引入时间，不是本次发现时间。上一轮 `1e6b0ef2` 未修改镜头运行逻辑，本次也没有证据表明用户原始路线在之前版本经过完全相同的区域。

## 干净修复

唯一修改的运行时所有者仍是 `src/gameplay/camera/controller.rs`：

- 统一通过 `resolved_walk_camera_y` 解析地面/空中视点高度；不再在调用处用 grounded 分支清掉修正。
- 地面继续使用原来的指数跟随与高度差上限，数值不变。
- 离地时视点直接加上真实身体位移，携带已有的台阶视觉高度差；落地后继续平滑收敛。这既不瞬间补齐旧偏移，也不把真实跳跃/重力运动再过滤一次。
- 没有已有高度差时，空中的相机轨迹与身体锚点保持一致；起跳立即生效。
- 显式重新定位、模式重置以及原有大位移保护继续清除旧偏移。
- 不修改角色碰撞、grounded 事实、重力、跳跃速度、贴地距离、12体素步高和防爬墙策略；不增加调参开关。

没有采用“一离地仍假装 grounded”或“减小重力/放慢全部下落”的办法。这样落地/跳跃逻辑和脚步物理位置继续只由碰撞权威决定。

- `cargo fmt --check`、`cargo check`、`git diff --check` 通过。
- `cargo test`：主程序 **1623 passed / 7 ignored**；辅助碰撞测试 **4 passed**；显示授权测试 **1 passed / 1 ignored**；剪贴板原生测试3项按原设置忽略。无失败。日志：`target/camera-descent-app-tests.log`。
- `cargo build --release` 通过；`cargo run --release -- --hidden --mute --auto-exit 0.5` 正常首帧和退出。日志：`target/re-flora-logs/re-flora-20261017-011744.385-64134.log`，无 WARN/ERROR/VUID/panic。
- GUI和相机快照文件运行前后 SHA256 一致；无生成文件、配置或 shader 改动。
