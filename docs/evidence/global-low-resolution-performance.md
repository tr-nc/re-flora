# 全场景低分辨率性能对比

## 结论

**不是按像素数成比例下降。** 同一原生三角形渲染路径中，把内部像素数减至 1/16，GPU 整帧 p50 只下降 **19%–25%**，约 **1.24–1.33 倍**提速，而非 16 倍。降低分辨率确实有效，但不会同步减少模型数量、几何处理、姿态准备、DDGI 探针、独立阴影资源和 CPU 工作。

另一项收益必须分开计算：与旧版启用逐模型网格的路径相比，新低分辨率路径在 82,454 株草的宽景中，GPU 整帧 **13.64 → 5.64 ms**，约 **2.42 倍**提速。这包含删除图集的收益，不能全部归因于分辨率。

## 方法与边界

- 实验基准源码：`eeb553aaba40e192f18f32ecc4255734d00415a9`。
- RTX 3060 Ti，Linux/native Vulkan，固定窗口 **2560×1440**，Release 构建。GPU/驱动信息：`target/global-low-resolution/performance/gpu-before.csv`。
- 同一路径三档：内部 **1280×720、640×360、320×180**，相对像素数 **1、1/4、1/16**。只临时改变 `scene_resolution::SCALE` 生成诊断二进制；之后恢复 0.125。没有添加生产分辨率配置或 A/B 开关。
- 附加两档旧版本：实验前保存的 `baseline-release`，分别关闭/开启草逐模型网格。它们不是纯分辨率消融，只用于区分历史图集成本。各二进制 SHA-256 存于测量 JSON。
- 三个固定相机、固定模拟/响应时间及种植时钟；小场景 **4,098** 株，大场景 **82,454** 株。相机坐标、目标和人口在所有档位一致，由脚本断言。
- 每组 300 帧采样，舍弃边界四帧；两次正反顺序重复，每指标/相机/档位 **592 个样本**。所有 GPU 运行串行，不同时编译。
- 正常 AUTO 实际选择 FIFO：完成 30 次；发现呈现等待后，显式指定 IMMEDIATE 做另外 30 次补充测量。**以下主表使用 IMMEDIATE，FIFO 结果另列**。不更改游戏默认呈现模式。
- GPU 用 Vulkan 时间戳；CPU 单列。各重复 scope 在帧内先求和。嵌套区间不得相加，CPU 与 GPU 也不拼成串行预算。
- 无 ERROR/VUID/hazard，全部 `failures=0`；用户两个配置文件的 SHA-256 在每次运行后保持不变。
- 未锁定 GPU 时钟。IMMEDIATE 各次运行结束的遥测为 1905–1920 MHz、P0；FIFO 出现 1485–1920 MHz。结束遥测不是逐帧硬件计数器，无法证明整个采样期时钟固定。p95 包含间歇工作和系统波动，不把小幅差异当作确定优化收益。

## 单独降低分辨率：GPU 整帧

单位 ms，单元格为 **p50 / p95**。

| 场景 | 1 倍像素，1280×720 | 1/4 像素，640×360 | 1/16 像素，320×180 | p50 下降 | p50 提速 |
|---|---:|---:|---:|---:|---:|
| 近景，4,098 株 | 4.709 / 7.060 | 3.870 / 8.236 | 3.631 / 5.699 | 22.9% | 1.30× |
| 宽景，82,454 株 | 6.988 / 9.637 | 6.009 / 8.551 | 5.636 / 8.995 | 19.3% | 1.24× |
| 低机位，82,454 株 | 6.820 / 9.245 | 5.783 / 8.537 | 5.116 / 7.523 | 25.0% | 1.33× |

若整帧真与像素数线性，则三个 320×180 结果应约为 **0.294、0.437、0.426 ms**，与实测显著不符。640×360 → 320×180 的边际收益也已变小。

## 哪些阶段随分辨率变，哪些不变

以下为 IMMEDIATE p50，单位 ms；箭头是 1280×720 → 320×180。

| 指标 | 近景 | 宽景 | 低机位 |
|---|---:|---:|---:|
| `tracer.pass` | 0.776 → 0.097 | 0.675 → 0.245 | 0.675 → 0.080 |
| `graphics.flora`，草绘制后端 | 0.105 → 0.039 | 1.193 → 1.267 | 1.182 → 0.837 |
| 草共享准备 + 后端（帧内相加） | 0.223 → 0.157 | 1.824 → 1.893 | 1.819 → 1.466 |
| `tracer.shadow_prepass`，父区间 | 2.270 → 2.261 | 2.482 → 2.303 | 2.442 → 2.359 |
| `post_processing.pass` | 0.109 → 0.101 | 0.109 → 0.102 | 0.109 → 0.102 |
| CPU trace recording | 0.526 → 0.549 | 0.606 → 0.591 | 0.616 → 0.598 |

- `tracer.pass` 下降明显，但也不是严格 16 倍。
- 阴影前置父区间仍约 **2.3 ms**；它包括子阶段，不可再把其中 DDGI 等子区间相加到整帧上。320×180 时 DDGI probe trace 仍约 **0.85–0.89 ms**。
- 大量草的后端没有同比下降：宽景甚至小幅上升。低分辨率没有减少实例、顶点/图元、姿态和照明准备。具体硬件瓶颈需计数器证明；本报告不声称已证明顶点或带宽饱和。
- 最近邻放大输出和 UI 仍是原生窗口分辨率；低内部尺寸不会令所有全屏阶段都减少 16 倍。

## 删除逐模型网格：与旧版分开看

IMMEDIATE GPU 整帧 p50，单位 ms。

| 场景 | 旧版草网格关闭 | 旧版草网格开启 | 新路径同尺寸 1280×720 | 新路径 320×180 |
|---|---:|---:|---:|---:|
| 近景 | 4.840 | 5.848 | 4.709 | 3.631 |
| 宽景 | 7.401 | 13.644 | 6.988 | 5.636 |
| 低机位 | 6.654 | 10.279 | 6.820 | 5.116 |

宽景旧网格开启时，CPU trace recording **4.581 ms**；新路径同尺寸 **0.606 ms**，低分辨率 **0.591 ms**。这里主要是删除图集批次记录成本，而不是低分辨率减少 CPU 工作。

旧版关闭草网格后，成本已接近新路径同尺寸；保留在旧版的其他模型图集在这些草主导场景中并未产生同样大的差异。不能推广为所有模型/所有普通游玩场景的收益。

## CPU 整帧与呈现等待

IMMEDIATE `frame.cpu_total` p50（包含等待，不是纯 CPU 运算），同新路径 1 倍 → 1/16 像素：

- 近景：**9.974 → 9.203 ms**。
- 宽景：**14.506 → 12.415 ms**。
- 低机位：**14.294 → 11.987 ms**。

FIFO 正常模式下，三场景 CPU 整帧 p50 均约 **17 ms**，其中 acquire 等待约 **7.5–8.7 ms**。GPU 更快不必然提高被垂直同步限制的可见帧率；这里不把 GPU 区间的倒数冒充游戏 FPS。

FIFO 的新路径 GPU 整帧 p50 对照（1 倍、1/4、1/16 像素）：

- 近景：**4.879、3.990、3.944 ms**。
- 宽景：**6.391、6.188、6.049 ms**。
- 低机位：**6.709、5.782、5.727 ms**。

FIFO 自动时钟和同步等待会影响实际观察，所以不以这一轮单独推导无上限吞吐。
