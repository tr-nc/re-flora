## 风声音量延迟：已有机制，不是 Fast 未接线

- 声音每个游戏更新帧读取刚更新的共享风场，再进行树冠位置加权采样和 Min/Max 映射。
- Fast=1 对应指数响应速率 8/s，不是关闭平滑。生产函数的确定性测试给出：125 ms 达到阶跃目标的 63.2121%，375 ms 达到 95.0213%；下降 125 ms 后仍剩 36.7879%。
- Wind Item 的源包络用持续时间前 15% 渐入；默认持续 3 秒，源强渐入为 0.45 秒。局部源还通过时间积分注入共享传输场，而非立即覆盖风速。传播距离、覆盖树冠比例、风强与响应区间都会影响何时明显可闻；这些时间不是简单相加的固定延迟。
- 视觉局部扭转在风强 0.3 时已有一半压力系数，而默认声音满响应参考风强是 8，二者敏感度不同。更早看到叶子响应不证明音频更新被卡住。
- 未发现独立的“松手后才刷新音量”等待步骤。没有测量实际设备端到端延迟，也没有把上述机制测试当成听觉验收。

本次只补确定性诊断测试，不调整 Fast、风阵包络或用户音量。若需要 Fast 端点更接近即时，应作为明确的手感变更处理。
