# 自适应铺路弯道

背景：[现实铺装、Tiny Glade 与旧限制的调研](research/pavement-curves-and-layout.md)。

## 行为合同

- 鼠标在未铺部分画出的缓弯，应利用现有石板的四边形形变能力；某个偏好的圆角半径排不下，不等于这条路不可铺设。
- 光标确定尾部的位置，不必同时确定一个完整转角的最终切线。刚转弯的短尾部，可以先形成一段未完成的弧，再随输入调整。
- 正常向前延伸时，真实发布的地形和出口截面不可变。尚未发布的排，包括已编译排队的排，都可以重新规划；明确回拖则允许回收当前笔画的后缀，不能修改之前已结束的路。
- 接缝、实际石板尺寸、凸性、完整排、地面支撑、已有铺装保护和连续发布仍是硬约束。失败输入不保存为合法历史，不能在障碍另一侧重启铺设。

## 实现

`src/app/path_band/curve.rs` 拥有曲线规划：

1. 从相邻输入线段估计局部曲率，避免把原本平缓的线突然拧到默认圆角半径。
2. 按相邻线段实际可用长度分配圆角切入量，可以局部缩小半径。移除旧的 98% 占用拒绝和 120°角度拒绝；接近完全反向时仍显式断开。
3. 最后一段不够放下完整圆角时，求一条与入射线相切、准确终止于末端输入点的部分圆弧，不要求尚未画出的出射切线。原有输入简化的一体素误差走廊保留。
4. 局部平滑半径／切入量的上界控制流式规划范围，不是物理最小转弯半径。是否可铺，由最终几何判断。

`src/app/path_band.rs` 拥有截面和排的几何事实：

- `course_fits` 对实际道路条带检查严格凸性，取代冻结出口上的 `pitch / width` 角度上限。
- `replan_unpublished` 从 `CourseContinuity` 的实际发布检查点重新生成候选排；不把最远的排队排当成不可修改历史。
- 下一排继承已经发布的确切出口、编号和距离，预览与写入使用同一份排和石板足印。

`src/app/pavement.rs` 拥有石板排布和接缝：

- 沿真实边缘收缝之后，再检查每块石板的最短边及对边间局部厚度。
- 已有的两体素名义宽度下限，现在也作用于变形后的 XZ 足印；这不是一个新转弯半径比例。数学上仍凸、但只有 0.054 个体素短边的薄片不会被当成可用石板。
- 任一必要石板无法生成，拒绝整排，不能悄悄漏掉内侧石板。

交互层不再通过把短尾部光标投影回直线来补救固定圆角的失败。地面快照、真实 GPU 模型写入、实时 atlas 保护和发布路径保持原有所有权与检查。

## 验证

- 两个新增回归在修复前明确失败：三块宽道路的缓弯，以及尚未容纳完整圆角的短尾部。
- 生产候选交互测试覆盖左右弯、18／45／180 次输入、按实际间隔固定端点与释放残段；并验证先发布直线前缀后继续压缩转弯，旧足印／种子和接续出口不变。
- 保留极端保存尺寸、半砖、S 弯、平地／坡地封闭网格、真实回折、旧路重叠、无支撑地面、采样上限与拒绝后恢复的检查。
- `scripts/validate-pavement.sh` 在平地通过生产候选、支撑、GPU 预检和发布路径，验证半径 0.18 与 0.10、宽度 0.12 的左右弯：每个鼠标目标通过、完整排落地、每块内部 atlas 材料正确、重走 atlas 字节不变、保存重载不变。半径 0.10 时保留四个完整排；外侧独立细分后块数可超过旧版 Slabs 12 块／Brick 10 块。
- native pointer／continuity／recovery 脚本验证窗口输入路由、危险转弯红色预览、暂停期间 atlas 不变、直接合法目标恢复、已铺前缀不变、实时 atlas 障碍保护，以及释放／取消的声音所有权。拒绝阶段的固定回折角度保留约 160°；旧 recovery 输入逐步减小角度后现在可以合法铺设，不能继续把它作为“必须一直拒绝”的例子。
- `cargo fmt --check`、`cargo check`、`cargo test`、`cargo build --release` 和隐藏静音 Release 启动，配合逐个检查运行日志。

这建立的是几何及真实地形写入证据，不替代玩家对绘制手感、图案外观的批准，也不是性能验收。

## 从 2D 原型移植的排布

游戏现使用原型确认的自适应分排和外侧独立分块，不再将名义排长当成固定物理长度。`path_band/adaptive.rs` 对整个可变尾部做包含砖缝奇偶状态的完整分割，优先短排；候选合排通过原中心线的解析包含／前进检查和材料所有者的真实足印检查。找不到完整合法分割时保留失败排，不能漏铺或抄近路。共享截面只采样一次，下一排按真实 `end_distance` 和已铺出口接续。

外侧单元按名义排长独立纵向细分；每块重新物理收缝并检查两体素尺寸，无法细分就保留原合法块，内侧道不会因此消失。子块 seed 从排／道／子块编号派生；不分块的 seed 不变。真实石材模型沿同一足印映射，地形支撑和实时 atlas 保护不变。共享墙体／Dirt 默认仍用原采样，不启用铺路材料策略。

Debug → Pavement 的可保存平滑复选框保留原拟合（关闭）和有界向内收圆（开启）供现场对照，默认关闭；平滑范围默认 2×、可调 0.5–3×。同一尺度统一派生拟合、位置容差和 4R 可变尾部，参数在开始每笔时冻结。启用后仍保留输入起终点和射线方向，真实交叉／折返不受豁免。

原型记录移植回归覆盖两次原始薄片输入、长外侧块、向内圆角和连续第二弯，以及旋转／镜像和两种铺装。`cargo test` 1592 个 app 测试、4 个 collision 测试和 1 个集成测试通过；`cargo check`、Release 构建和 `scripts/validate-pavement.sh` 的真实 GPU 写入／重走保护／保存重载通过。GUI 字段由构建自动生成。这里验证的是原型行为移植与地形正确性，不是性能验收。

## 当前笔画的回拖回收

`core/pavement/retraction.rs` 拥有当前拖拽的输入检查点；`core/pavement/edit_history.rs` 的 `EditHistory` module 统一拥有体素归属、逐排体素／植被 receipt 和撤回事务。沿尾迹反向拖动，在道路宽度 ¼ × 回退范围的走廊内，从尾部向前查找有界回收目标；不依赖红／绿状态或是否已经铺出石板。默认开启、范围 2×，可保存控件支持关闭及 0.5–4×。已完成的其他路没有参与这笔的回收历史；Dirt 仍保留原地表刷行为。

- 检查点同时保存 planner、连续发布出口／编号及输入、覆盖、体素／植被事务的前缀长度。恢复后截掉整个后缀，局部残段仍经过相同几何、支撑和实时 atlas 保护；不是只缩短线条。
- 每块石板在真正 stamp 前读取即时 before-image，不能复用整排预检时的旧矩形快照，因为相邻块可共用体素边缘。只保存实际字节差异和之前的所有权。撤回先预检整个后缀，发现其他地形写入冲突就明确报错，不覆盖它；共享体素按最后保留的前缀恢复。矩形中未改动的体素保留当前值。
- 撤回走同一个 Visible Terrain Publication，更新地形网格、射线、碰撞、光照和连通性观察者；晚期 GPU 写入失败仍发布已经成功写入的范围，不声称有未实现的故障原子性。
- 植被所有者返回精确删除 receipt，只恢复被这笔删掉的根，保留原 response identity、seed、growth 和绝对 spawn 时间，不用全世界快照倒带其他植物。重复恢复不重置已经存活的植物；与其他 authored root 冲突时拒绝覆盖。
- 实际指针与投影编辑端点分离，停住或松手不能重新长出旧尾。回收到起点的释放不补成一次点铺装；取消／换工具发生在下一帧之前时也先完成已请求的回收。当前笔画的临时检查点／receipt 不写入存档，保存的仍是最终体素和植被。

原型原始回拖记录在 Rust 交互接口中覆盖石板／砖、旋转／镜像；另有红尾、停住、缩至起点、继续分支、共享体素与外部冲突、植被幸存者不倒带的确定性测试。`scripts/validate-pavement-prototype-native.sh` 通过真实 GPU 写入检查两种材料的已铺回收、土壤和既有路 atlas 字节不变、植被数量与身份恢复、未等下一帧就取消、2× 平滑锐角发布，以及新进程存档重载的 atlas CRC／植被身份和 seed。

`EditHistory` 的 interface 同时用于生产调用和确定性测试：记录一次实际 stamp 时更新 receipt 与归属，撤回时统一预检、写入、发布、恢复植被，全部成功后才退休后缀。内部 `RetractionTarget` seam 有 App 和内存两个 adapter；GPU 与植被身份仍由原所有者维护，不新增全局地形副本。测试覆盖共享体素、同排重叠矩形、未改动的外部体素、冲突零写入、第一／后续写入失败及发布／植被失败。GPU 失败仍不具备故障原子性，调用方必须结束该笔画，不得当成已回滚后重试。

原有 pointer／continuity／recovery 脚本也保留回拖开启：几何拒绝目标从捕捉走廊外开始，恢复目标在原有效输入头之前方。旧测试的微小反拖现在是合法笔画编辑，不能继续要求它一边回收石板一边维持旧发布计数。没有通过关闭回拖或改变游戏守卫来让测试通过。

最终 `cargo test`：1596 个 app 测试、4 个 collision 测试和 1 个集成测试通过；`cargo fmt --check`、`cargo check`、Release 构建、隐藏静音启动及上述五个 native 铺路脚本通过。只更新了 GUI 构建生成字段，没有手改 shader 派生文件，也没有移植 HTML 日志主机／回放或整条路撤销工具。原型的密集锐角／回拖手势歧义仍是已知边界，并非本次移植宣称修复的内容；尚无新的性能验收。

## 当前边界

仍然保持固定横向分块和四边形石板。不支持内侧合块、三角块或通用局部重排；当真实接缝／体素尺寸不足或条带折叠时仍拒绝。未宣称复刻 Tiny Glade 的内部算法。

试玩：`cargo run --release -- --flat-terrain`，按 **V** 在平地拖拽铺路。
