# 蝴蝶 Blender 管线：一手资料复核

## 结论

**3D 预渲染是已发行像素游戏验证过的制作路线，但不等于低成本自动生成好看的 8–16px 精灵。** Dead Cells 证明它适合反复改动作、复用模型；Celeste 美术作者的具体案例则证明，低分辨率表现依赖主动取舍和逐像素设计。没有行业抽样，不能据此声称「大多数像素游戏」使用任何一种路线。

本次已阅读 [v2 调研](../../experiments/butterfly-method-comparison/blender-v2/research-3d-to-pixel.md) 与[现有管线审计](butterfly_sprite_workflow_research.md)，直接抓取下列一手正文复核。仅研究，不制作资产、不修改运行时代码。

## 可核查案例：制作工具不是运行时表示

| 案例 | 一手证据与边界 |
| --- | --- |
| **Dead Cells：3D → 离线 2D 帧** | Motion Twin 美术 Thomas Vasseur [亲述，What / Result 小节](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)：先画像素 model sheet，再用 **3DS Max（不是 Blender）**建模、绑定；小尺寸无抗锯齿渲染；“export each frame … to a .png, along with its normal map”。角色约 **50px 高**。因此这里是预渲角色精灵＋法线贴图参与着色，不是运行时绘制该角色的骨骼网格，也不是全游戏所有素材都由 3D 生成的证据。[官方产品页](https://dead-cells.com/)可核实游戏已发行。 |
| **Celeste：手工像素设计的具体角色证据** | Pedro Medeiros [本人文章，第 2 节](https://saint11.art/blog/thoughts_on_low_resolution/)解释 Theo：突出胡须、头发、围巾与背包；躯干向后移 **1px** 表现放松姿态；加入格纹，舍弃耳机、口袋甚至脸。原文为 “I made him … by moving his torso one pixel back”。这是已发行作品中人为设计像素的明确实例，**不证明整款游戏所有帧都纯手画、完全不用程序或 3D 参考**。[开发团队文章](https://exok.com/posts/2019-12-10-celeste-pixel-art/)确认作者讲解本作像素制作流程；[游戏官网](https://www.celestegame.com/)可核实产品。 |
| **同一作者的混合路线：3D 仅作参考，最终重画** | [Using 3d models as pixel art reference](https://saint11.art/blog/3d-ref/)：旋转咖啡招牌手画各角度太费力，于是 Blender 粗模录屏，Aseprite 缩图减色、筛到 32 帧，再在另一层重画：“just drew everything on another layer”。作者同时承认 “a long process”。这是作者另一个案例，**不是 Celeste 的制作证据，也不将其计入已发行游戏样本**。 |
| **t3ssel8r：运行时真 3D，不能算预渲精灵案例** | [Cascadeur 官方对作者的采访](https://cascadeur.com/blog/general/making-an-animation-for-a-3d-pixel-art-game)：作者明确说 “true 3D assets in-engine”，用途包括共享武器、动画混合及跨模型复用动画。像素外观不代表输出了 PNG 帧；该采访描述开发中项目，不作为已发行案例。 |

## 成本与 8–16px 限制

- **有来源的收益与代价：**Vasseur 认为改关键帧、改姿态和复用部件是主要收益；也承认低分辨率有闪烁像素、细节不足，手修可处理但违背其追求速度的目标。这是作者自身经验，不是我们的耗时基准。
- **手工并非落后路线：**Medeiros 的[低分辨率文章，第 1、2、6 节](https://saint11.art/blog/thoughts_on_low_resolution/)强调每像素承载意义、删减细节，极小时甚至舍弃轮廓线。3D 投影负责空间一致性，不能替作者决定哪些像素最能表达蝴蝶。
- **以下是工程／美术推论，不是案例测量：**16×16 只有 256 个画布格，8×8 只有 64 个；有效不透明区域更少。亚像素翼纹、触角、薄翼边容易随姿态消失或跳点，1px 边线也可能挤占主体。50px 人形的成功不能直接外推到 8–16px 蝴蝶；增加模型细节不增加输出像素预算。
- **成本要看修改次数：**Blender 有模型、绑定、相机、采样及导出设置成本；手画少量帧可能更直接，多角度同步和后续改姿态则可能更费工。混合路线同时承担设置和清理成本，且重渲后手修可能重做。目前没有数据能断言哪条更便宜。

## 推荐一个小实验：比较最终像素，而不是模型截图

**建议先做两条制作路线的离线对照，不承诺 Blender 必胜。**沿用现有审计的 16×16、五相位、5fps；优先运行时实际使用的物理行 1、3，共十格，其他三行待视觉通过后补齐。

1. **统一设计输入：**先定展开／半开／合拢剪影、胸部锚点、主色块。A 为手工像素候选（现有图作基线），B 为最简 Blender 身体＋四翼，一套动作、固定正交相机与画布；同列同相位，禁止逐帧 auto-fit。让身体可以有意升沉，不强求整张 alpha 质心不动。
2. **保留 B 的原始与手修两个版本：**先试直接目标尺寸采样；仅在轮廓失败时追加高分辨率渲染再量化对照。旧文建议的 128→16 是待测选项，不是成功保证。记录所有手改像素和工时，别把手修成果标成纯 3D 自动生成。
3. **16px 原尺寸循环＋整数最近邻放大一起看：**检查蝴蝶辨识、胸腹是否退化为细杆、开闭翼节奏、孤点闪烁、两视角及镜像切换、末帧回首帧；保持同背景、显示尺寸和播放速度。8px 另做缩小压力预览，失败时尝试专门简化，不修改当前 16px 导入契约。
4. **测真正的修改成本：**分别记录初建、清理、导出时间；再给两路线同一个任务（例如加宽后翼或改合拢姿态），记录重做时间与跨视图错误。先让人评视觉，再比较成本，不用渲染速度代替制作效率。
5. **选择依据：**B 原始版若不好看，手修版仍可作为有效候选；若十格已需大幅逐帧重画，则将 Blender 降为运动／透视参考。通过后才扩成 80×80、五行五列、透明＋四个不透明灰阶的索引图，并验证运行时。若以后做游戏内 A/B，须按仓库要求提供 Debug 运行时复选框；本研究不实现该功能。
