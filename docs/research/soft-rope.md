# Re: Flora 可复用软绳研究

状态：**游戏接入前的历史研究与候选设计**（原型提交 `d99b05f6`）。可交互研究原型见 [柔软之物 HTML 原型](soft-rope/index.html)。本文保留一手来源、当时的工程推论与未决问题，不是当前游戏的功能清单；后续实现以代码和可执行测试为准。浏览器原型只验证二维行为表达，不证明游戏中的三维碰撞、风筝飞行、流体或性能。

## 结论

建议以 **CPU XPBD 中心线粒子链**作为第一阶段：段长、抗弯、挂接和接触共用求解框架。麻绳、细线、基础软管复用拓扑、时钟、碰撞接口和渲染输入。水管若确实需要扭转、接头转向、盘卷记忆，再加入带材料标架的 **Cosserat Rod** 能力，而不是为每个物品复制模拟器。[1][3][5]

这不是“所有材料只换参数”的承诺：仅有位置的模型缺少轴向扭转自由度；增加迭代、加粗外观或提高抗弯都不能补出这个状态。中心线可以编码某些弯曲静止形状，但不能完整表示截面材料朝向。[3] Obi 的 Rope 不保存静止形状、Rod 不能运行时改变长度，是该产品 7.1 的具体能力限制，不是所有粒子链/杆模型的数学禁令。[5]

风筝空气动力、水管水路和玩家抓取属于独立玩法模块。绳索提供挂接点、形状、张力估计及长度控制接口，不负责知道物品叫“风筝”还是“水管”。

## 一手来源与能支持的结论

### [1] XPBD，2016

- 作者论文：[Macklin, Müller, Chentanez — XPBD: Position-Based Simulation of Compliant Constrained Dynamics](https://matthias-research.github.io/pages/publications/XPBD.pdf)。已阅读作者镜像的 PDF 提取文本；`mmacklin.com` 的直连抓取超时，不以那个失败请求充当阅读证据。
- 作者团队实现：[PositionBasedDynamics / XPBD.cpp](https://github.com/InteractiveComputerGraphics/PositionBasedDynamics/blob/master/PositionBasedDynamics/XPBD.cpp)。核对 `solve_DistanceConstraint` 的步长缩放、累计乘子和质量加权校正。
- 论文 Algorithm 1 / Eq. 17–18：预测位置，清零乘子，在迭代内累积乘子，按逆质量修正位置，最后由位置差重建速度。
- 其动机是解决普通 PBD 中材料“刚度”与迭代次数、时间步长耦合的问题。引入柔顺度后参数有对应的弹性能定义，且能估计约束力；**并不意味着任意步长、任意有限迭代、任意拓扑的数值结果完全相同**。
- 本项目推论：适合可调材质库；不要用“solver iterations”作为材料参数的权威所有者。

对段长约束，采用论文的离散乘子约定：

```text
C = |x_b - x_a| - L0
alpha_tilde = compliance / h²
Δlambda = (-C - alpha_tilde * lambda)
          / (Σ w_i |grad_i C|² + alpha_tilde)
Δx_i = w_i * grad_i C * Δlambda
lambda += Δlambda
```

每个子步开始清零 lambda，同一子步多轮求解累计；跨步 warm start 需要额外的设计与缩放，不能无意沿用旧值。对这个距离约束，力的标量尺度约为 `lambda / h²`；若 `C = distance - L0`，拉伸时 lambda 为负，可取 `max(0, -lambda/h²)` 作为拉力估计。必须先完成单位标定与收敛验证，不能把本页像素单位直接标成牛顿。[1]

### [2] Small Steps，2019

- [作者 PDF](https://matthias-research.github.io/pages/publications/smallsteps.pdf)、[Eurographics 官方记录与摘要](https://diglib.eg.org/items/322424d5-a24f-490a-a6bb-542233852032)。已读论文提取文本。
- 相比一大步做 n 次求解，论文实验中 n 个小步、每步一次 XPBD 求解降低了约束误差和数值阻尼。
- Section 4.3/4.4 还讨论了初始穿透导致的分离速度、接触不等式和以法向乘子限制的库仑摩擦。
- Section 7：速度项误差、Gauss–Seidel 顺序依赖、过小步长下单精度误差仍存在。
- 工程推论：先试固定时钟下的少量内部子步，但同时记录碰撞查询成本。不要将文章理解成“碰撞也随便少算”或“重负载长链不用验证”。

### [3] Position and Orientation Based Cosserat Rods，2016

- [RWTH 作者研究页、摘要、论文与源代码入口](https://vci.rwth-aachen.de/publication/0550/)。已读取研究页摘要，不声称在本项目重现其论文性能结果。
- 使用中心线位置和单位四元数材料标架，耦合位置与朝向，描述弯曲和扭转。
- 补充实现说明：[Blender Developer — XPBD Method](https://developer.blender.org/docs/features/nodes/xpbd_solver/xpbd_method/)，已读取其 stretch/shear、bend/twist、contact 和 damping 说明。公式约定应回到选定求解器统一，不把不同文档的 lambda 单位混用。
- 工程推论：软管圆截面的几何外观可能看不出绕轴旋转，但内部扭矩、接头朝向和弯扭耦合仍可受其影响。

### [4] Unreal Cable Component

- [Epic 官方 Cable Components 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/cable-components-in-unreal-engine)，已读取。
- 使用 Verlet 积分、粒子链和距离约束；迭代控制有效刚度；将中心线生成管状网格。
- 碰撞选项在每个子步对粒子 sweep，官方明确警告碰撞/刚度带来额外成本。
- 工程推论：适合解释轻量绳特效的可行起点，但不等价于完整的物理软管，也不能证明本项目的性能。
- 概念澄清：Verlet 是积分方式，PBD/XPBD 是约束求解框架，不应当把“Verlet vs XPBD”当成同一层面的互斥选择。

### [5] Obi 的 Rope / Rod 边界

- [Obi 7.1 Rope/rod blueprints](https://obi.virtualmethodstudio.com/manual/7.1/ropesetup.html)，已读取。
- Rope：位置粒子、distance + bend；Rod：带朝向粒子、stretch/shear + bend/twist。
- 文档指出分辨率下降时粒子之间会出现碰撞缝隙，并区分可裁断/变长的 Rope 与保持形状/抗扭的 Rod。
- 价值是成熟产品的能力划分，不是建议将 Unity 插件直接引入 Rust/Vulkan 项目，也不暗示商业插件许可允许拷贝实现。

### [6] 碰撞不能只看粒子

- [Obi 7.1 Surface collisions](https://obi.virtualmethodstudio.com/manual/7.1/surfacecollisions.html)、[Collisions](https://obi.virtualmethodstudio.com/manual/7.1/collisions.html)，已读取。
- Surface collisions 把绳段作为线 simplex；接触点修正经重心权重分配给两端，避免仅检查粒子留下的空间缝隙。
- 仍有局限：每 simplex–collider 对只生成一个最近接触，复杂凹形状可能漏掉其他接触；共享粒子的相邻元素需要过滤，避免自相矛盾约束。
- 文档还区分自碰撞、绳间碰撞，以及刚体双向耦合和 kinematic 单向模式。
- 工程推论：原型用线段–圆的离散最近点；真实花园需要段/胶囊对地形和模型的查询、摩擦、必要的连续检测。**空间上覆盖整段不等于时间上的 CCD**。

### [7] 风筝的力

- [NASA Glenn — Four Forces on a Kite](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/four-forces-on-a-kite/)，已读取。
- 升力垂直来流、阻力沿来流、重量向下、张力沿线；稳定时各分量平衡。
- 工程推论：风筝模块使用相对风速、姿态、面积、升/阻力系数和提线点产生力与力矩；绳索模块约束端点并传递反作用。本原型只有二维标量风力驱动的示意加速度，不能验证迎角、失速、翻滚、尾翼稳定或风筝布面。

### [8] Rapier 备选

- [Rapier 官方 joints 文档](https://rapier.rs/docs/user_guides/rust/joints/)，已读取。
- 球关节锁定两刚体局部挂点的相对平移而允许旋转；还提供固定、转动、滑动及通用关节。
- 工程推论：短的粗重链条、多个需要独立转动惯量的段，可以先比较现有刚体链；长细绳的对象数、约束收敛和大质量比要测试。不以直觉断言它一定比自写 XPBD 慢。

### [9] 曲线标架与管状渲染

- [Hanson & Ma, Parallel Transport Approach to Curve Framing, Indiana University TR425, 1995](https://scholarworks.iu.edu/dspace/items/39fbe931-c2c8-43a1-9c9d-a207b92d551e)。已核验学校馆藏记录、作者和报告日期；未逐式审阅该 PDF。
- 候选渲染设计：沿曲线平行移动标架，避免简单 Frenet 标架在直段/拐点的退化；遇到反向切线、零长度段、闭合环还要定义稳定规则。此处是工程建议，不是本项目已验证能力。

## 可复用系统的边界：候选，不是已实现 API

### 定义层

- 弧长参数化静止中心线、线密度、半径、轴向柔顺度、抗弯刚度；Rod 扩展另有静止曲率、扭转刚度、材料朝向。
- 不把所有属性压成一个 softness。麻绳可以很容易弯，同时很难拉长。
- 与模拟分辨率无关地定义材料，然后离散到段：轴向弹簧 `k = EA/L`，柔顺度 `L/(EA)`；以转角为约束的弯曲能 `E_b ≈ EI/(2L) * (Δtheta)²`，其角柔顺度随 `L/(EI)` 缩放。这里的 `L` 对应选定的段/对偶长度，必须与实际离散公式一致。[1][3]
- 半径改变碰撞包络也改变物理截面属性；不能只更新渲染网格。HTML 故意只开放未标定的手感百分比，不暗示已经完成材质实验。

### 模拟层

- 独占节点位置、速度、逆质量、静止段长、乘子、拓扑版本与睡眠状态；Rod 可选通道持有材料标架与角速度。
- 约束注册、接触处理、外力采样与时间推进有明确顺序。长链仍可能需要更多内部子步、对称扫、分层或全局方法；只有出现可重复收敛问题才引入后一层复杂度。
- 局部段长等式可防伸缩，松弛通过中心线弯曲出现；低抗弯的链不是全局直杆。若建模的是仅限制两端最大距离的 taut tether，则用拉力单边约束，不能将负拉力当作绳在推风筝。真实负载耦合要验证松弛时不传递非物理推力。
- 初始形状、挂点和碰撞体必须可行；在岩石或地面里生成一条绳，再用高阻尼压住爆炸不是正确初始化。

### 挂接与玩法层

- 区分世界固定点、运动学抓取点、动态刚体局部挂点；局部挂点跟随位姿，动态模式有反作用。
- 对刚体挂点的约束有效质量包括平移与转动项；反作用产生角冲量，不能只给质心一份线性力。
- 跨 Rapier / XPBD 的分裂求解需要固定的更新顺序和同步子步。单向读取当前刚体位姿再迟一帧施力，可能在大质量比下不稳定；先隔离验证，再启用负载玩法。
- 抓取优先软约束 + 有限目标速度；不任意把中间粒子瞬移到不可达位置。解除挂点不能残留约束引用。
- 收放线按材料弧长推进，在卷轴口增删/重采样粒子，按线密度更新质量，处理新粒子的速度、动量和 UV 连续。截断删除跨断口约束并更新碰撞邻接；Rod 同时处理材料标架。不是把所有 rest lengths 一起缩短。
- 水管先有独立端口连接图/流量状态，按需用弯曲或扭折量影响通水；普通杆不能自动模拟截面压扁与折瘪。

### 渲染层

- 使用只读模拟快照，按显示帧插值，不写回物理状态。
- 中心线采样、管截面边数、屏幕空间最低可见宽度与模拟粒子数分开。样条可能越过接触包络，需受限插值/接触区保留折线，不能为漂亮而穿石。
- 麻绳捻纹先用材质/法线/程序纹理；截面几何只表达轮廓，不为看不见的股线做独立碰撞。
- 水管先用低边数管、沿弧长的稳定 UV 和接头网格；细风筝线考虑屏幕空间宽度与抗锯齿，但保留真实物理半径。
- 高频变形几何是否参与 DDGI 遮挡需要独立决策，不能默认每帧重建体素。初期可先作已有光照场的 raster consumer，再评估自阴影和接触阴影。

## 验证与落地关卡

先给视觉反馈，不用尚未确定的硬性能阈值阻挡原型；但 NaN、资源越界、破坏存档或不可恢复的碰撞错误不能当作“视觉实验可接受”。

1. **手感**：三预设拖拽/松手、无风/阵风、固定/自由端；软管抗弯与麻绳有可见差异。HTML 展示这层，未取得用户美术批准。
2. **不变量**：不同 30/60/144 Hz 显示帧分组推进同一固定时钟，比较状态；检查约束残差、有限值、挂点漂移；后台恢复不做巨型时间步。
3. **接触**：花园实际地形、台阶、薄柱、岩石、接头；高速扫过、快速拖拽、运动中的地形编辑；地形 revision 切换后的接触不能读半更新数据。二维离散圆碰撞不构成此项通过。
4. **拓扑**：放线、剪断、删除绑定物、物体传送；质量/动量和稳定句柄策略明确。自碰撞过滤邻段但不能漏掉远处同绳段。三维打结须单独验证。
5. **刚体耦合**：静态悬挂、1:1/1:10/1:100 负载候选矩阵；自由端无外力下不凭空增能；张力/反作用方向正确。上述是拟议测试点，不是已通过数据。
6. **Release 成本**：候选 1/10/50 根 × 32/64/128 段，分别记录求解、碰撞查询、网格生成/上传与帧耗时分位数。比较开关前后和休眠/活动状态；记录硬件与驱动。HTML FPS、Node 测试耗时、论文 GPU 数字都不是本项目性能证据。

## 本轮原型的已知边界与未决问题

- 二维、49 点、固定 240 Hz、每步 8 轮；百分比抗弯是演示映射，**未实现按分辨率标定的生产材质**。
- 段长与有符号转角用 XPBD；地面和线段–圆接触是离散硬投影；地面只有切向速度衰减，**不是静/动库仑摩擦**。
- 没有自碰撞、CCD、跨物体碰撞、可靠打结、真实收放线或扭转。快速拉过障碍、先关闭碰撞使绳掉下去再开启，可能造成不可行穿透；可重置观察，不作为生产碰撞方案。
- 没有三维风筝姿态/升力矩、喷头刚体、水流、压扁、折瘪、漏水或断裂；风筝只是受风驱动的端点负载。
- 软管应偏软橡胶、编织管还是会回卷的塑料管？用户确认外观/手感后再决定 Rod 范围。
- 玩家是否真的需要穿环打结、缠绕树枝、拖动重物、剪断和收线？这些会显著影响碰撞和拓扑优先级，不能默认为都在 MVP。
- 绳长、同时活动数量、最低显卡、游戏尺度与目标帧预算尚未确定。当前不承诺 GPU 必要性或具体毫秒指标。
