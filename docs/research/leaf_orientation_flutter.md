# 轴对齐体素树叶：局部抖动与内部叶片朝向

2026-09-11；只读调研，代码基线 `c577702e`。本文没有运行 GPU、改动着色器或宣称视觉验收通过。主分支正在删除 Kochia，实施时必须使用 `FLORA_SPECIES_TREE_LEAF` 等符号，不能照抄本基线的物种数字。

## 结论与约束

可以保留现有轴对齐 cube，以**一个叶片机械状态 + 一个叶片光学状态的统一模型**表达所需细节：机械状态包含缓慢偏移以及有界局部平移；内部叶片朝向可以转动，用于在叶中心求出当帧唯一颜色。所有顶点、所有面使用同一颜色。绝不旋转几何，不添加正反面网格或面材质，不制造叶内颜色渐变。

准确的定位是“一个体素代理未解析的薄叶片”，不是“立方体表面的物理材质”。方向驱动反射与透射有物理依据，但固定方块轮廓、整块同色是明确的美术约束；因此不能把该模型称作完整物理正确的叶片渲染。维护性来自明确这个边界以及统一状态所有权，而非隐藏近似。

## 第一手证据

1. **整体摆动和局部抖动是不同自由度。** Tadrist 等对榕树叶和人工叶片的风洞实验区分枝条运动与叶片相对枝条的运动；后者可能由湍流受迫、尾流耦合或气动不稳定产生。论文的扭转模型为 `J θ'' + 2 J ζ ω₀ θ' + J ω₀² θ = M_air`。其稳定性取决于入流角、风速、惯量、刚度和阻尼。特定试样约 4 m/s 起振不是所有叶种的通用阈值；游戏风当前也没有 SI 标定，不能直接套数值。[Tadrist et al., 2015, §§1–4](https://yakari.polytechnique.fr/Django-pub/documents/tadrist2015rp-1pp.pdf)
2. **叶片色彩变化不只是两种底色切换。** Wang 等将叶片外观拆为表面粗糙反射、组织内部散射产生的漫反射和透射，用 BRDF/BTDF 表达方向关系，并分别处理环境光和太阳直射。不同叶种需要不同参数；不能假定所有叶背都同样更亮。本文采用其物理分解，不移植其空间纹理、测量数据或 PRT 系统。[Wang et al., 2005, §§3–4](https://graphics.cs.yale.edu/sites/default/files/leaf2005.pdf)
3. **游戏里的分层已有实践，但不能把经验波形当作气动解。** Crysis 将主弯曲与叶片细节弯曲分开，并使用平滑三角波、实例相位及顶点标记控制细节。其透射是实时近似，可借鉴成本控制，不应照搬独立颜色振荡。[GPU Gems 3, Chapter 16](https://developer.nvidia.com/gpugems/gpugems3/part-iii-rendering/chapter-16-vegetation-procedural-animation-and-shading-crysis)
4. **光学朝向不能替代遮挡几何法线。** PBRT 明确区分 geometric normal 与 shading normal；混用会造成漏光和错误暗斑。我们的固定 cube 与自由旋转虚拟薄叶比普通法线贴图偏差更大，应该把虚拟法线限定在叶片光学求值，不用于移动光线起点或改变遮挡半球。[PBRT, BSDFs](https://pbr-book.org/3ed-2018/Materials/BSDFs)
5. Unreal 的 Two Sided Foliage 为薄叶透光提供专门模型，说明叶片应与厚实体散射分开；该引擎模式不满足本项目“轴对齐、整叶同色”的全部要求，不建议为名称相似直接引入。[Epic, Shading Models](https://dev.epicgames.com/documentation/en-us/unreal-engine/shading-models-in-unreal-engine)

## 建议的最小实现

### 1. 状态与驱动

每叶保留原平移状态，再增加 `theta, angular_velocity`（需要两个扭转轴时才扩展为四分量）。静态 `rest_normal, hinge_axis, lever_arm` 从稳定叶身份和树冠局部位置导出；将其命名为代理参数，不能声称当前树冠生成器提供了真实叶柄方向。

角状态采用受迫阻尼振子。力矩至少依赖同位置风、虚拟叶朝向、迎风面积及有效力臂；可用 `F ~ U_rel * |U_rel| * projected_area`，`M = dot(cross(r, F), hinge_axis)` 作为可解释的受力近似。目前风单位是艺术单位，增益需在游戏校准。局部位移使用同一角状态的小幅投影，例如 `d_local = bounded(R(theta) r - r)`；这只是 cube 中心平移，**不能**对 cube 的 `vertexOffset` 应用 R。

恒定风 + 正阻尼振子会最终静止。要在风中持续灵动，必须有持续激励：先用共享风场里实际的小尺度变化；若不足，再增加明确表示未解析湍流的有界、时间连续局部力矩，相关尺度与采样速度独立定义。不要加白噪声逐帧驱动力或直接 `color *= sin(t)`。用稳定相位不能保证它物理正确，但可使未解析激励可重复、可检查。第一版不实现负阻尼自激 galloping；它需要非线性饱和与阈值标定，单纯把阻尼改负会无界。

角度、平移、光学输出必须使用同一 published pose 时间桶。现有低频离散姿态是审美选择，不能让颜色 60 Hz 转而几何停在 5 Hz；也不能为了叶片改全局 World Tick。静风下所有驱动应消失，余振按阻尼衰减。

### 2. 统一的叶中心光学求值

令 `n = R(theta) n_rest`，`V/L` 在叶中心计算。薄叶近似用 `dot(n,V)` 判断内部代表叶片的可见侧，用 `dot(n,L)` 表达入射投影。漫反射和透射共享能量预算与同一实际太阳可见度；正反光学系数可以不同，但结果是**一个 RGB**，所有 cube 面都读取它。边缘过渡可以代表未解析的朝向分布，应连续且窄，不能硬切两种颜色。

在首版里建议先统一底色，只让方向相关反射/透射产生亮暗；如果需要叶背差异，再加一个有明确含义的背侧漫反射比与轻微色偏。用户禁止的是几何两面和叶内异色，不是内部薄叶状态；仍需将具体色差幅度作为视觉选择。不要用视角随便乘整个最终 HDR 颜色。

应有单一 `evaluateLeafAppearance(...)`，Legacy 与 DDGI 路径共用直接光部分。太阳漫反射当前通过风格化 shadowWeight 求值，仅旋转 `prepared.shading_normal` 并不会自动得到所需太阳角度变化。新叶专用光学函数须明确保留可见度、光源强度及环境光的职责，避免把阴影权重重复当入射余弦。

为控制范围，可先只让太阳的叶片光学项旋转，环境采用既有稳定代理方向，但必须记录这一近似。完整方向一致的版本应在每叶光照缓存内求方向相关环境项；不要把相机相关反射直接写进 DDGI 辐照度缓存，否则缓存语义改变。复用一个 RGB irradiance 无法还原任意方向的环境光分布，不能凭缓存数值猜两侧照明。

### 3. 遮挡、阴影与 ABI

保持 canonical receiver、射线 bias 使用现有几何位置/法线；虚拟朝向不旋转 shadow receiver 法线。阴影代理随真实平移已有链路移动；虚拟角只改变材质响应，不应每帧清空叶影历史或重建 DDGI。固定 cube 轮廓下，真实薄片翻转导致的投影面积变化无法严格还原，首版接受这一限制。

新增运行态及 held pose 应随存活身份保留，新叶初始化为静态姿态，删除立即解除状态所有权。修改共享 shader state 后通过构建生成 CPU 镜像，并验证 stride、offset、descriptor 及复制迁移；不手改生成代码。不改变 `LeafVertex` 输入，也不引入叶几何面属性。所有可见/LOD/光照缓存消费同一叶姿态帮助器，避免实现分叉。

## 验证与建议初值

初值仅用于视觉探索，不是植物实测：局部平移上限约 0.1–0.3 体素、典型虚拟角约 5–15°、振子固有频率约 1.5–3 Hz，先在现有离散姿态下避免过高频率混叠。全局摇摆仍由原响应承担，不用放大整体位移制造抖动。展示后再定性能预算。

- 固定近景单叶和整树，静风、轻风、阵风分别录制 A/B；检查整树运动与局部细动能区分，角状态与亮暗事件时间一致。
- 单叶各顶点输出 RGB 应完全一致；立方体边必须轴对齐，平移前后任意顶点差保持不变。检查近景所有面和 LOD 切换，不能只看远处树冠。
- 暂停 wind/pose，在固定光照下绕树看；再固定相机改变太阳方向。分别验证视角效应与入射效应。关太阳时太阳项必须为零，遮挡中不能发光。
- 检查无风回静、低帧率、停顿恢复、删除重建、地形加载及状态迁移；没有重播相位跳变或旧状态误用。
- 检查强背光、夜晚局部光、DDGI/Legacy、叶影时间累积；记录仍采用静态环境朝向的限制。
- 代码基本验证用 `cargo fmt --check`、`cargo check`、有意义的状态/ABI测试及 hidden muted release 日志。视觉验收必须使用实际游戏连续画面；单张图和统计数不能证明抖动自然。性能以固定场景 release A/B CPU/GPU 和状态字节数为准。

推荐先交付这一有限模型，并让“整叶同色、轴对齐、同一状态驱动”成为代码不变量。后续只有实际画面暴露问题时才扩展叶片物理或环境光方向表示。
