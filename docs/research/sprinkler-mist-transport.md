# 喷水器水雾：有方向的扩散、悬崖下垂与低成本地形交互

状态：**调研与实现建议，尚未改动产品渲染路径，尚无新方案的性能测量或视觉验收**。
代码基线：`f7ae4b9f`。已有模型、对象级采样、散射与暗线修复见[实现记录](stylized-sprinkler.md)。

## 问题与结论

用户认为新版散射明显改善，但补充了三个形态要求：

1. 悬崖边的雾应能越过边缘、漂到喷水器基座以下，而不是被限制成上半球。
2. 近喷嘴集中；传播后展开、稀释，远处／下方逐渐不明显，不能扩得越大、白雾反而越多。
3. 喷射有方向。同一高度上的分布应可能是有厚度的环带或数段弧，而非均匀填满的圆盘。

**建议：用少量有方向、有年龄和可见雾量的体积单元／路径段构成连续喷雾幕，并给运动加有限的地形约束。保留现有连续体积光学，不恢复可见水粒，不上完整流体求解器。**

形态更像展开、下垂、逐渐消散的薄伞裙，而不是实心半球、固定甜甜圈或浓白瀑布。碰撞是约束形态的一个输入，不是必须另建一套刚体系统。

## 当前限制的诊断

- **影响范围**：当前所有喷水器的视觉雾都不可能延伸到基座以下；悬崖／台阶使这一限制尤其明显。模型、动画、放置、浇水和现有散射不因此失效。
- **根因**：[mistDensityAt](../../shader/slang/sprinkler_mist_math.slang) 把密度乘以 `smoothstep(0.0, 0.012, position.y-base.y)`，把“喷水器基座高度”误用为整个区域的地面高度。另有固定椭球支撑域：中心高于基座 0.058、垂向半径 0.105；只有整体风偏移，没有传播年龄、喷嘴发射方向或地形响应。[积分器](../../shader/slang/sprinkler_mist.comp.slang) 的相机深度裁剪只负责视线遮挡，不负责雾的运动。
- **何时引入**：`acd6af69`（git 作者日期 2026-10-18）的初始连续雾实现已包含上述基座高度门限与固定支撑域；后续光照修复没有引入这一限制。
- **干净修复方向**：密度所有者改为方向／年龄驱动的传播分布；地面限制读取局部已发布几何，而非常量基座高度。包围体也必须包含向下传播的尾部。只去掉高度门限或拉长椭球只能解除截断，不能满足方向、稀释和地形阻挡要求。

## 一手资料与适用边界

### 少量体积单元，而不是逐滴模拟

NOAA HYSPLIT 的 [puff 教程][noaa-puff] 描述：跟踪云团平均轨迹及分布宽度的增长，可以替代跟踪大量单独粒子的湍流轨迹。[浓度方程][noaa-equations] 把平均风平流与扰动分开，并按雾团质量与扩散尺度求浓度。

这里借用的是**“中心运动 + 分布展开 + 雾量归一化”这一降阶表示**，不是把大气污染模型或其公里／小时尺度参数照搬进游戏。计算用的体积单元不会被画成球、粒子或广告牌；最终仍采样连续密度场。

该教程同时提醒：单元少不意味着总成本小。雾团覆盖的浓度网格越大，积分成本越高；一个雾团也不能描述所有高度的不同输运。这与本项目必须防止“少量路径，渲染时却遍历全部路径段”的问题直接相关。

### 边界交互不必等于完整流体模拟

Bridson 等人的 [Curl-Noise for Procedural Fluid Flow][curl-noise] 给出不求解完整流体方程的程序流场，并讨论固体边界处的切向滑移条件 `v·n=0`，以及用距离场修正势场。

但这**不等于任意噪声乘一个碰撞遮罩就会自动绕障碍**：论文的三维约束需要距离与法线，尖锐边缘还需专门处理。当前项目的占用位图也不是现成的 SDF。初版不建议为了细小水雾新建全世界距离场；低频扰动也先在少量路径更新处计算，不在每个像素／每个积分步计算多层 curl noise。

NVIDIA [GPU Gems 3 第 30 章][gpu-fluids] 的完整网格流体包含平流、外力、压力投影与障碍边界。它能做更多真实流动，但不是仅为“悬崖边下垂、碰到地面散开”所需的最小方案。

### 渲染成本必须单独计算

Epic [Local Fog Volumes 官方文档][local-fog] 使用屏幕 tile 剔除，并强调屏幕覆盖及重叠体积数量的影响。它不是本项目可直接移植的实现；它支持的结论是：**碰撞更新便宜，不代表新增的体积渲染便宜**。

## 建议的形态模型

### 1. 从实际喷嘴发射，保留历史

每个新生单元记录：喷嘴位置、发射方向／速度、出生时间、宽度及一份可见雾量。位置和方向应来自已有[尺寸／姿态所有者](../../src/sprinkler.rs)与[共享动画契约](../../shader/slang/sprinkler_animation.slang)，不能另写一套漂移的喷嘴动画。

当前硬件是每秒交替 X／Z 两对喷嘴，不是持续旋转的整圆喷头。因此：

- 年轻雾应有对应喷嘴的扇形／弧段偏重，而非出生就铺满 360°。
- 换向后旧雾继续漂移、扩散和淡出，新雾接上；不能让整片雾随活动喷嘴瞬间开关。
- 多个方向、不同年龄的雾叠加后可以接近环带，但不强制制造永远完美、均匀的圆环。
- 不用硬空洞把中央挖空：有限宽度与旧雾混合可以在中央留下少量稀雾。

在理想轴对称、无风／无碰撞条件下，传播年龄 `a` 对应一组半径 `r(a)`、高度 `y(a)`；若某一高度对应一个主要年龄，水平切面自然接近有厚度的环。实际喷嘴方向、风与地形会把环打散、偏移。这是几何推导，不是对任意真实喷头都成立的实验结论。

### 2. 外喷动量逐渐衰减，风与沉降接管

建议运动原型为带阻力松弛的平流：

```text
v_target = authored_wind - settling_speed * up
v_next   = v_target + (v - v_target) * exp(-dt / drag_time)
```

恒定目标速度的一步位移可用对应的解析积分；空间变化风场、地形接触处再做有界的短步更新。这里的速度、沉降与时间尺度需要在游戏世界单位下调视觉，不应直接把重力常量套入后声称是精确的水滴物理。

重点是源头有方向、后段慢慢随风下沉，而不是无限自由落体。初版不需要空气压力、液滴间作用或升腾热烟模型。

### 3. 扩散必须降低浓度

用有限支撑、边缘导数为零的核保留当前的柔和轮廓。例如一个椭球单元：

```text
a       = time - birth_time
m(a)    = initial_visible_amount * exp(-a / lifetime)
sigma_j = sqrt(sigma0_j² + 2 * diffusion_j * a + spread_speed_j² * a²)
q_j     = (p_j - center_j) / sigma_j
K(q)    = max(0, 1 - dot(q,q))²
rho_i   = m(a) * 105 / (32*pi*sigma_x*sigma_y*sigma_z) * K(q)
rho     = sum(rho_i)
```

`105/(32π)` 来自此三维单位球核积分的倒数；这是本方案的归一化推导，不是 NOAA 使用的核。可以转到喷射方向的局部坐标，以分别控制纵向厚度和横向张开。

**可见雾量不变时，展开只分散它，不凭空增加它。** 半径增大后峰值浓度下降；寿命项再表示蒸发／不可见化等损耗。`m` 是视觉液滴含量代理，不是灌溉水量；蒸发参数尚未按湿度、温度或真实粒径标定。

对于连接的路径段，应按段的体积／长度与所代表的出生时间区间归一化，不能给每个新分段复制一份相同雾量，否则细分会使雾变白。接触地面可沉积／丢弃可见雾量，不为“补回被裁掉的核”把其余部分强行增密。

这样可得到近喷嘴细而较浓、向外及向下展开后淡去的雾幕；“越低越淡”来自年龄与展开，而不是另加一个按绝对高度一刀切的衰减。

## 地形交互：分清三种能力

| 层次 | 能做到 | 做不到／代价 |
| --- | --- | --- |
| 相机深度裁剪（已有） | 雾不覆盖当前视线中更近的实心表面 | 不改变运动，不能保证雾不穿墙后在另一侧出现 |
| 几何约束的少量路径／单元（建议） | 短距离扫掠发现阻挡；去掉入射法向速度、保留切向运动；悬崖外无支撑时继续下沉 | 需处理有限支撑域、薄墙和尖角；只是可控近似，不是完整流场 |
| 完整三维流体边界 | 更自然的分流、尾流、涡旋与体积输运 | 网格存储、每步多次遍历、压力求解、编辑后的边界维护；当前目标不值得直接承担 |

第一版建议对**地形／大块固体**做第二层，不把每片叶、花瓣和每个装饰物都加入碰撞，也不让雾反推物体或反馈灌溉。

路径中心不穿墙仍不代表它的有限半径密度核不穿墙。仅把固体内部密度置零，也可能在薄墙另一侧留下同一个核的“幽灵雾”。实现必须明确采用局部保守支撑域／接触边界，或在受影响邻域做有限的可达性裁剪；不能拿中心点测试宣称已经支持任意墙体。具体核裁剪方式需用薄墙与悬崖夹具验证后选择，当前未完成。

**不建议只做高度图**：它能处理普通坡地与悬崖，却不能一般地表示洞穴、挑檐、悬空板及多层地形。也不能永远沿第一次碰到的无限平面裁剪，否则会在悬崖外重新造出一张看不见的地板。

## 项目接入与成本边界

可复用的事实：

- [DDGI voxel visibility](../../shader/slang/ddgi_voxel_visibility.slang) 已有 GPU 占用位图和单独发布的几何 revision；它不是距离场。查询必须检查 readiness、坐标换算与几何版本，不能把“未发布”当成“空地”，也不能误用延迟的辐亮度 revision。
- 此位图对树木使用独立处理，不能把占用位图一个点查询描述成覆盖所有树／动态物体的通用碰撞；首版目标限于明确支持的地形。
- [terrain query](../../shader/slang/terrain_query.slang) 能查询场景，但 CPU 接口 `query_terrain_rays_batch_with_validity` 当前会提交一次 GPU job、等待完成，再 read back。见 [`src/tracer/mod.rs`](../../src/tracer/mod.rs) 与 [`execute_one_time_gpu_job`](../../crates/re-flora-vkn/src/command/command_buffer.rs)。**不能把它放进每条雾路径的逐帧 CPU 循环**；同步往返可能比查询数学本身更值得担心。
- 若走 GPU 路径更新，应在正常帧命令中批量处理并留在 GPU，遵守已有帧槽 fence／资源生命周期。状态随现有喷水器实例所有者发布，避免另建一份 gameplay 发射器登记表；删除与索引重排不能让旧雾继承给另一实例。

可以从 **4 个喷嘴方向 × 每方向 6 个年龄节点，20 Hz 更新并在渲染时插值** 作为视觉原型起点。这只是试验预算，不是已证明足够平滑的参数，也不是固定产品上限。256 个喷水器对应约 12.3 万次节点更新／秒；每节点查询多少体素、碰撞短步上限与法线获取成本尚未确定，不能换算成已知毫秒数。移动扫掠应有步数上限与保守的耗尽行为，不能只测终点而穿过薄墙。

渲染时必须另外控制成本：

- 保留一个喷水器的保守包围范围，并让它覆盖全部下垂尾部；做屏幕范围剔除。
- 评估只访问少量候选路径段的表示／索引；不要简单把 24 节点再嵌入现有“每像素 × 每实例 × 12 步”循环。
- 远处低浓度雾的结束条件应来自剩余可见贡献与有限寿命，不是任意基座高度；合并／LOD 也不能复制雾量。
- 保留已认可的相函数、体积 DDGI 查询、阴影、透射与软边缘；不靠增加白色或提高全局密度来弥补形态。

尚未决定的是候选路径段索引和有限核的接触裁剪实现。它们会影响实际画面、复杂度和成本，应在一个悬崖视觉原型中确认，而不是在调研阶段承诺耗时。没有理由先为此构建全世界 SDF 或完整雾流网格。

## 下一步验证建议（未执行）

先做可比较的视觉原型，确认形态后再独立测性能；任何 A/B 实验都须有 Debug 面板运行时复选框，未勾选保留当前版本。不是只用 CLI 或两份离线截图代替 A/B。

- **平地／侧视**：源头连续、方向清楚；无中央实心白球、离散珠串、换向闪灭或突然断层。
- **水平切面／多个高度**：近源为喷嘴扇区，适当高度有环带／弧段；向下更宽更淡，不要求每个切面都是完美圆环。
- **悬崖／坡地／墙角／薄墙／挑檐**：悬崖外密度可低于基座；坡面／墙面可阻挡；核不在薄墙另一侧凭空出现。地形编辑后使用同一可见几何事实，不读半完成的重建。
- **数学**：同一单元增宽不增加积分雾量；调整时间步／细分数不复制雾量；年龄衰减、零密度恒等、零光不发白、核边缘连续。
- **原有回归**：自然地形暗线图像对照、雾内／遮挡／夜晚、放置／删除／重排／resize、对象采样独立、普通粒子关闭仍有效、浇水独立，GUI／相机和花头尺寸 1.11 不变。
- **性能另测**：Release 模式分别记录节点更新／碰撞、体积 GPU pass、整帧；比较 1／16／64／256 实例、低重叠／高重叠、近景／远景及当前版本。现有历史单实例计时不能证明新方案或 256 实例可接受。

本次只新增调研记录；上述新算法、A/B、碰撞和视觉／性能检查均未实现或运行。
