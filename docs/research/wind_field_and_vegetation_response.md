# 风场与植被响应：为什么有风，却仍显得死板

日期：2026-09-06。范围：只读生产代码审计、一手资料研究与视觉实验设计；不实现、不改参数、不启动应用、不跑基准、不提交。

审计基线：`main`，HEAD `b632b27078826e094bb2b384fb791621e86d49bf`；工作区原有 23 个未提交路径（材质候选、GUI 配置及 AGENTS 更新）。下文代码行号对应本次工作区，**不是把脏工作区当成纯 HEAD**。只新增本报告；已有修改保持原样。

## 结论先行

1. **当前生产风场没有地形遮挡、绕流或涡脱落。** 它把随风向平移的二维分形噪声与方向偏置叠加，再存入三维纹理；生成函数只读位置的 x/z、时间、风源和 GUI 参数，既不读取地形几何，也不使用高度 y。地形确实影响植物放置、生长和光影，但这不等于影响风矢量（生产链见下一节）。用户“似乎受地形影响”的感受仍值得保留为视觉观察，不能据此反推已有流体求解。
2. **不是完全没有颤动，而是已经有的颤动不具备阵风后的运动记忆。** 草/花有双正弦横向颤动，地肤有分枝 jelly 与梢部 flutter，树叶有拍动，果实有摆动。然而主响应仍是“当前风直接换算位移 + 当前风调幅的解析波形”。没有植物位移/速度的跨帧状态，也没有质量、弹性恢复力或阻尼积分。波形偶然向反方向运动，不等于由阵风释放触发的回弹。
3. **离散摆动是用户明确选择的美术风格，应保留，不是待修缺陷。** 当前保存的 `world_tick_seconds=0.05`，四桶轮转；正常逐 tick 渲染时，每桶及其可见植物动画每 0.2 秒更新，即 5 Hz。草的 40/80 rad/s 波形约为 6.37/12.73 Hz，发生混叠是可推导的采样事实，但它只是设计这种离散动作的频带约束，不能据此否定用户喜欢的节奏或要求改成连续动画。
4. **最小有价值的方向是在同一离散节奏下增加因果响应，不先建设大风模拟器。** 固定风输入、桶节奏和个体布局，以一株草/花、一簇地肤、一组树叶比较现状、事件式解析回弹与低自由度阻尼振子。认可回弹手感后，再增加有空间传播的阵风和小幅细节运动。呈现是否离散，与是否有惯性/过冲是两个独立维度。
5. **研究不是诊断完成。** 本次没有运行红绿视觉反馈环，没有记录脉冲响应，没有证明某候选已改善观感；“更像用户所要的 vivid 运动”仍须用户观看短片或实际画面决定。遵循 AGENTS 的最新视觉优先规则：先可见效果与快速反馈，认可后单独做 release 性能优化/验收；崩溃、无效资源、状态重置造成的意外跳姿等正确性问题始终不能豁免，不能把有意的逐格跳动本身归为故障。

将 shader 简写成公式，当前输入近似为：

```text
W(x,t) = Σ d_i · max(0, gain_i · bias + turbulence · N_i(xz − c_i t))
```

其中 `d_i` 是每个源固定的平面方向，`c_i` 来自方向和 speed；`N_i` 包含 gain 与多 octave 噪声，公式只为解释结构，确切尺度见源码。重要含义：

- 单个源的最终贡献非负，只沿自己的方向推；它不是具有独立横向分量的湍流。多个不同方向源的相对强弱可以改变合成方向；相反方向源也可以让合成风反向，不能说整个系统“绝不反向”。
- speed 改变图案平移速度，不直接改变平均推力。设 speed=0 是冻结空间图案，不是关风；gain/bias 才直接控制强度。调快“风速”不等于增加植物惯性。
- 所有 octave 使用同一个被平移的坐标，各 octave 只改变空间频率/权重；没有独立的涡生命周期，也没有由障碍物生成的尾流。
- 纹理虽为三维，场值在高度方向重复；它不是三维流体速度场。世界尺寸只是坐标映射，不是“地形参与求解”。
- `src/tracer/resources.rs:40` 为每 chunk 每轴 10 texel；一个 chunk 的归一化跨度对应 256 voxel（`flora_vertex.slang:56`），故名义格距约 25.6 voxel。空间线性插值提供局部连续性，也会滤掉无法由网格表达的细节；**本次没有测出它对当前视觉的重要程度**。不要把任意 FBM 的 octave 频率直接当作真实湍流能谱。

`surface_flora_vertex.slang:37-51` 确实读取 `chunk_atlas` 的湿度，但用途是 `floraEnvironmentGrowthFactor`；`flora.vert.slang:54-63` 把它传给生长裁剪。这里不是风遮挡。改变植株高度/密度、地形遮住部分植物，或相同 x/z 位置在画面中的投影不同，都可能让人感觉风受地形影响；这些只是待验证解释。

### 1.2 `src/wind.rs` 不是可见植被风纹理的 CPU 真值

`Wind` 本身是无字段类型（`src/wind.rs:97-108`）。其 `sample_sources` 调的是 CPU OpenSimplex2（`:78-83,110-129,152-177`），GPU 则是 classic gradient noise、逐 octave 换 seed，并额外加 directional bias/非负截断。两者不能当成数值一致的同一个采样器。

当前 CPU 调用见 `src/audio/tree_audio_source.rs:123-145`（树冠风声），以及 `src/particles/emitters.rs:219-228`（落叶生成倍率）。树冠音量在 `tree_audio_source.rs:152-177` 有 attack/release 指数平滑；它只控制音量，不会给顶点动画增加弹性或惯性。`wind_audio_attack_decay` / `wind_audio_release_decay` 不是视觉回弹参数。落叶生成用的是 `Wind::sample_response` 内建默认源，也不是当前 GPU 纹理。

因此，后续视觉实验必须在 GPU 生产输入处观测/注入，不能只画 CPU `Wind` 曲线就声称重现了草叶受到的风。声音与落叶同步是否需统一属于另一项产品选择，此次不扩大到实现。

### 1.3 四桶时序：有意的离散呈现，以及它的设计约束

`src/tracer/mod.rs:5375-5387,5406-5447` 初始化四桶，之后每次新 step 只更新 `step_index % 4` 的一桶；同一步直接返回，没有每帧平滑。`flora_motion.slang:61-106` 按 seed 选择桶，采样一个桶；没有读取前后两帧风做时间插值。

`flora_vertex.slang:264-265` 将 **可见风附加运动的时间** 也换成该桶最后更新时间，交给 vibration/jelly/paddle/swing。不是“风场低频更新，植物在帧间仍以连续时间颤动”。用户已澄清这类离散观感正是目标；本报告默认不插值姿态、不提高展示帧率，也不把 5 Hz 直接当作不灵动的根因。

当前保存配置（不能证明用户观察时的现场值）：

| 项目 | 当前数值与代码推导 |
| --- | --- |
| 世界 tick | `config/gui.toml:175-181` = 0.05 s；运行时最小值是 1/240 s（`src/game_time.rs:1-5`），不是永久固定 20 Hz。 |
| 每桶/同 seed 动画刷新 | 常规每个 step 都被渲染到时，`4 × 0.05 = 0.2 s`，即 5 Hz；其间零阶保持。整片植物有四个错开的时刻，不等于每株有 20 Hz 动画。 |
| 草/花颤动 | `config/gui.toml:1430-1458` 的 amplitude=0.5 voxel，speed=40/80；`flora_motion.slang:210-212` 直接进 sin，故是 rad/s，约 6.37/12.73 Hz。相对 5 Hz 采样，两项都超出 2.5 Hz Nyquist 频率；按恒定采样推导，会混叠到约 1.37/2.27 Hz，但实际视觉还叠加风调幅、像素尺度与其他动作。 |
| 树叶拍动 | `config/gui.toml:1474-1490` 两项 speed 都为 20；`:1562-1579` 倍率为 0 到 3。固定风强下两项现在是同频、不同相位的合成，而非两个不同速度层；强风端为约 9.55 Hz，当前每叶节奏无法无混叠地表达这个原始频率，但艺术上是否要保留这种逐格变化由视觉决定。 |
| 地肤 | `config/gui.toml:2188-2249` body response=0、branch amplitude=1、branch speed=1、phase spread=0、tip amplitude=0.23、tip speed=6。body=0 不会关掉 jelly/flutter（`flora_vertex.slang:258-280`）；phase spread=0 会取消显式分枝相位展开，但仍有分枝 speed/direction jitter，不能称所有分枝完全同步。 |

“高频参数数值”不等于观众真的看到了同频的细颤动。它可以有意成为逐格变化，但需要按实际采样后的动作调，而不是一味把 speed 增大。此事实不构成更改美术节奏的授权。

GUI 入口是 Debug 中的 `World Tick Time (s)`（`config/gui.toml:174-183`）；四桶数量目前是常量而非独立 UI。这个值不是风专属：会影响世界时钟/生长和日夜推进、粒子桶/喷头等调度。水模拟的调度还按该值乘自己的倍数并限制范围；刚体/苹果物理则另有独立时间步，不能笼统说所有物理都跟它一起改。后续实验应固定当前 world tick，不以修改全局节奏冒充窄小的风响应调整（入口与影响见 `src/app/core/mod.rs:2303-2315,3259`、`src/app/core/particles.rs:523-540`、`src/app/core/water/coordinator.rs:208`、`crates/re-flora-physics/src/lib.rs:14,368-378`）。

还有两个与“有意逐格显示”不同的状态一致性边界需未来验证，而不是本次修复：

- 低帧率跳过多个 step 时，CPU 仅更新当前一桶；shader 的 `windVolumeBucketUpdateTime` 却按“各 step 都曾更新”推算时间。因此纹理真实新旧与解析 motionTime 可能不符。暂停、时间跳转、漏 tick 应进入未来正确性检查，不能把“理想 5 Hz”当作所有运行情况的保证。
- 叶片使用 `sin(time × speed × frequencyMultiplier(currentWind) + phase)`（`flora_motion.slang:284-304`），不是累计 `phase += angularSpeed × dt`。风变时会重定相位；连续情形其导数还含 `time × multiplier'(t)`。这是可从公式推导的时间一致性风险，不代表已在画面中确认出现跳闪。第一轮可固定倍率排除它。

### 1.4 各类植物到底怎么动

统一入口是 `prepareFloraVertex`（`shader/slang/flora_vertex.slang:191-336`）。species 编号见 `flora_types.slang:5-12`。

| 植物 | 风采样/相干单位 | 生产位移和细节 |
| --- | --- | --- |
| 长草、短草 | 根位置采样，一株一个 seed/风桶 | 按相对根高度的幂函数弯曲权重，将风直接作为 voxel 位移；加种子固定的自然静态弯曲，再加横风方向双正弦。根部权重为 0，草高有 seed 差异（`flora_vertex.slang:154-166,235-287`；`flora_motion.slang:173-214`）。 |
| 薰衣草、Ember Bloom 花 | 每 voxel 的世界位置采样，voxel hash 选桶 | 与普通 surface flora 共用自然弯曲/双正弦，但高度权重用资源的 windGradient；**并不是整根花茎共用同一个风桶**。空间邻近位置仍受同一平滑场影响，voxel 时序却可分到四桶（`flora_motion.slang:109-115`；`flora_vertex.slang:235-287`）。 |
| 地肤 Kochia | 根位置采样，animationGroup 给每枝 seed/桶 | body 位移乘独立 response；分枝 jelly 是两项正弦，另有横风梢部 flutter；分枝相位、方向与速度可不同。动画组确由网格生成写入，并非未使用字段（`src/flora/construct.rs:127-141,180-193`；`flora_motion.slang:217-249`）。 |
| 挂树树叶 | 叶实际位置采样，叶簇 anchor 为基准、voxel hash 选桶 | 风乘叶簇径向 gradient²，加主要上下方向、略横风的 paddle。windGradient 是距 anchor 的几何权重，不是空间风速度梯度；它不表示涡或遮挡（`flora_vertex.slang:109-118,235-265,289-293`）。 |
| 挂树苹果 | 果实 anchor 采样、一个 seed/桶 | 不使用线性 body windOffset；使用解析摆角及弧形位移，有独立速度抖动与最小响应，因此无风时也可按设置摆动，但不是保留先前冲量（`flora_vertex.slang:261-263,294-296`；`flora_motion.slang:252-271`）。 |

树叶的 anchor 是实际 twig 附着点元数据：`LeafPlacement` 定义见 `src/tree_gen/tree.rs:138-144`；`:206-217` 从骨架末梢生成叶簇；`src/app/core/vegetation.rs:550-556` 上传局部位置为 leaf−anchor。它提供了未来叶簇整体运动的合理归属点，但当前没有通过这个 anchor 传递实时树枝力学状态。

树干/木质枝条与这些顶点动画不是同一路：树形编译为 round cones（`vegetation.rs:488-501`），由树干物理发布事务发布（`:1898-1903`）；树叶另由 `add_tree_leaves` 发布（`:1906-1917`）。本次有效风调用搜索只到上述 flora/leaf 路径，没有风驱动木质树干骨架的入口。不能把地肤的动画分组说成整棵树的层级力学。

### 1.5 主画面、LOD 与阴影：哪些一致，哪些刻意不同

主渲染确实调用这些代码，不是只找到孤立函数：`src/tracer/mod.rs:4463-4523` 对五类 surface flora 选择 `flora_ppl` / `flora_lod_ppl` 并提交 draw；`:4552-4582` 选择树叶的普通/LOD 管线。挂树果实也使用 leaves 管线（`:4659-4660`）。shader 模块和管线绑定见 `src/tracer/pipeline_builder.rs:372-436,943-1046`。

| 通路 | 姿态一致性审计 |
| --- | --- |
| 草/花/地肤 主画面与 LOD | `flora.vert.slang:45-75` 与 `flora_lod.vert.slang:45-75` 都调用 `prepareFloraVertex`；前者画 voxel cube，后者绕已变形中心画 billboard。因此共享动作公式/采样策略，不保证几何轮廓逐像素相同。 |
| 树叶/挂树果实 主画面与 LOD | `leaves.vert.slang:43-78`、`leaves_lod.vert.slang:43-78` 都从叶/果元数据重建 anchor 并调用同一个准备函数；区别仍是 cube/billboard。 |
| 草/花/地肤 投影 | 当前叶影生产批次只有 Leaves 与 Apples（`src/tracer/flora_frame_plan.rs:195-198,304-312`；`src/tracer/mod.rs:5176-5193`），没有 surface flora caster 批次。`flora_shadow.slang` 是接收光影的辅助函数，不是它们另有一个动画投影 pass 的证据。它们在主渲染接收 terrain/leaf/cloud shadow；草的叶影接收点还特意用静止位置（`flora_vertex.slang:322-333`）。 |
| 树叶 投影 | `leaves_shadow.vert.slang:184-204` 用 spray seed 选风桶，不用主画面的逐叶 hash；直接风偏移仍是 gradient²，但细节调用 `leafShadowSprayPaddling`，用连续 `pc.time`。`flora_motion.slang:11-12,312-347` 对拍动幅度和频率各乘 0.12，舍弃逐叶 shellPhase，以叶簇代理呈现低频整体变化。**主画面/叶影当前并非同姿态**，这是源码注释明确的代理设计，不宜直接判为 bug。 |
| 挂树果实 投影 | `leaves_shadow.vert.slang:196-198` 使用 `appleWindSwing`、同样 anchor seed 与桶时间；中心摆动机制与主画面一致，但投影几何为 LOD billboard。 |
| 脱落后的动态果实 | 不再经 `appleWindSwing`；`dynamic_fruit.vert.slang:44-52` 与 `dynamic_fruit_shadow.vert.slang:31-35` 读取同一实例位置/四元数。不能把它已有刚体旋转当作挂树叶片已经有受风动力学。 |

当前草花叶的运动核心是**移动 voxel 的 anchor**。近景随后加未旋转的 cube 顶点（`flora.vert.slang:73-74`、`leaves.vert.slang:76-77`），远景是面向相机的 billboard（`flora_vertex.slang:468-481`）。所以 `leafWindPaddling` 名称并不意味着叶片围绕叶柄转动，更没有法线随叶片扭转的完整机制。位移过大可能让相邻 voxel 看起来松散；将来若加入旋转，需同时审查根部连续、局部形状、光照法线、包围盒和投影代理。

## 2. 当前已经有与确实缺少的东西

| 机制 | 代码结论 | 对观感的含义，不是已证实根因 |
| --- | --- | --- |
| 空间相干 | 有：共享平移噪声、空间线性采样、根/分枝/叶簇归属。又有 seed 分桶及逐 voxel phase。 | 并非每株完全独立噪声，也并非整片完全同步；但 hash 的桶差异是调度差异，不应当作物理传播速度。 |
| 个体差异 | 有：草高、自然弯曲方向/幅度、相位、地肤分枝速度/方向、果实速度等。 | “再随机一点”未必解决；低频整体相关性与高频局部差异需各自保留。 |
| 振动/多频细节 | 有：正弦合成；树叶当前两项配置同频。 | 能调出更多运动，不保证出现阵风先推、释放后回弹的因果顺序。 |
| 弹性形状 | 有静态弯曲曲线、根部权重和弧线形状；没有弹性恢复力。 | 静态弯曲不是弹簧。 |
| 惯性、阻尼、任意风历史 | 可见植被链无位移/速度积分状态，无惯性/阻尼参数。 | 同一位置/seed/当前时间/当前风输入会得同一姿态，不知道之前是否被推过。 |

将现有主响应写为 `x(t)=a·W(t)+A(|W(t)|)·sin(ωt+φ)` 可以看出限制：当风归零且振幅响应归零时，风驱动细节也消失；相同当前输入不携带历史。**若要求对任意阵风都有停风余振，只调现有 amplitude/speed/bias 参数无法创建缺失的记忆机制。** 反之，若只要求恒定风下更有层次、稍有抖动和个体错相，现有参数可能就足够；应直接观察目标离散节奏下的结果，而不是以连续运动作为通过标准。

## 3. 外部机制：输入和响应应分别设计

以下只使用作者原论文、作者撰写的官方 GPU Gems 章节、官方产品文档和 NASA 验证案例；核对日期同报告日期。Stam/GPU Gems/NASA 原文已直接读取；SpeedTree 页面直接读取受限，但其官方页面的搜索索引返回完整相关正文，以下只依此转述文档，不推断 SDK 内部实现。资料中的历史硬件性能不外推成本项目性能。

### 3.1 可信机制依据

- **机械响应是对外力的滤波，不是直接复制风。** Stam 的原论文使用质量、阻尼、刚度矩阵构成动力学，再通过少数模态和频域随机合成产生树枝运动；它也强调相近枝条的风载荷应有空间相关。这说明“有弹性特征”不一定要求每帧做庞大物理求解，也不能把独立白噪声当自然风。[Jos Stam, 1997，原论文第 2–5 节](https://www.dgp.toronto.edu/public_user/stam/reality/Research/pdf/eg97.pdf)
- **可辨认的现象比求解规模更重要。** Zioma 的方法把树干、枝条分层，通过不同频带、沿风/横风/轻微轴向转动合成动作，并明确示例中回摆会越过平衡位置；作者也明确它不保留前一帧状态，不是严格物理模拟。因此解析合成并不天然死板，关键是是否合成了需要的视觉关系。[GPU Gems 3，第 6 章，尤其 6.3–6.4](https://developer.nvidia.com/gpugems/gpugems3/part-i-geometry/chapter-6-gpu-generated-procedural-wind-animations-trees)
- **整体弯曲与叶片细节可以分开，并给美术少量有意义的权重。** Sousa 描述 Crysis 的主弯曲/细节弯曲、逐实例刚度与逐叶相位；同时限制变形，避免仅平移顶点造成不可信形变。这可借鉴结构，不意味着照搬其网格模型就适合体素植物。[GPU Gems 3，第 16 章，16.1](https://developer.nvidia.com/gpugems/gpugems3/part-iii-rendering/chapter-16-vegetation-procedural-animation-and-shading-crysis)
- **“阵风持续多久”和“植物多久反应”应是不同控制。** SpeedTree 文档分别暴露阵风强度/频率、模型强度/方向响应时间和分层枝叶动作，并建议叶片比大枝更早表现风增强。这里引用的是控制语义和制作经验，不据文档推断其内部必为弹簧求解。[SpeedTree VFX Wind](https://docs8.speedtree.com/modeler/doku.php?id=wind_vfx)
- **涡脱落有自己的空间/尺度机制，不是通用抖动同义词。** NASA 的圆柱绕流验证案例记录尾流中的交替影响，并用 `St=fD/U` 联系障碍尺度、流速和脱落频率。圆柱案例不能直接决定草叶频率；对本项目的启示仅是若要模拟尾流，就须让它与障碍、下游方向和尺度相关，不能全场加同一正弦后称为“涡脱落”。[NASA：Laminar Flow Over a Cylinder，Post-Processing](https://www.grc.nasa.gov/www/wind/valid/lamcyl/Study1_files/Study1.html)

### 3.2 风输入可以多有趣，但不能替代植物响应

| 输入现象 | 应表达什么 | 对 Re: Flora 的最小可控版本 | 不能宣称什么 |
| --- | --- | --- | --- |
| 阵风 | 一块区域先后受到增强的推力，具有到达、持续、释放 | 基础风 + 沿方向移动的平滑包络，分开控制峰值、宽度、传播速度、间隔 | 给所有植物同一时刻乘个随机数，不等于阵风经过花园。 |
| 湍动 | 多尺度、有限相关长度/时间的小变化；方向也可变化 | 保留低频共享场，叠小幅横向与局部变化，频带受展示采样约束 | 更多 octave 不自动等于真实湍流，也不保证更 vivid。 |
| 地形遮风/绕流 | 上风面、背风区、边缘的风强/方向差别 | 若视觉实验确有需求，再试局部遮风权重和边缘扰动，明确称艺术近似 | 阴影强度、地形坡度或三维纹理本身不是空气阻挡求解。 |
| 涡脱落 | 与物体几何和尾流有关的交替扰动 | 暂不作为首轮；若需要，先一个障碍物 + 有范围的下游扰动原语 | 不能为了补草的惯性而先引入 Navier–Stokes 或全园双向流固耦合。 |

主响应可先用一个二维归一化振子表达：

```text
q¨ + 2ζω₀ q˙ + ω₀² q = ω₀² q_eq(W)
ω₀ = 2π f₀
```

这里 `q` 是植株/分枝的弯曲量或角度，`q_eq(W)` 是艺术控制的当前风下静态目标；`f₀` 控制回摆快慢，`ζ` 控制余振衰减，幅度/最大角度控制轮廓。公式是上述质量—阻尼—刚度关系的低自由度归一化设计，不是声称现有代码已实现。

- 欠阻尼 `0<ζ<1` 才允许常见的衰减振荡；`ζ=1` 是临界阻尼，通常回得快但不形成所求的来回余振。单纯“平滑追目标”仍可能只缓慢回原位。
- 自由响应含 `exp(−ζω₀t)` 衰减包络与 `ωd=ω₀√(1−ζ²)` 振荡；要有余振，释放时必须有非零位移或速度，不是任何参数组合都必然明显过冲。
- 高频叶片/梢部可以继续采用小幅解析波形，不必每片叶都保存完整刚体状态。低频整体/中频枝组/高频梢部应共享到达事件而有不同响应时间，防止一整株像果冻或一堆独立噪点。
- 弯曲/扭转需要合适的形状权重或 pivot。首轮只验证视觉运动，明确保持根部、限制角度、检查 voxel 连续；不要立刻引入整棵树通用骨骼求解器。

### 3.3 保留 discrete：动力学内部时间与可见姿态时间分开理解

有惯性不要求画面变平滑。一株草完全可以以“受推 → 偏到最远 → 越过静态位置 → 较小反摆 → 安静”的几个离散姿态呈现弹性；相比现状，新增的是这些姿态之间的因果与衰减，不是插帧。

未来候选可在固定求解步长内更新低自由度状态，或用分段常力下的解析更新保持稳定；只在现有桶展示时刻发布并保持可见姿态。**这只是设计选项，现有代码尚未分离响应状态与呈现节奏。** 若能在现有更新点用稳定的精确离散响应满足目标，也无需引入额外高频调度。不要直接以 0.2 s 对任意高频弹簧做未经稳定性检查的显式积分。

细节也应围绕逐格可读性设计：主回摆用几个采样点看得清的低频动作，梢部以更小幅度、分组错相的短促变化叠加；每组内部保持形状联系。它不需要变成满帧连续抖动，也不能用全组随机换姿态代替惯性。主画面与影子目前有各自代理节奏，首轮先固定它们，不擅自把影子全部改成逐叶同步。

## 4. 少数本质不同的方案

| 方案 | 能解决/验证什么 | 主要控制与成本风险 | 适合阶段 |
| --- | --- | --- | --- |
| A. 固定离散节奏的短参数对照 | 判断幅度、实际采样后的频带、同频、分组相位设置是否已能提供所需层次 | 保留当前 world tick/桶节奏，只动局部动作参数。不能产生任意风历史的自由衰减。 | 先做可逆视觉基线，不把“调参失败”自动等同需换风场。 |
| B. 无状态、响应感知的解析合成 | 给已知阵风事件解析地生成推压、延迟、回摆；或按频带给风输入加相位滞后/响应幅度 | 保留少量事件参数/已知输入，容易固定时间重放，无每株积分状态；若任意实时风变化，必须真正保存事件/历史或做对应卷积，不能把当前风乘正弦伪称因果响应。 | 若目标主要是可编排的花园氛围，这是一条成立的独立路线。 |
| C. 小规模有状态响应 + 离散发布 + 解析细节 | 对任意风开关/转向保留位移和速度，在相同逐格呈现中实现可因果解释的惯性、回弹、衰减 | 每株或每枝组保存低自由度状态，明确生命周期、稳定求解、离散姿态发布、暂停/重置与 LOD 共享；有缓冲区/更新成本但无需逐顶点状态。 | **针对本次“阵风后还有颤动与回弹”的首选候选。先一株/小片验证，不承诺全面上线。** |
| D. 地形耦合风场 + 大枝叶动力学 | 解决真正的遮风、绕流、树干弯曲与结构耦合 | 地形编辑重建、边界条件、稳定性、状态量、阴影/碰撞一致性复杂度明显增加；仍可能美术效果不合适 | 当前证据不支持先做。只有用户明确认可相关可见收益后再考虑。 |

推荐不是“先调参直到完美”，而是 **A 的短对照 → C 的最低自由度候选，同时保留 B 作为无状态竞争方案；所有方案默认使用同一离散呈现节奏**。输入先固定；响应挑选后才把阵风包络重新接入空间场。如此能知道新增效果来自哪里，也避免把风输入和植物参数一起改后无法解释结果。

## 5. 下一步最小视觉 A/B，尚未执行

本节是请求后续授权时可直接采用的实验设计，不是已存在的新 CLI，也不是本次默默开工。

### 5.1 固定控制

- 固定相机、画面尺寸、光照/时刻、植物位置/seed/年龄/高度；停止生长/出生动画干扰。取近景单株侧视看过冲，中景一片植物看传播；不要只拿随手选的截图比较“更自然”。
- 每次从相同视觉时间和相同响应初态开始，记录输入矢量、响应量/速度和帧序号。固定帧时钟用于因果比较；实际帧率、世界 tick、风更新率、内部响应求解率、最终姿态展示率分别记清楚。保留四桶分组与离散保持，不开启可见姿态插值。
- 布置成熟长短草、至少一种花、地肤和一个带明确 anchor 的叶簇；同一阵风穿过同种小队列，再穿过混合种类。最小候选无需先覆盖全地图。
- 先固定风方向为世界 +X，并给一个可解释的值域，禁用所有额外噪声；视觉中定义“向右”相对镜头，避免把世界风向与屏幕风向混淆。
- 先锁定 leaf frequency multiplier，不让可变频相位重定同时影响结果；关闭/开启附加 vibration 为独立对照，不改多类参数后一次评价。

已有可复用基础：`--foliage-shadow-bench` 的树 seed=122、成熟树、固定时刻/相机见 `src/app/core/foliage_shadow_bench.rs:9-47`；`:50-74` 配置草混合接收区；`src/app/core/denoiser_bench.rs:558-567` 用 `presented_frames × 1/60` 形成固定视觉时间。它适合作为相机/树草/时钟的技术参考，**不自带上述混合植株、任意脉冲或按帧外力注入**。普通 `--denoiser-bench` 也不是通用固定动画时钟，`:501-504` 只有 FoliageShadow 返回固定步长。复制整个阴影基准来冒充响应测试并不合适；后续应增加窄小、可逆的实验控制。

### 5.2 用几段短输入逐项辨别

| 实验 | 固定输入与单项变量 | 要观察什么；如何排除错误解释 |
| --- | --- | --- |
| E0：离散基线 | 恒定风，固定当前桶时间；原参数与一组按实际离散动作挑选的频率/幅度/相位对照，参数一次只改一项。不引入连续展示对照作为默认目标。 | 看逐格姿态是否有可辨认的小变化、群组关系是否成立；记录混叠后的实际节奏。现有表达能到哪一步，与有无风后回弹分别评价。 |
| E1：单脉冲 | 建议 0–1 s 无风、1–1.25 s 升至峰值、1.25–1.75 s 保持、1.75–2 s 降为 0、继续观察至 5 s；输入由固定帧序号决定。现状/B/C 均在同一桶时刻发布姿态。 | 从离散姿态看峰值滞后、风归零后的非零运动、第一次跨过静态位置、反摆逐次减小及根部固定。不能靠更平滑的展示赢得比较；现状没有历史尾迹，候选须经实际生产姿态验证。 |
| E2：两次推压 | 复制 E1，第二脉冲分别落在植株顺摆和逆摆阶段；分别重置初态，不混入随机风。 | 有状态响应应对第二次推压的时机作不同反应；仅每次播相同回弹片段的方案可能显露拼接或不连续。 |
| E3：转向 | 相同峰值 +X → −X 与 +X → +Z 两种转向，固定转换时间与离散发布时刻。 | 内部速度/能量是否被硬重置、下一格是否有可解释的惯性方向、二维摆动是否只成直线。区分有意逐格变化与近零风方向回退导致的无关跳姿。 |
| E4：空间阵风 | 把选定输入包络沿一排相同植株平移，固定传播速度与间距；随后换成混合植物。 | 到达顺序必须来自空间输入，个体差异不应破坏整片风的流动；轻梢先响应、主体后回摆等层次是否成立，由用户评价。 |
| E5：投影与生命周期 | 同一候选下看主画面、LOD 切换、叶簇影；再暂停/恢复、跳时间、重建/删除植物。 | 根部不漂移、无 NaN/爆振、形状不过度分离；主低频姿态与阴影代理能解释一致性；状态不会串给复用实例或随 LOD 重置。 |

首轮 C 候选只需少量艺术参数：静态偏转幅度/最大角、自然频率 `f₀`、阻尼比 `ζ`；可以先对比 `ζ=0.3、0.7、1.0`，并用约 `f₀=0.7–1.2 Hz` 的低频试值，让一个回摆周期有若干清楚的离散姿态。它们是**未校准的视觉探索起点**，不是这些植物的测量常数或验收标准。先让用户选“逐格但有弹性、不过分”，再调梢部/叶片小幅细节；不把大幅度摇摆或连续平滑当作 vivid 的唯一指标。

记录位置峰值、释放后过零次数/时刻、衰减包络、近邻响应相关性以及用户短评即可；这些是解释动作的量，不应替代视觉认可。可加短视频叠加输入曲线，比单帧“有没有动”更有辨识力。

## 6. 成本、正确性与交付边界

第一轮成本只列风险，不设阻止用户看效果的硬预算：有状态方案需要每株/每枝组状态与更新；稳定求解策略可能需要内部子步，但不改变离散可见姿态；新增维度可能扩大变形包围盒；树叶代理需读取可解释一致的低频姿态，不能仅复制参数却各自重算不同状态。

视觉认可后的性能阶段，才在同相机、相同数量、固定输入与版本下做 release app 测量，分别量风场更新、响应更新、主 flora/leaves、叶影和总帧时间。不引用历史 GPU Gems 的毫秒数作为本机预算，不以 debug 单测判断性能。若先有小幅性能回退，可以展示候选并如实记录；这不等于性能验收通过。

实现获授权后的基本验证需遵守仓库要求：Rust/shader 改动后 `cargo check` 再生成派生结构、相关确定性测试、hidden muted release smoke 及日志检查；用户要亲自试时按仓库约定从对应工作区运行可见 `cargo run`。**本次这些命令均未执行**，因为只有研究授权。
