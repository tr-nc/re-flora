# 程序化攀墙植物：先例与附着点模型

状态：调研与设计建议；未实现，非已批准规格。仓库基线：`fe1b3ccd`。

## 结论

已有成熟的程序化爬藤制作工具，也有支持动态环境、折断和剪枝的交互研究。此次找到的公开一手资料**不能证明已有商业游戏完整实现“运行时生长 → 离散附着 → 可破坏墙体 → 局部脱附与恢复生长”**，不能将编辑器生成能力说成已发布游戏玩法。

用户提出的“先伸长，再形成附着点，再继续伸长”适合作为本项目的玩法抽象。建议采用**持久的枝茎拓扑 + 稀疏的表面附着约束 + 独立的生长尖端**，不要在墙面编辑时重新随机生成整株。

## 生物学边界

“几何上平整的墙”与“微观上光滑、难以粘附的材料”不同。[English ivy 附着实验][6] 指出其附着效果依赖基底，在木材、软木、砂浆等结构化表面有效，而大部分玻璃、铝等光滑表面不适合；不同基底也有不同失效方式。

因此：

- 第一种植物建议限定为**贴墙附着型**，不要一开始混合绕杆缠绕型和卷须攀援型。
- “每隔几十厘米一个附着点”是可调的视觉/计算抽象，不是本次文献已证明的普遍植物学规律。一个游戏附着点可以代表一小簇附着组织。
- 沿茎的累计弧长安排附着机会，不按世界高度或每个渲染顶点安排。可先试约 20–40 cm 的观感，但需确认游戏单位换算，加入有种子的间距变化，并允许附着失败。

## 建议模型（本项目设计推导，非文献原样实现）

### 三种关系分别保存

1. **枝茎连通**：谁与谁相连；影响枝条结构以及是否仍连到根部。
2. **外部附着**：哪个茎节点通过哪一小片接触区域固定到哪个支撑物上。
3. **生长尖端**：哪个芽仍在伸长、探索和形成新附着。

附着消失只是删除一个外部约束，不是删除茎边。茎断开才改变植物连通性。失去根部连接可以停止生长并延迟枯萎，但仍有墙面附着的枝条不应立即掉落。

建议保留：稳定的 plant/node/anchor ID、茎段静止长度和弯曲属性、附着位置/法线/接触范围、支撑物身份、检查过的源 revision、年龄，以及确定性随机状态。revision 是需要重查的依据，不是附着点身份。

### 生长循环

```text
尖端沿当前方向伸长
→ 在近邻查询表面，综合向上、方向惯性和少量相关噪声选方向
→ 沿表面切向前进，并做扫掠碰撞检测，不能跨薄墙或拐角穿模
→ 累计到附着间距，且材料、距离、表面接触条件满足
→ 形成一个附着约束，继续伸长；按芽规则产生侧枝和叶片
```

重要区别：**贴近/避让墙面的几何约束可以持续存在，固定在墙上的粘附约束应当稀疏。** 否则每个采样点都被焊死，就没有“先长一段再附着”的行为。

找不到支撑时允许有限长度的自由探索；自由段更长时弯曲、下垂或暂停向前生长。不能无限伸出刚性悬臂，也不能无限距离吸到另一面墙。墙角、墙顶和天花板需有独立退化处理，向上方向投影到表面后可能接近零。

### 墙体修改后的局部失效

```text
已发布的地形修改 / 支撑物修改
→ 修改范围查询可能受影响的接触区域（跨 chunk 边界也要覆盖）
→ 使用最新可用的权威表面事实重查附着，不把 revision 变化直接当成脱落
→ 移除确实失效的附着约束
→ 唤醒相关茎段；保留其他枝叶的位置、ID 与生长历史
→ 变形/受力可能进一步传播到相邻段或引发后续脱附
```

- 建立空间区域到 anchor ID 的反向索引，用 chunk 作粗筛，再按实际接触范围精查。接触范围覆盖多个 chunk 时记录完整依赖。
- 只删附着点下方的支撑时才脱附；同一 chunk 里远处的编辑应只引发必要复核，不应让藤蔓整体掉落。
- 缓存 `NotReady` 不等于空气。异步查询必须带依赖版本，过期结果丢弃。已确认被删除的支撑及时释放；尚不明确时标成待验证，不用旧碰撞缓存建立新附着。
- 墙被挖掉、墙被填回、墙变成不适合附着的材料，都是表面变化；生长尖端与活动茎段也需要相应碰撞更新，不能仅更新锚点。
- 不自动将失效附着点瞬移到附近新表面。重新附着应有接触、距离及成熟过程。
- 如果将来墙块变成可运动碎块，必须明确采用“附着随碎块运动”还是“转换时释放”；不能默认为墙块消失，也不能依赖会重建的临时 collider handle 作为稳定身份。第一版可只支持静态墙被删除。

### 建议的可见反馈

| 事件 | 预期反馈 |
| --- | --- |
| 中间一个附着点失效，两侧仍固定 | 释放局部约束；有余长的藤段松弛、轻晃，其他位置保持 |
| 连续多个附着点失效 | 无支撑跨度变长，弯曲或下垂加大；较弱附着可在后续受力中继续剥离 |
| 上部附着丢失、下部仍固定 | 自由端弯折/垂落，仍连根时后续可重新探索支撑 |
| 茎被切断、上半仍粘墙 | 上半可以留在墙上，停止生长并逐步枯萎；不是立即消失 |
| 断枝不再连接根部，也无任何外部支撑 | 掉落并与地面碰撞；何时回收是另外的玩法规则 |
| 挖掉附近但无关的一块墙 | 植物外形不变 |

注意：两端固定且原本完全拉直、无余长的茎段，**不能凭空形成大幅下垂**。下垂来自原有曲率、可控弹性或进一步脱附，需保留静止长度；不要为了视觉强行拉长藤蔓。失去附着也不保证细枝必定立即折断，需考虑刚度与跨度。

## 与当前代码的结合点

检查范围为基线代码的相关入口，不是全面架构审计：

- `src/flora/construct.rs` 当前生成草柱、薰衣草等局部体素几何；`shader/slang/update_flora_growth.slang` 主要递增实例生长进度。可以沿用程序化外观与叶片资产思路，但这两个入口本身没有跨墙面、跨 chunk 的持久枝茎与附着拓扑，不能只把普通花草的朝向改成墙面法线。
- `shader/slang/flora_surface_planting.slang` 当前种植材质允许 dirt/stucco。爬藤的“根能种在哪里”和“枝能附着在哪里”语义不同，不建议直接共用这一个判定。
- `src/builder/contree/mod.rs` 的 `chunk_source_dependency`、快照和 sparse export 已区分源 presence/revision、缓存就绪与过期依赖。附着复核应沿用这套事实来源，不再发明第二套地形版本计数。
- `crates/re-flora-physics/src/lib.rs` 已有 revisioned voxel brick 更新及刚体模拟基础；`docs/voxel_collision_architecture.md` 说明 CPU 表面壳与水用 filled-solid SDF 不能互换。不要默认水的粗 SDF 可作为精细墙面附着的权威依据，也不要假设现有刚体 API 已包含柔性藤蔓求解器。

建议第一版使用低分辨率茎骨架作为状态真相，叶片跟随骨架；粒子距离/弯曲约束（例如 XPBD）是待选实现，不预先承诺性能。附着稳定段可休眠，仅生长尖端和被编辑/受力唤醒的部分活动。空间检索可以局部化，但力的影响未必只停在相邻两个附着点，不作严格常数时间承诺。

存档需要保存实际生长/破坏历史或足够的持久状态；只保存随机种子并在已改变的墙面上重跑，不能保证恢复同一株植物。

## 最小可评审闭环

先做一面可破坏平墙、一株贴墙植物，展示：

1. 尖端伸长 → 形成稀疏附着点 → 继续生长，产生少量侧枝和叶片。
2. 删除一个/连续多个附着位置，比较局部松弛、自由端垂落和完全脱离。
3. 编辑无关区域，确认远处枝叶不重新随机生成。
4. 保留根与切断根分别测试，验证“支撑”和“存活”不是同一个开关。
5. 墙角、跨 chunk 编辑、连续快速编辑、缓存未就绪及重填墙体作为正确性边界。

先评审实际外观，再扩大规模和做 release 模式性能测量；不先实现全套植物生理、卷须缠绕或每片叶子的刚体。正式实现后按仓库规则运行 Rust/shader 检查、测试、隐藏静音 release app 并检查日志；本次仅调研文档，未做运行时验证或性能测量。
