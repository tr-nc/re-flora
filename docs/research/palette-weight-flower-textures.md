# 花朵贴图：索引还是调色板权重

## 结论与方案

用户希望“贴纸决定颜色如何分布、palette 决定实际颜色”，支持蓝瓣心→白瓣缘等渐变，而不是给每个部位另加颜色参数。本轮采用 **四槽 palette + RGB 权重图**；不把颜色表索引当连续数值插值。

- PNG 的 indexed-colour 像素是 PLTE 项的索引；PLTE 为 RGB 条目表。[1] 数值索引之间没有颜色距离的语义：索引 0 与 2 的平均值 1 可能是任意颜色。这是设计推论，不是 PNG 的缺陷。
- 一个 texel 保存 A/B/C 的非负权重（RGB 三通道）；D 权重为 `max(0, 1-R-G-B)`。最后归一化四权重，超出总和 1 的 RGB 也能确定地处理。纯红、纯绿、纯蓝、黑分别表示 A/B/C/D；红绿混合表示 A↔B 渐变。alpha 不作数据，输入要求不透明，避免浏览器预乘 alpha 丢失权重。
- 四种 palette 色先从 sRGB 转 Linear-sRGB，再按权重求和，生成可供共享标准材质消费的颜色纹理。Three.js 官方说明渲染／插值在 Linear-sRGB 工作空间；颜色图需要正确颜色空间标记，非颜色数据不应进行 sRGB 解码。[2] CPU 权重只是数值，不作 gamma 转换。
- 预览提供少量权重模板、权重图绘制／导入／导出，以及 A/B/C/D 四个颜色槽。没有“瓣根颜色／中圈颜色／瓣边颜色”的专属分支；同一图可换 palette 产生同品种色变。
- UV 图集约定：左 3/4 为重复应用到每片花瓣的贴纸（横向：左缘→右缘；纵向：瓣根→瓣尖）；右上花心、右下花萼。图集岛保持边缘留白／内缩，避免线性过滤跨岛污染。
- 这是有限四色的凸组合，不能表达任意数量的独立色，且物理线性蓝白混色不是感知均匀渐变。未来可扩为更多权重或“两索引 + 混合量”，但后者边界过滤与索引解码更复杂。本轮不把这些可能性做成更多玩家滑杆。
- 实现保留颜色纹理与几何的独立更新：改 palette 或权重图不重建网格。复用现有 source／pixel／高分辨率补点采色，不另造后处理算法。
