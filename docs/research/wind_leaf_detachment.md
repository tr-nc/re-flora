# 风致落叶：瞬时过载、长期弱化与大规模叶片采样

## 结论

自然落叶不能简单归结为“累计风量”或“统一风速阈值”。更合理的分层是：叶柄/离层的承载能力随生理状态和损伤变化；当当下的局部机械载荷超过剩余承载能力时发生分离。反复受风可能造成损伤，但不等于所有叶子都必须先累计几秒风才能落下。

针对本项目的短时吹风交互，建议以**局部载荷超过每片叶子的有效阈值时及时响应**为基础；不同叶子的阈值不同。长期弱化是可选的独立生态机制，不应借落叶粒子发射器的数量积分来模拟。这里的“当帧触发”是游戏近似，不是声称真实断裂没有动态响应或裂纹传播时间。

## 文献证据与边界

1. **叶片风载会转化为叶柄弯曲和扭转。** *How wind drives the correlation between leaf shape and mechanical properties* 测量叶片形态及叶柄力学性质，并建立风载弯矩/扭矩模型；其近似载荷含风速平方项。论文也报告拉伸试验在叶柄/茎连接处失效。这支持“载荷与承载能力”的描述，但不是阵风中脱落延迟的直接测量。
   - 原始研究全文：https://pmc.ncbi.nlm.nih.gov/articles/PMC6218545/
   - 可用于游戏的简化：`F ≈ 0.5 * rho * Cd * A_projected * U_relative²`，弯矩还取决于力臂。叶片转向、卷曲、柔性和动态惯性意味着不能把它理解为固定面积下精确的风速平方断裂定律。
2. **离层会先发生生理弱化。** *Kinetics of Abscission in the Bean Petiole Explant* 通过拉断离层所需机械力测量脱落进程；在该离体菜豆实验中，1 ppm 乙烯引起可测弱化的最短时间约为一小时。这不是所有树种的统一时间，也不是“一次吹风必须持续一小时”。
   - 原始研究摘要：https://pmc.ncbi.nlm.nih.gov/articles/PMC396070/
3. **持续风确实可以造成组织损伤，但不能据此认定秒级线性疲劳。** Reis 等的可可叶研究使用 2.5、3.5、4.5 m/s 的持续/间歇风，暴露 3、6、12 小时，观察到生理及组织损伤，幼叶更敏感。研究不是叶柄秒级疲劳寿命或逐片脱落时间的标定。
   - 原始研究全文：https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0198274

检索还找到番茄离层多聚半乳糖醛酸酶沉默实验，搜索结果支持细胞壁降解影响拉断强度，但出版社全文请求返回 403；本建议不依赖该未成功抓取的全文。

因此，现有证据支持长期弱化和急性过载可以并存；**不支持把当前“累计生成数满 1”解释为已验证的植物疲劳模型**。没有从这些研究得出通用的脱落风速或毫秒响应常数。项目 wind strength 也不能未经标定直接视为 m/s。

## 当前代码事实

- `src/particles/emitters.rs`：默认 `spawn_rate=0.5`；风响应下限/上限为 0.5/1.0；随机 `fall_chance=0.2..1.0` 实际是速率倍率。`spawn_accumulator += rate * response * chance * dt`，累计到 1 才生成；无风时保留余额。这是数量发射模型，不是逐片叶子的损伤或断裂模型。
- `src/app/core/particles.rs`：每簇一个发射器，速率乘 `sqrt(items_count)`；只传入 `cluster.pos`，叶位置列表为空。
- `src/util/clustering.rs`：`ClusterResult` 仅保留代表点和数量，不保留成员。更准确地说，代表点是建簇时的首个输入位置，**不是几何质心**；此前调查中“中心”指 emitter 的采样位置。
- `src/app/core/vegetation.rs`：`compiled.world_leaf_positions` 来自枝端 leaf-spray anchors，而可见叶体素来自 `relative_leaf_placements()`，随后按量化世界位置去重。这两套集合不是一一对应；真实脱落必须映射最终可见叶实例，而不能直接使用旧发射器的 anchor 列表。
- `src/app/core/mod.rs`：聚类距离 0.08 world units，按风场换算约 20.48 voxels。
- `src/wind_field.rs`、`src/wind_field/transport.rs`：共享 32×32 水平网格；位置按 x/z 做双线性采样，不区分高度。人工/自然风进入相同风场。逐叶查询可以提高已有场内的空间精度，但不会凭空增加冠层遮蔽、垂直风等物理信息。

此前临时诊断直接调用真实发射器 update：在固定倍率 1、基础速率 0.5 下，风强 1 的首次发射约 2.017 秒，0.6 约 10.017 秒；速率 2 时约 0.5 秒。这些是确定性逻辑时间，**不是 Release 性能测量，也不是全部游戏树木的固定延迟**。临时测试已移除。

## 性能与可选设计

当前每帧采样复杂度约 O(C)，C 为叶簇数量。直接改成逐叶 CPU 查询则约 O(N)，N 为叶对象数量，并新增身份/状态与内存访问成本；在大量叶子时有回退风险。没有测量，不能保证具体毫秒数或零回退。

### 方案 A：装饰性落叶的视觉近似

建树时为每簇保存少量、空间分散的真实成员位置/身份，例如 4–8 个代表候选（数量是待验证的设计参数，不是研究结论）。每帧检查这些位置的局部风，只让达标位置触发落叶，不再从单个簇代表点无条件生成。

- 每帧风采样约 O(kC)，k 固定；可让到达冠层边缘的风更早产生对应位置的落叶。
- 同时保持即时阈值响应和持续风下的独立数量控制，避免同一候选每帧重复触发。
- **这是近似，不保证每一片受风叶子都被发现。** 必须明确是否只生成装饰落叶，还是要求原来的叶子真正从树上消失。

### 方案 B：要求逐叶语义时

保留成员身份和空间索引，用风场单元覆盖叶簇范围的保守风强上界做粗筛。只在确定整个簇都低于最小有效阈值时跳过；边界/可能达标的簇再对成员精查。不要仅用簇中心无风就跳过整个簇，这会保留原问题。双线性向量插值可用覆盖单元角点的最大向量模长作保守上界，但应覆盖完整簇范围并匹配边界采样规则。

- 典型局部阵风可减少精查；全场强风的最坏情况仍为 O(N)。
- 粗筛、阈值数据与实际载荷模型必须一致；若加入惯性/历史状态，不能仅凭瞬时风上界安全跳过。
- GPU 事件判定可作为后续选项，但结果读回、落叶生成和附着叶移除的同步可能引入延迟；不能无测量地当作免费优化。
- 把判定轮流分帧虽然省成本，却直接引入用户不希望的触发延迟；不作为默认解决办法。

## 建议与验证边界

先区分产品目标：自然、及时的装饰性落叶，还是每片附着叶的真实脱落。前者优先方案 A；后者需要方案 B 及附着/脱落身份生命周期。两者都应让人工/自然风使用同一规则，并把首次阈值响应与持续落叶密度分开。

后续实现先做视觉 A/B（Debug checkbox：原模式/实验模式），不在本次调研中修改运行逻辑。验证必须覆盖：首次局部达标到生成的时间、风只击中簇边缘、短阵风、持续风、同时达标的大量叶子，以及重复触发/耗尽语义。性能须在相同大场景 Release 模式比较 CPU 判定、GPU/帧耗时、采样数量和峰值生成开销；不能用上述单元测试时间当性能证据。

## 后续讨论：真实脱落、可再生叶位与实验隔离

**状态：调研和设计建议，尚未定稿或实现。** 用户进一步希望实验开启时，落叶来自树上实际存在的一片叶子；原位置空出后逐渐长出新叶。每片新叶具有自己的初始连接强度，已有叶片的强度随时间缓慢下降。GUI 可切回完整旧模式。因此，少量代表点的装饰性方案不再是目标方案；可以用空间分组加速，但不能让固定代表叶成为唯一可脱落对象。

### 生物学补充：socket 不是断柄复活

- 马里兰大学植物学课程说明：叶腋通常有芽；芽可发展成新梢，新组织来自分生组织。叶片脱落留下的叶痕与芽是不同结构。https://science.umd.edu/classroom/bsci124/lec2.html
- Burrows 的 *Eucalypt naked buds – expansion or abscission?* 展示叶腋、脱落芽痕和保留的副芽/分生组织，说明这些保护性芽可支持再萌发。这是桉树类群的解剖观察，不应推广为所有叶痕都会长出替代叶。https://pmc.ncbi.nlm.nih.gov/articles/PMC9322473/
- 因此可以把 socket 定义为游戏中的“枝条上的可再生叶位”，抽象附近芽的补叶能力；同位置长出一片替代叶是有意的园艺游戏简化，不是声称脱落的旧叶柄重新接好。
- “新叶连接更强、随后单调下降”也是本实验的玩法模型，不能说真实幼叶一定比成熟叶坚固。先前可可研究反而观察到幼叶对风致损伤更敏感。

### 最小规则建议

1. **两层身份**：`LeafSocketId` 表示树上的叶位；`LeafId = (socket, generation)` 表示这一代具体叶子。脱落后旧 LeafId 进入落叶模拟，新叶使用下一代身份，不受旧粒子消亡回调影响。
2. **叶位循环**：`Attached → Empty/Recovery → Growing → Attached`。脱落叶的飞行、落地与消亡是独立分支；叶位再生不必等待旧叶粒子消失。
3. **瞬时判定**：`load(local_wind, growth) >= attachment_strength(now)` 时提出脱落。人工和自然风走同一个局部场，不添加发射数量积分、每帧随机抽签或额外“攒风”时间。
4. **每代固定差异**：用树/叶位/代数的稳定种子选取 `S0`；每代出生时选一次，而不是每帧重抽。阈值分布决定普通阵风下哪些叶子先掉；相同输入可重复验证。
5. **缓慢弱化**：不做完整生理年龄、季节、养分系统，仅在成熟后让有效连接强度缓慢下降。例如 `S(t)=Smin+(S0-Smin)*exp(-k*t)`，`Smin>0`。这是候选函数，不是文献标定定律；也可以替换为设计曲线。时间使用模拟时钟，并与树几何 growth_age 分离。由出生/成熟时间推导当前值，不必每帧在 CPU 写回全部叶子的强度。
6. **再生**：恢复等待和生长时间具有少量稳定差异，避免同时掉落的叶子整齐弹回。Growing 阶段从小到大，瞬时有效载荷随面积增长；新一代强度重置。这样可减少刚冒芽就被普通背景风吹掉，不引入无解释的无敌状态。极强持续风仍可能妨碍恢复。
7. **面积与风强**：首版可用 `K * |wind|² * growth²` 作为无量纲载荷指标（growth 表示线性尺度），暂不承诺真实 SI 单位、柔性重构或完整相对气流载荷。首版采样采用哪个已发布叶位必须统一；树枝摆动后的实际位置和静止根位置不是同一事实，不能声称使用精确瞬时叶位却只采 rest anchor。

有限阈值分布只能保证普通阵风下分批落叶，**不能保证任意强风永不吹秃**。若还要求最低冠层保有量，这是另一条明确的玩法保护规则，会改变纯阈值语义，需要用户决定，不应暗藏在速率限制里。

### 模块深度与真实接缝

建议由一个 `LeafLifecycle` module 管理叶位、每代身份、连接强度、再生、模式和单次脱落承诺。`GardenTrees` 负责接入树的创建/替换/移除。小 interface 大致表达“同步树叶拓扑；按当前模拟时间/共享风推进；获得一份一致的叶状态发布”，而非把计时器、随机种子、阈值判断散进 App、shader、粒子系统。

这不是再加一层只转发的 facade。它的 leverage 来自独占以下 invariants：

- 同一个 LeafId 不能同时作为树上叶和新落叶发布；每代最多脱落一次。
- 可见树叶减少与对应落叶诞生属于同一次发布。落叶槽位不足、GPU 交接或上传失败不得先删树叶后悄悄丢弃事件。
- 初始落叶的位置、颜色、尺度和运动应来自脱落前已发布的那片叶，而不是簇代表点加重新随机的外观。完整外观连续性还取决于挂树体素与现有 3D 落叶模型能否共享视觉描述；这是需验证的工作，不是改一个 spawn position 就完成。
- dense draw index 不是叶位身份；重排/压缩不能重置强度或重新长叶。拓扑编辑导致旧叶位失效时，需要清晰的重建/重置规则，不能承诺任意编辑都能自动继承。
- 外部消费者不各自维护一套“还有多少叶子”。渲染/阴影/生态查询通过当前模式的同一份占用事实读取；结构性树元数据不冒充活叶数量。

内部可以有渲染、粒子等 adapters，但发布顺序、失败策略与模式恢复由同一 owner 封装。测试跨生产 interface 覆盖完整“少一片挂树叶、多一个同身份落叶”的链路，而非只测试阈值函数。

### 已核对的复用点与实际成本

- `src/tracer/vegetation_response/leaves.rs` 已按可见叶体素维护 response identity，而非按 shadow proxy 或 spray anchor；键包含 tree、world、anchor_local，支持重排保留状态。这是可复用经验，但世界坐标键本身不是天然跨树生长/拓扑变化的永久 socket id。
- `shader/slang/vegetation_response.comp.slang` 已对这些叶体素逐个采样风并更新响应。真实逐叶判定不必默认再加一遍全量 CPU 采样；可评估复用 GPU 工作或 CPU 空间粗筛的两种实现。尚未决定执行位置，不能宣称新增成本只有一次比较。
- `TreeLeafInstanceResource` 有可见流和独立阴影代理流。保留现有 8-byte 可见实例布局，考虑独立紧凑占用/生长状态，避免每片脱落都重建整棵树。隐藏实例仍有访问/顶点成本，不等于零成本；大量空位后的压缩可作为后续优化。
- `shader/slang/leaves_shadow.vert.slang` 会对代理成员求平均响应。脱落后需要排除缺失成员，更新覆盖/权重或受影响代理，不能只改主画面留下幽灵阴影；LOD 也必须遵循占用状态。
- `src/tracer/vegetation_response/fruit_handoff.rs` 提供从已发布 GPU 姿态交给 CPU 物理的事件式先例，但当前路径含同步复制/读回。叶子数量大得多，不能照搬成每片一次同步。应批量交接或留在 GPU 路径，测量 GPU 等待和真实发布延迟。
- `GardenTrees::ecology_regions/sample_ecology_leaf` 当前把原始 `leaf_render_positions` 当作叶资源。实验开启时不能继续在空 socket 生成新生态对象。已有对象是否离开、冠层音量/遮蔽如何随稀疏变化是独立的消费策略；它们应读取统一事实，不能由每次落叶触发整树重建。
- 粒子系统有容量限制，当前装饰性发射会忽略 `spawn` 失败。真实转移必须暴露并处理容量不足；“无上限瞬时脱落、有限容量、每片可见”三者不能同时保证。支持场景内应预留/测量峰值容量；超出支持范围时明确报告限制，不能把事件排队数秒后仍称即时脱落。

### GUI A/B 的建议语义（待确认）

使用可保存的声明式 Debug checkbox，例如“真实落叶与再生（实验）”，默认未勾选。未勾选完整沿用现有冠层和旧落叶发射器；勾选后停用旧装饰性叶发射，启用真实生命周期，避免双重落叶。

为便于反复比较，建议本轮采用**退出实验时重置实验状态**：恢复旧冠层、移除本次实验拥有的落叶，恢复原发射器；进入时从确定性种子和完整冠层启动。进入时需清理旧装饰叶，或明确区分其来源，避免误判“开启后仍凭空掉叶”。清理只针对落叶类别/实验所有权，不得清空蝴蝶、水滴等共享粒子。若用户希望保留实验进度，则改为冻结并恢复完整实验快照，而不是复用已恢复的冠层当作实验状态。两种语义应选定一种并在 GUI 提示。

设置可保存，不等于整片冠层的生命周期快照已持久化。本轮可只做运行期实验、重进游戏重新初始化，并明确声明；不自动扩大到存档格式和离线生长。

### 下一步讨论与验证

优先确认：一片叶是否定义为当前单个可见叶体素（建议如此，不是整个叶簇）；持续足够强的风是否允许暂时吹秃。其余首版建议不涉及季节、营养、叶柄有限元或完整生理衰老。

验证至少覆盖稳定身份、单次转移、当前位置/颜色连续、缺叶与再生、持续风下新叶行为、无风不自发掉落、同强度风在弱化后能吹落更多旧叶、不同 dt 下的规则一致性、重排/树编辑/删除、主视图/LOD/阴影与生态的一致性、A/B 往返及容量不足。性能分别测判定、状态上传、姿态交接和峰值落叶；Release 大场景测量不能被“模块设计合理所以一定很快”替代。
