# 植物茎：连续几何与转镜头时的像素稳定性

## 范围与当前结论

讨论阶段；未修改游戏、未实现候选、未运行性能测试。本文区分来源事实、仓库事实和设计建议。优先解决用户提出的“不移动相机位置，只转头”的情形；绕植物公转实际上改变相机位置，不属于纯旋转。

建议恢复连续的可分叉茎形状，但不要直接把“低分辨率屏幕后处理”当作稳定性方案。先选择视觉契约：

1. **屏幕像素契约**：方块始终水平/竖直、大小统一。容易实现，但连续视角变化会改变轮廓覆盖，细枝尤其容易跳点。
2. **方向空间契约**：采样格固定在世界方向，画面是它的投影。相机原地转动不改变源采样，代价是屏幕上的格子会变形、大小不均，有面接缝与最终重采样问题。
3. **表面风格契约**：正常光栅化连续轮廓，只让颜色/纹理呈像素风。最容易保留细分叉，但不是严格像素化剪影。

三者不能被混称为同一种“像素风”。源采样稳定也不等于最终显示像素完全无闪烁。

## 当前仓库事实

- `src/flora/models/column.rs`：每层是完整立方体，`center` 只沿单一弯曲中心线分布，`triangles` 每格生成六面；目前表达的是一条堆叠杆，不是分叉图。
- `shader/slang/flower_stem.vert.slang`：当前茎本来就使用三角形顶点光栅化，按层改变位置后乘真实相机矩阵。因此准确的变化是**替换几何表示并选择采样方案**，不是从完全非光栅化回到光栅化。
- `src/gameplay/camera/controller.rs` 使用 `Mat4::perspective_rh`；不能默认套正交相机技巧。
- `docs/model_pixel_frame_architecture.md` 描述的共享模型表面缓存主要是花头、果实、蝴蝶等的另一条路径。恢复茎的连续网格不要求撤销这些对象的缓存设计。

方块本身并非不能分叉；当前单列数据模型不支持。即使加分叉，粗方块仍限制渐细、曲线与接点表现。这是技术上的纠正，不是继续使用方块的建议。

## 为什么只转头也会闪

屏幕固定粗采样格下，茎投影在格子中连续滑动。一根宽度小于一个粗像素的枝条，可能这一帧覆盖采样中心、下一帧完全错过。另有阴影、法线或分档光照引起的颜色跳变。应分别检查：

- 网格相位游动；
- 细枝覆盖/消失；
- 光照或阴影闪动；
- 角度图集的离散切换。

放大低分辨率结果不能恢复已丢失的枝条。多采样可改善覆盖估计，但再次二值阈值化仍会产生跳变；保留软覆盖则会引入半透明边或额外颜色。最小显示宽度可保住重要细枝，但改变真实粗细，不应默认为无代价的修复。

## 一手资料及适用边界

### 2D：固定图像与像素网格

Unity 文档将 Pixel Snapping 定义为把精灵对齐世界网格，将 Upscale Render Texture 定义为先画临时低分辨率纹理再放大。[1] David Holland 的本人实现进一步说明相机对齐视图网格后，把最终画面按 snap error 平移回来恢复顺滑。[2]

这对固定朝向的平移很有启发，但不证明自由旋转稳定。透视转头通常不是整张图统一平移；正交相机旋转也会改变物体投影形状，不能把“正交可消除 pixel creep”理解为任意运动都无覆盖变化。ProPixelizer 作者明确推荐正交，并说明透视无法用其 snapping 方法彻底消除 creep。[3]

Dead Cells 美术作者使用 3D 模型/骨骼，低分辨率无 AA 渲染，再导出逐帧 PNG 和法线图。[4] 值得借鉴的是以最终分辨率设计剪影，不是为任意茎形与任意相机枚举图集。它并未解决运行时自由相机问题。

### 与“原地转头”特别匹配：Obra Dinn

Lucas Pope 的开发日志逐步比较了屏幕抖色、表面纹理抖色、历史形变、屏幕偏移、立方体和球面映射。[5]

最后的 fullscreen 方案把抖色模式映射到随相机平移但不随相机旋转的球面；以更高分辨率计算后降采样。他明确列出代价：边缘点变大、点不总对齐屏幕横竖、降采样后不再严格 1-bit。

**这证明的是抖色图案的旋转稳定，不是细茎剪影已被解决。** 可迁移的是“不要把风格采样格钉在屏幕上”的思想。

### 更直接像素化轮廓：固定方向 cubemap

Texel marching 作者的可复现文章把场景画到低分辨率 cubemap，转镜头时从同一方向空间取图；位置变化再用深度重投影。[6] 作者明确说这是对 Shadowglass 效果的个人复现猜想，不是 Shadowglass 官方技术披露。

Texel Splatting 预印本更进一步：记录 cubemap 的位置、法线、材质、ID，把纹素作为世界空间小面片投影到屏幕。[7] 原点固定时，旋转不改变 cubemap 源纹素分配。原点格子切换、平移暴露的新区域需要额外探针/混合，作者承认补洞区仍闪烁，动画、LOD 等仍有开放问题。论文中的性能数字不是本项目性能证据。

**本项目建议（未验证）**：若用户接受非屏幕轴对齐像素，先用固定相机位置、固定世界朝向的低分辨率 cubemap，实时光栅化同一株连续分叉网格，测试原地 yaw/pitch。无需先加入全部探针或枚举植物。风吹仍需刷新内容；固定采样坐标不等于冻结画面。若进入游戏仅处理茎层，必须保存可比较的深度/覆盖并处理与地形、花头的遮挡，不能最后无条件盖上 RGBA。

最终屏幕重采样、立方体接缝、很细枝条的源采样缺失仍需观察。纯旋转时的优点不能延伸成公转/行走已解决。

### 时间抗锯齿不是免费的保险

Godot 官方文档说明 MSAA 对几何边缘有效而不解决所有材质混叠，TAA 使用历史信息并可能模糊、拖影。[8] 对细茎风动与新暴露分叉，不应先依赖重 TAA 掩盖问题。测试可先关风、用无高频高光的简单材质区分问题来源，再逐项加回。

## 缓存：需要反驳的部分

“每株不同，所以缓存没有意义”仅对某类跨实例图像复用成立。

| 数据 | 建议 | 理由 |
| --- | --- | --- |
| 所有高度 × 分叉 × 角度 × 风动的离线图集 | 不作为主路线 | 组合增长且角度切换有视觉风险 |
| 每株分叉骨架、半径、生成种子 | 保留 | 表达植物，不需要与其他植物重复 |
| 每株生成的连续网格 | 按形态变化更新 | 同一株跨帧重复使用，转镜头不重建 |
| 风动姿态 | 动态计算 | 拓扑不变时可复用静态网格并变形 |
| 方向空间颜色/深度 | 先当实时采样目标 | 能否少刷新取决于运动/光照，别先承诺缓存收益 |

连续网格可由分叉图和渐细曲线生成；分叉接点需要单独处理，简单叠圆管可能产生接缝、鼓包。暂不以每帧完整 SDF 重建或高复杂度统一网格生成器作为前置条件。

## 下一轮讨论/可交互对照

优先确认：

1. “转视角”是否指相机位置固定的转头，还是相机绕植物公转？
2. 是否接受像素块随视角略有倾斜/变形，换取更稳定的附着感？还是要求始终屏幕横平竖直？

HTML 若制作，应是同一真实 3D 分叉几何、同一透视相机的同步比较，而不是图片轮播：正常光栅化、屏幕低分辨率、固定方向 cubemap。分别提供原地转头与绕物体公转、慢速自动转动、细枝宽度和像素密度，后加风动。明确标注网页不代表游戏的遮挡/性能验收。固定位置转头应保持足够视野而非暗中改成 orbit controls；同一图像整体旋转也不构成 3D 稳定性证据。

这是讨论设计，不是已经实现或通过验收的方案。暂未制作 HTML，先确认美术取舍后再决定是否值得做可交互对照。
