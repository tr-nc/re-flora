01 / 松弛，不是拉伸。

麻绳的柔软来自弯曲，而非橡皮筋式变长。试着拖起中间一段，观察重力如何重新分配弧线。

原型边界：二维 XPBD 段长 + 转角约束；离散线段–圆碰撞，无 CCD / 自碰撞 / 打结 / 真实扭转。水管未模拟截面压扁或水流；风筝使用示意升力，不是完整空气动力学。长度调节只改变静止段长，不是真正卷线。所有数值均为未标定的演示参数，不能直接移植为游戏物理配置。

02 / CHOOSE THE RIGHT COMPLEXITY

不是越复杂，越适合花园。

下面是工程取舍，不是本项目的性能测量。XPBD 的柔顺度可解释，但有限迭代仍有残差。

最值得提前守住的四条边界
  • 绳子的伸长、弯曲、扭转分开定义；“软”不是一个万能滑杆。
  • 模拟节点密度与渲染细分解耦；不能用视觉更圆滑掩盖穿透。
  • 接触检测覆盖整段，不只检测端点；高速时还需要 CCD。[6]
  • 动刚体只回写一次反作用；“端点跟着物体走”不等于双向耦合。
如何接入当前 Re: Flora？

当前 re-flora-physics 已封装 Rapier，CollisionWorld 默认 120 Hz。将绳索纳入同一固定时钟，并通过碰撞查询、挂接与冲量接口合作，而不是按渲染帧另起一套时间。

初版 CPU 顺序求解更易验证；GPU 只在 Release 实测证明瓶颈后考虑。本页没有修改 Rust、shader 或游戏配置。

为什么选择小步，而不是只堆迭代？

Small Steps 的实验表明，同等约束求解次数下，多次小步可减少伸长误差与数值阻尼。[2] 但碰撞检测成本、长链收敛、不同质量比仍需实测；它不是“永远只迭代一次”的通则。

本页使用固定 240 Hz、每步 8 轮；参数仅为离线手感展示。真实接入要由共同物理时钟调度内部子步。

水流、打结和收放线，为什么暂不实现？

水流应先作为端口流量 / 水压玩法独立建模，无须把流体粒子塞进软管。扭折导致断流需要曲率 / 截面模型，不由普通绳索自动得到。

打结需要可靠的段–段自碰撞、摩擦和连续碰撞；二维交叉也不能验证三维结。真实收放线要增删或重采样段、按线密度更新质量，并保持材料坐标连续。

02 / CONTACT

放进真实花园

地面、石头、薄杆；快甩、抓取、端点解除。核验穿透与地形更新后的接触。

03 / COUPLING

牵住真实物体

04 / SCALE

用 Release 决定优化

1 / 10 / 50 根，32 / 64 / 128 段候选矩阵。分测求解、碰撞与渲染，不以浏览器 FPS 代替。
