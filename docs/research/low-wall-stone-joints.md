# Stone 低墙：用有支撑的几何接缝代替悬空分层

调查基线：`85d8943a`。范围：问题核实与方案研究，**未修改游戏生成器、材质或存档**。
本轮没有导入图片/纹理资源，也没有进行新方案的视觉或性能验收。

## 结论

建议采用 **上下接触的砌块 + 外表面浅凹缝/倒角 + 少量石面起伏**。
先让真实几何成立，再利用现有光照显示分层；纹理只作辅助，不用纹理或阴影掩盖空气夹层。

第一步不需要新增贴图管线、材质 ID 或永久开关。现有 Rock 逐体素色差可以继续使用，
先看几何与光影是否已经足够。若以后需要“每块石头有不同颜色/石纹”，再单独设计
墙面外观的标识与持久化，不能顺手修改全世界 Rock 的着色。

## 1. 已核实的问题

### 影响范围

用户观察到 Stone 低墙的各排石块像悬浮。当前 **Stone 和 Brick 都使用同一横向床缝规则**；
Earth 的连续土墙不走该规则。单层墙没有层间床缝，多层直墙和平地已经足以产生问题，
不需要弯道、阴影偏移或复杂地面来触发。

### 根因与证据

[`LowWallRecipe::pieces`](../../src/app/low_walls.rs) 当前设置：

```rust
let bed_gap = 2.5 * VOXEL_SIZE;
// 中间的上层底面与下层顶面分别退开半条缝：
lower = layer as f32 * step + bed_gap * 0.5;
upper = (layer + 1) as f32 * step - bed_gap * 0.5;
```

`VOXEL_SIZE = 1 / 256`，因此相邻层之间的几何间距为 **0.009765625 世界单位 = 2.5 体素**。
它是贯穿整个墙厚的空层，不是只退入外表面的浅槽。各砌块自身是闭合体，不代表整面墙
有支撑或连通。当前 grounding 检查地面支撑、墙柱范围和每个闭合体的正体积，
但没有检查上层与下层的接触面积。

本轮用临时 Rust 探针调用实际 `LowWallRecipe::pieces` 和 `WallSlice::solid`，
在平地上测量相邻实体的最高/最低 Y；没有复制缝宽公式作为实现替身。
参数：width=0.06、height=0.12、pitch=0.05、seed=42，ground=0.5。
结果：

```text
Stone layers 0 -> 1: full-width empty bed = 0.009765625 world = 2.5000 voxels
Stone layers 1 -> 2: full-width empty bed = 0.009765625 world = 2.5000 voxels
Brick layers 0 -> 1: full-width empty bed = 0.009765625 world = 2.5000 voxels
Brick layers 1 -> 2: full-width empty bed = 0.009765625 world = 2.5000 voxels
Brick layers 2 -> 3: full-width empty bed = 0.009765625 world = 2.5000 voxels
FAIL: stacked masonry courses have no direct vertical contact on flat ground
```

探针以退出码 1 表示“应当接触但没有接触”。本地证据：
`target/low-wall-research/support_probe.rs`、`support_probe.log`。
它通过 Rust `#[path]` 引用本仓库 low_walls；为独立编译，仅将 path_band 源文件及其
子模块原样复制到该临时目录，链接已构建的 glam。不是新增的产品测试或性能基准。

现有测试：

```sh
cargo test low_walls_real_head_joints_stagger_upwards_without_an_internal_half_brick_gap -- --nocapture
```

本轮通过，但该测试明确断言相邻层间距为 `2.5 * VOXEL_SIZE`，所以它实际保护了错误的
外观契约。之前的“完整层数 / 无半砖伪缝”验证不能证明层间有支撑。
本轮也查看了已有 `target/low-walls/candidates.png`，它是旧原生验证截图，不是新效果。

**证据边界：**本轮确认的是生成几何的真实断开，未重新测量 GPU 体素化后的所有连通分量。
[`model_voxelize.slang`](../../shader/slang/model_voxelize.slang) 还会填充近表面的体素壳，
当前 [`MODEL_VOXELIZE_SURFACE_THICKNESS_VOX`](../../src/builder/plain/mod.rs) 为 0.75。
未来不能靠这个壳或偶然栅格对齐来保证接触；需要同时验证解析几何和实际 atlas。

## 3. 推荐的几何方案

### A. 先建立宽实的接触面

- 相邻层共享接触高度；不再以整块抬高/压低制造水平缝。
- 砌块在墙厚内部留有宽的上、下承压面，而不只是一个点、一条边或一个体素连接。
- 竖向接缝也应从“贯穿墙厚的空切口”改为外露面的浅接缝，保留错缝节奏。
  当前 `head_gap` 对 Stone 为 2.5–2.85 体素，对 Brick 为 2.5 体素，
  单独删 `bed_gap` 不是完整的表面接缝设计。
- 不用不可见碰撞盒支撑仍然悬空的可见石块。可见几何、体素实体、挖掘和保存必须一致。

### B. 外表面浅凹缝与微凸石面

一个石块的外表面可用少量分段截面构造：

1. 中部石面稍突出。
2. 靠近上下边缘逐渐退入，形成窄倒角。
3. 两排之间在外表面形成浅 V 形或不规则凹槽，槽底后面仍有石材接触。
4. 实际竖缝采用相同原则，但保持上下错缝，不形成通长竖裂缝。

示意（只说明墙厚方向，非网格精度）：

```text
错误：上层实体   ██████████████
      空气夹层   ··············  ← 整个墙厚都断开
      下层实体   ██████████████

目标：上层石面   ██████████████
      浅凹接缝   ·████████████·  ← 两侧浅退，内部有宽实接触
      下层石面   ██████████████
```

接缝处是实体形态的一部分，不是贴在连续墙上的浮空装饰板。接触区可由同一闭合砌块的
上/下截面表达，不要求另建一堵隐形墙来兜底。

### C. 石材感来自有界变化，而不是结构漂移

- 同一逻辑石块可有轻微的面部进退、削角和边缘不规则；不要独立随机升降每排的底面。
- 两个半格组成一块石头，必须共用同一个外形种子；不能在半格内部又出现一次倒角/色差缝。
- 保留当前 PathStroke 的共享截面和弯道闭合边界，不把凸起挤出允许的墙体宽度。
  先把最大外轮廓作为带宽边界，其余面向内退，让“凸起”相对于凹缝出现。
- 第一版建议从 **约 1 体素凹深、1–2 体素边缘过渡**试起，并按最薄墙/最低层高夹紧。
  这是视觉探索起点，不是已验证尺寸；0.75 体素的体素化壳可能吞掉小细节，
  必须用真实 Release 截图和 atlas 验证，不能靠扩大空隙补偿。
- 石块不要全倒成圆枕头；以偏平的断裂面、少量不对称削角为主。

### 为什么不是简单设 `bed_gap = 0`

同材质、共面的长方体体素化后会并成平墙，原先依赖空洞的水平分层就消失。
应一次性把“整层断开”替换为“接触实体 + 表面起伏”；仅删除空隙可以作为诊断，
但不是完整的视觉交付。

## 4. 纹理：适合作第二层，不适合先做

现状：

- [`candidate.rs`](../../src/app/core/pavement/candidate.rs) 把 Stone 写成 `VOXEL_TYPE_ROCK`，
  Brick 写成 `VOXEL_TYPE_TERRACOTTA`，不是独立的 StoneWall 渲染材质。
- [`terrain_material.slang`](../../shader/slang/terrain_material.slang) 已经给 Rock 添加
  稳定逐体素色差；它不知道哪一个体素来自墙、哪一层/哪块石头。
- 墙被烘焙成普通体素；GUI Save 保存建造偏好，Terrain Save 保存体素和植被。
  没有持久化的墙曲线、逐块 UV 或 block ID。参见
  [低墙恢复证据](../evidence/pavement-low-walls-restoration.md) 与
  [当前地形材质](../terrain_materials.md)（其后半部分为历史方案）。

因此建议分级：

1. **首选首版：**保留现有岩石色差，先做连续几何、浅槽、削角。通过逆光/侧光、
   平光、近景和普通游戏距离判断层次是否足够。
2. **可选后续：**低对比的每块明暗/冷暖变化、少量石脉或凿痕。它们跟随实际砌块，
   不要用高对比黑横线把墙重新画成“断层”。
3. **不推荐：**给全局 Rock 着色器按世界 Y 画横条；这会影响天然山石，且不匹配
   每次手势冻结的墙基准高度、行高和坡面。通用三平面投影能减少 UV 需求，
   但不能凭空恢复丢失的墙身份和分层坐标。
4. 真的需要逐块纹理时，先明确稳定的墙面外观身份/坐标如何保存、如何在 Dig 后继续有效、
   如何让主视图与 DDGI 一致。不要为了这次结构修正顺带引入大材质系统。

## 5. 建议实施边界与验收

### 所有权

- `src/app/low_walls.rs`：拥有层排布、逻辑块身份、接触几何和表面轮廓。
- `src/app/core/pavement/low_walls.rs`：把完整墙柱接地、转换为同一批有限闭合实体，
  继续走现有 candidate 保护、体素化和 Visible Terrain Publication。
- 有凹凸后，各层的接触面仍须由同一地面基准推导，不能每层重新独立采样而又制造裂缝。
- 不改 Earth、普通铺路、路径覆盖/回拖或全局 Rock 材质。Brick 共享的结构断开需同样修正，
  但 Brick 可以保留更规整的表面，与 Stone 的轻微不规则分开。
- 当前原生 fixture 按每层 12 个三角形索引；增加表面截面后必须改为显式层/块范围，
  不能让测试依赖旧三角形数量而误检。

### 行为验收

1. 解析几何：相邻层有正面积接触；表面凹槽不贯穿墙厚；各实体闭合且不越过路径边界。
2. 实际 atlas：跨层具有多体素宽的连接，而不只是角点接触；典型墙不产生悬空组件。
   测量不同轴向/斜向、亚体素平移、左右弯、闭环、坡地、最小/最大宽高和多种 seed。
3. 保持已有完整柱体发布、地面支撑、障碍保护、同手势连续性和闭环接头；
   无内部半块伪缝，建筑占用之外的地形不变。
4. 原生 Save → 重启 → Dig：存档字节和可编辑性按现有契约工作。
5. 视觉：正面和斜视不透过通长横缝看见背景；侧光可读出层数；弱阴影时也不像悬浮条带；
   近景不像软垫，远景不出现抢眼的黑线或随机闪烁。
6. 先交付视觉候选再优化。三角形增加会影响建造阶段体素化工作量；
   稳态帧率与建造耗时须用 Release 实测，不能仅据 CPU 几何测试判断性能。

### 兼容性

新生成器只影响之后新建的墙。已有存档只保存体素，不能安全区分“原有缝”与玩家刻意
挖出的洞，也不能可靠找回原始高度/行距。不自动填旧存档空洞；旧墙需玩家重建，
除非后续另行设计有明确选择范围的迁移工具。
