# 蝴蝶扇翅与飞行运动耦合调研

## 结论与范围

可以把翅膀相位与垂直、前进、转弯运动挂钩。建议采用**受生物力学启发的低阶模型**，而不是完整 CFD，也不是令高度直接等于翅膀角度的正弦。

本次仅调研和方案设计，不修改运行行为。代码基线：`56eed5c8`，工作分支 `butterfly-blend`。下面区分实验结论与游戏设计建议；实验主要涉及特定物种的起飞，不能直接当成所有蝴蝶巡航的通用定律。

## 一手研究

### 1. 下拍支撑体重，上拍合翼产生推进

Johansson & Henningsson (2021), *Butterflies fly using efficient propulsive clap mechanism owing to flexible wings*, DOI: [10.1098/rsif.2020.0854](https://doi.org/10.1098/rsif.2020.0854)。已读取[作者所在大学保存的摘要](https://lup.lub.lu.se/search/publication/39de965f-ff1e-48d2-9c95-a4478340a8d0)。PMC 页面正文此次抓取失败，不声称已读该篇全文。

研究结合自由飞行蝴蝶起飞时的流场测量与机械合翼装置，发现：

- 下拍主要承担体重支撑。
- 上拍及末端合翼时，柔性翅膀形成杯状结构、排出空气，提供向前推进。
- 柔性相对刚性机械翼提高有效冲量约 22%、效率约 28%。这些数值不能直接当成游戏加速度参数。

启示：一个拍翼周期内，垂直与前向加速度的峰值不应机械地重合；“合翼”也不只是无动力的回程。当前刚性关节翼并不具备实测的柔性杯状形变，第一版只能模拟其推进节奏。

### 2. 转弯是力方向与身体姿态一起变化

Henningsson & Johansson (2021), *Downstroke and upstroke conflict during banked turns in butterflies*, DOI: [10.1098/rsif.2021.0779](https://doi.org/10.1098/rsif.2021.0779)，已读取[全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC8633796/)，重点 Abstract、§2、§3、Figures 1–2。

六只银斑豹蛱蝶（Argynnis paphia）的起飞转弯数据表明：

- 身体侧倾，通过偏转气动力产生转弯所需侧向力。
- 身体朝向与飞行方向不完全一致；存在未完全补偿的逆偏航。
- 下拍与上拍甚至可能产生相反的侧向作用，上拍推进会降低转弯效率。
- 实测没有显著左右拍幅差异，但内外翼迎角存在差异。因此不能把“转弯必定是某侧翅膀扇得更大”写成事实。

启示：游戏里值得先实现平滑侧倾、有限转向响应、身体朝向与速度方向的小幅分离。不必第一版复现逆偏航力矩，更不应每次随机换方向都瞬时旋转身体。

### 3. 身体俯仰与翅膀惯性也参与运动

*Revisiting the flight dynamics of take-off of a butterfly: experiments and CFD simulations for a cabbage white butterfly*，已读取[全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC8966778/)，重点 Abstract。

菜粉蝶（Pieris rapae）的起飞测量与六连杆模型同样得到下拍升力、上拍推力的分工。腹部与翅膀惯性力与气动力量级可比，但平移作用部分抵消；惯性力矩仍影响胸部俯仰。该实验中，起飞初始上冲主要依赖腿部蹬离，不能全部归因于第一下拍翼。

启示：身体俯仰不是简单的速度向量朝向；可以保留周期内小幅俯仰，并叠加慢速机动姿态。不要把“离地弹起”误作每次拍翼都会产生的效果。

## 当前实现：同步发布不等于动力耦合

检查了以下源码与动画数据：

- `src/particles/butterfly_flight.rs`：120 Hz 固定步长；`SharedFlightRhythm` 按 `flight_frequency_hz` 采样有正有负的随机垂直意图；另外有巡航、随机机动、栖息地恢复、限加速度与限 jerk。没有从翼相位计算推进。
- `src/particles/butterfly_presentation.rs`：位置、速度与动画时间在同一展示 tick 发布。已有正确的统一展示时钟，不能再拆回独立更新。
- `src/particles/system.rs`：snapshot 携带每只蝴蝶的 `animation_phase_offset`，目前注明为渲染专用。
- `src/tracer/butterfly_mesh.rs`：`Mesh::pose` 从 `sampled_time + animation_phase_offset` 采样 `[wing, pitch, bob]`。整体 yaw 来自水平速度，额外 pitch 来自垂直速度；没有转弯 roll。
- `assets/models/butterfly.glb`：25 Hz 源关键帧、26 个含闭环端点的 key。网页和游戏直接共用此 GLB；翼运动耦合也从其旋转通道求出笔画积分，不再单独导出动画 JSON。当前 runtime 按一秒循环播放；源 FPS 与展示 FPS 都不是每秒拍翼次数。
- 模型原点还叠加局部 `bob`，它属于动画修饰，不参与真实轨迹与碰撞。若再给物理轨迹加整套同类起伏，会重复计算。

因此不能直接把现有默认 10 Hz 的随机垂直意图当成翅膀频率，也不能将展示 8 FPS 当成 8 Hz 拍翼。批准源与发布流程见[共享模型约定](../../assets/models/README.md)，Blender 制作配方保留在 `blender-v5/create_export_blender.py`。

## 建议的实现模型（设计建议，不是实测拟合）

### A. 一只蝴蝶，一个连续拍翼相位

建立模拟拥有的 `WingbeatState`，保存连续相位、频率和用力程度。固定步长推进相位，运动与翅膀都消费它；展示层只冻结同一时刻的完整快照，不能反过来驱动物理。

将动画采样从 renderer 私有代码抽到共享的纯数据模块：提供翼角、角速度/行程标记与周期俯仰。需要先检查源坐标与整个动画曲线，标记真实的下拍、上拍、合翼窗口，不能凭角度正负猜行程。动画循环相位与单次拍翼相位要有明确映射。

### B. 用拍翼调制加速度，不直接指定高度

示意模型：

```
phase += frequency * dt
acceleration = steering_mean
             + lift_amplitude * (downstroke_pulse(phase) - mean_downstroke) * support_axis
             + thrust_amplitude * (upstroke_pulse(phase) - mean_upstroke) * forward_axis
             + environmental_response
velocity += acceleration * dt
position += velocity * dt
```

这是保留现有平均飞行控制的“平均值 + 周期调制”模型，不是完整受力方程。周期脉冲减去自身均值，避免平飞被额外升力/推力不断抬高、加速；若之后改成真实升力、重力与阻力，必须整体替换平均支撑，不能重复叠加。姿态和幅度变化时仍需长期漂移验证，局部零均值不保证复杂机动下全局零漂移。

- 下拍增强支撑，上拍末端增强前向推进；两者窗口与动画同步。
- 加速度先改变速度，速度再改变位置，因此上升、最高点与翅膀极值不应强制同时发生。这是积分关系，不需要硬编码通用“滞后四分之一拍”。
- 慢速导航选择目标和平均转向，拍翼节奏决定周期内如何发力。
- 爬升、加速提高相关用力包络；下降降低平均支撑。频率可以后续小幅变化，但不是第一版唯一控制手段。
- 随机性放在每次机动或每若干拍的意图上，不再让独立的随机垂直力掩盖周期联系。
- 现有 jerk 限制可能抹掉拍翼脉冲。分别控制慢速导航平滑与有界拍翼调制，再统一安全限速/碰撞；需测输出波形，不能仅仅调大旧参数。

### C. 姿态与轨迹共同变化

由侧向机动意图/加速度得到有界侧倾目标，平滑跟随；侧倾影响支撑方向，并维持必要垂直支撑。身体 yaw 有限速地跟随目标，与速度方向允许小幅暂态差异。俯仰由飞行意图、低频速度趋势和源周期俯仰组合，不应直接用拍翼导致的每帧垂直速度反复放大。

第一版不做独立左右翼力矩求解。保留已批准翅膀外观，通过整体朝向、侧倾与相位耦合先验证观感。

### D. 明确起伏所有权与风

耦合模式中，世界轨迹负责可见的平移起伏；源 `bob` 应移除或明确缩减为局部修饰，不能双算。原模式保持不变。风漂移应独立于自身推进，身体朝向更适合参考相对空气的运动与飞行意图，而非完全跟随含风的地面速度。

### E. 保留像素节奏，不直接照搬真实频率

已有一秒动画循环及低展示 FPS 是美术选择。较高真实拍翼频率在低 FPS 下会混叠，甚至冻结或倒相；第一版保留批准节奏，先做相位关联，不同时改变频率与动画外观。后续明确选择风格化慢节奏，或提高展示采样率，不能把三种频率混成一个参数。

## 最小可视候选与验证

建议下一阶段仅实现：共享相位、垂直支撑脉冲、前进脉冲、轻微侧倾，并消除重复 bob。暂不模拟柔性翼、完整气流、腹部连杆或逆偏航。

- Debug 面板增加保存绑定的 A/B 复选框：unchecked 原模式，checked 耦合模式。遵循 `docs/agents/gui-settings.md`，不要增加 App-only 设置。
- A/B 切换保留个体、位置、寿命、颜色和相位连续性，明确速度/控制状态如何过渡。
- 确定性测试：相位 wrap、调频连续性、脉冲周期均值、左右转对称、安全边界、暂停/恢复、A/B 不跳位；2/8/16/60 FPS 展示不得改变物理结果。
- 记录 phase、行程、位置、速度、加速度、姿态，检查力峰值和动画行程确实对应，以及持续平飞无系统性漂移。不能仅检查波形长得像正弦。
- 原有避障、离地、恢复、限速仍必须有效；快照位置、朝向、翅膀相位保持原子发布。
- Rust/渲染修改后按仓库要求执行 fmt/check/test、release hidden muted run 并检查日志。此次只有文档，无运行验证需求。
- 先展示固定种子、同镜头的近景/正常视距 A/B，确认能看见“扇动产生运动”的因果感，再单独做 release 性能评估；不自动打开可见游戏。

预期观感是有节奏地托起、推进、侧倾转向并带惯性衔接，而不是一团粒子沿随机路径漂浮、翅膀恰好在播放动画。
