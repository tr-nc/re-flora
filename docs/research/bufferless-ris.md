## Why this estimator preserves the existing light model

Let `f(x)` be the nonnegative RGB irradiance contribution of a discrete light/tap pair, including the original finite-emitter quadrature weight, receiver cosine and current visibility/transmittance. For an analytic point there is one contribution. For a voxel box there are the same twelve receiver-facing Gauss contributions as the reference, **not a point-light replacement**.

A shared integer table proposes a light with `q(light) = multiplicity / 4096`. Its allocation starts from a 25% uniform / 75% power mixture with at least one slot per light. Receiver-side finite-emitter tap selection is uniform over twelve taps, so `q(pair) = q(light)/12`; for an analytic point, the otherwise ignored tap does not introduce a factor of twelve. Quantization changes proposal quality, not the intended energy, because the reciprocal uses the actual slot multiplicity.

For each reservoir, draw `M` proposals and stream weights `w_j = t(x_j)/q(x_j)`, where `t` is luminance of the unshadowed RGB response at the **actual receiver**, including its cosine. Select `x_s` proportional to `w_s`, trace only that selected connection, and return:

`f(x_s) × sum(w_j) / (M × t(x_s))`.

Average `K` such reservoirs. Conditional expectation over the reservoir's selection equals `(1/M) sum_j f(x_j)/q(x_j)`; expectation over properly distributed proposals recovers the reference discrete sum. Every proposal, including zero-response/out-of-range proposals, counts in `M`. Empty reservoirs return zero. Visibility is not used to discard proposals or renormalize visible-only energy. The discrete tests enumerate proposal sequences and selection intervals, including opaque/colored transmission, zero targets and the finite-emitter model.

This is an expected-value argument for the sampling algorithm, **not a claim that a fixed deterministic image equals its expectation**. Spatially shared proposals introduce correlation. Current hashes deliberately keep a static receiver's pattern stable instead of adding frame-to-frame random flicker; there is no temporal accumulation/denoiser and no guaranteed temporal convergence. Camera visibility compaction can change workgroup membership and hence the candidate pool. Wind and moving lighting still change receiver responses/visibility; no previous-frame lighting is reused. Bright rare paths, thin blockers and disocclusion can remain noisy or change their spatial grain.

## What the native evidence does and does not establish

The report contains actual eight- and nineteen-uploaded-light Release comparisons, not merely more authored objects behind the old eight-light cap. Sixty-four accepted analytic lights and final removal were additionally exercised through the existing DDGI lifecycle fixture. That fixture has essentially no grass workload (about 1 µs cache scope), so **its timings must not be advertised as sixty-four-light grass performance**. Terrain, trees and DDGI retain their original all-light consumers; this first experiment budgets raster grass/flower stem preparation, not the whole renderer.

The optional audit reads the real normal-program output in a separate shader, recomputes the same RIS value, and separately evaluates the exhaustive reference on a rotating receiver subset. Zero non-finite records and zero rendered mismatches establish the actual output path, not per-receiver equality to exhaustive lighting. Aggregate RGB errors are signed errors of repeated, correlated receiver samples; they are neither worst-case error bounds nor independent-sample confidence intervals. Quality approval, representative sixty-four-light grass scenes, controlled light/geometry motion at grass receivers, and Apple/MoltenVK runtime validation remain open.

During validation, a new proposal descriptor initially aliased the existing tree-cell descriptor at set 0/binding 47. A startup smoke and scalar CPU estimator tests did not detect the resulting zero direct lighting. The actual-receiver audit did. The proposal moved to free binding 57, and a red-then-green test now checks unique bindings across the real opaque/Glass normal/band/audit SPIR-V artifacts and audit read-only output access. Both finite-emitter and analytic-point selected connections use the authoritative transport policy. This is why a nonzero-reference/nonzero-rendered audit is mandatory rather than treating successful startup as lighting correctness.
