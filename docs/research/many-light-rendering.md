# Many-light rendering: source and decision record

Research date: 2026-11-03. Repository inspected at `6cb6edd93e59e5d85b0a7930092c282314b230e4`.

**Visual deliverable:** [HTML report](../reports/many-light-rendering/index.html). This note preserves source provenance, negative findings and decision boundaries, not an implemented-feature specification. No renderer, shader, GUI default or scene changes are part of this research.

## Decision

Adopt the established **fixed-budget stochastic direct-light sampling family** rather than continue inventing a coarse irradiance/visibility representation. For the current eight-selected-light, world-space grass-cache architecture, the smallest suitable starting point is shared light presampling plus **buffer-less RIS**. It selects a fixed number of light/emitter samples and traces visibility only for the selected samples. **ReGIR is a conditional spatial importance-sampling upgrade**, not a mandatory default-size grid; full screen-space **ReSTIR DI plus denoising** is a larger, quality-oriented rendering migration, not a drop-in for the current grass pipeline.

This is an algorithm-family recommendation, **not authorization to vendor RTXDI**. The repository is GPL-3.0; the inspected RTXDI/RTXDI-Library and NRD licenses are NVIDIA proprietary SDK licenses. In particular, RTXDI-Library license §4(e) prohibits uses that subject the SDK to the described source/distribution obligations. Do not import the SDK into the GPL application without a compatible grant and licensing review. An independently expressed implementation of published, established sampling mathematics is ordinary algorithm implementation, not an invitation to invent a new estimator; copying restricted SDK source or assuming a paper's pseudocode is permissively licensed is not approved. No patent clearance is implied.

Shared sampling aggregates a **weighted sample distribution**, not an exact irradiance sum. Fixed-budget receiver work replaces full light enumeration with a stochastic estimate of that sum. This satisfies the intended no-all-light-loop/no-12-taps-per-selected-light work organization, but must not be described as exact constant-time evaluation of arbitrary lighting. Quality can worsen as lighting complexity grows. If an exact pre-summed lighting field is still an independent requirement, stochastic sampling is not that representation.

## Project facts checked in code

- [`src/lighting/mod.rs`](../../src/lighting/mod.rs): `LOCAL_LIGHT_GPU_CAPACITY = 8`, explicit stable small-N selection; CPU registry remains unbounded. More authored emissive objects do not mean more than eight current GPU-selected local lights. Scaling above eight requires changing and validating the actual upload/selection policy, not only the scene.
- [`shader/slang/local_emitter.slang`](../../shader/slang/local_emitter.slang): twelve Gauss taps on three receiver-facing box faces; twenty-four stable source identities across all six faces. Preserve this energy/model contract during a sampling comparison rather than silently substituting a point light.
- [`shader/slang/local_visibility_query.slang`](../../shader/slang/local_visibility_query.slang): receiver loop over `localLightCount(info)`, with an inner `LOCAL_EMITTER_SAMPLE_COUNT` loop. Current visibility sharing does not remove `G × L × 12`.
- [`shader/slang/flora_lighting_cache.comp.slang`](../../shader/slang/flora_lighting_cache.comp.slang): shading at prepared world-space stem/layer receivers; DDGI environment plus local direct light, written to the flora cache.
- [`shader/slang/grass_band_cached.vert.slang`](../../shader/slang/grass_band_cached.vert.slang) consumes prepared position/color; [`shader/slang/flora.frag.slang`](../../shader/slang/flora.frag.slang) outputs only color. These interfaces do not supply the per-pixel grass material/normal/depth/motion/history guides needed by a standard screen-space ReSTIR+NRD pipeline. This is a claim about this grass path, not absence of depth/camera data everywhere in the engine.
- Current visibility is custom compute Contree/dense Glass transport, not an existing Vulkan hardware-RT backend. RTXDI's application visibility callbacks permit architectural separation, but compilation and performance on Slang/MoltenVK are unverified.
- Prior negative evidence: [fixed-32 report and diagnostic](../reports/local-light-field-32/README.md), no blockers, upward exact response about 711.108 versus old irradiance interpolation 0. This is a deterministic diagnostic, not a new quality test or proof against every possible field.
- Prior positive evidence: [measured visibility fix](../reports/visibility-performance-fix/measurements.json), Apple M4 Pro / Vulkan–MoltenVK, three alternating 30-second Release pairs, eight selected lights. Median grass 28.472 → 22.812 ms; whole-profiled FPS 17.1465 → 18.5292. Historical local measurements, not a measurement or prediction for RIS/ReGIR/ReSTIR.

## Primary-source ledger

All web sources below were accessed 2026-11-03. Dynamic docs are identified separately from pinned source.

1. **ReSTIR DI, SIGGRAPH 2020** — [authors' NVIDIA Research page](https://research.nvidia.com/labs/rtr/publication/bitterli2020spatiotemporal/). Supports reservoir-based spatial/temporal resampling, unbiased and biased variants. Its published speedups/ray counts are not re-flora measurements.
2. **Production rearchitecture, HPG 2021** — [Wyman and Panteleev](https://research.nvidia.com/labs/rtr/publication/wyman2021rearchitecting/). Productization addresses cost, coherence, ray budget and quality/performance controls; not evidence that the original academic implementation is a turnkey engine feature.
3. **RTXDI Integration** — [pinned document](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/Integration.md), especially “World-Space sampling and ReGIR.” Explicitly supports buffer-less sampling through `RTXDI_SampleLocalLights`; shadowing is not evaluated there. ReGIR stores world-space light samples, is rebuilt per frame, can feed ReSTIR, and is not an irradiance field.
4. **RTXDI Noise and Bias** — [pinned document](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/NoiseAndBias.md). Wrong PDF zeros can lose support; full material response matters. Initial sampling alone is inadequate for high-quality large-light-count pictures under tight real-time budgets. Temporal/spatial reuse, visibility reuse and bias correction have distinct costs and failure modes. Do not promise arbitrary-scene unbiased output or denoiser-free many-light quality.
5. **RTXDI application bridge** — [pinned document](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/RtxdiApplicationBridge.md). Applications own surface/light representations, sampling/PDFs, visibility and temporal light mapping. A Vulkan SDK sample is not automatic Apple/MoltenVK/Slang compatibility.
6. **ReGIR original chapter, 2021** — [research page](https://research.nvidia.com/labs/rtr/publication/boksansky2021rendering/), [author-hosted PDF](https://boksajak.github.io/files/RTG2_ReGIRGridBasedReservoirs.pdf), Ray Tracing Gems II chapter 23, pp. 351–365. Describes two-stage RIS, actual-receiver BRDF reweighting, 16³ cells / 512 slots defaults, eight build candidates, noise, slight bias, dynamics/history caveats; larger cells and limited stored samples affect quality. PDF uses CC BY-NC-ND 4.0: link, do not vendor illustrations/pseudocode as presumed MIT code.
7. **RTXDI-Library ReGIR implementation** — pinned `f12037fa8e97ebc08e9e3edfd2de528ed1772a4b`: [ReGIR parameters](https://github.com/NVIDIA-RTX/RTXDI-Library/blob/f12037fa8e97ebc08e9e3edfd2de528ed1772a4b/Include/Rtxdi/ReGIR/ReGIR.h), [build](https://github.com/NVIDIA-RTX/RTXDI-Library/blob/f12037fa8e97ebc08e9e3edfd2de528ed1772a4b/Include/Rtxdi/LightSampling/PresamplingFunctions.hlsli), [receiver initial sampling](https://github.com/NVIDIA-RTX/RTXDI-Library/blob/f12037fa8e97ebc08e9e3edfd2de528ed1772a4b/Include/Rtxdi/DI/InitialSampling.hlsli). Receiver loop bound is `numLocalLightSamples`, not total light count. Out-of-grid path selects Power RIS or uniform sampling, not an exhaustive visibility fallback. ReGIR slot payload is `uint2`; optional compact-light storage is additional.
8. **RTXDI-Library license** — [pinned license](https://github.com/NVIDIA-RTX/RTXDI-Library/blob/f12037fa8e97ebc08e9e3edfd2de528ed1772a4b/LICENSE.txt). Inspected source has `LicenseRef-NvidiaProprietary`. Repository [README](../../README.md) and [LICENSE](../../LICENSE) identify project code as GPL-3.0. Licensing gate is substantive, not a footnote.
9. **RTXDI sample platform/build description** — [pinned README](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/README.md). D3D12/Vulkan via NVRHI and HLSL→SPIR-V via DXC; documented build paths Windows/Linux. Does not establish a tested macOS Slang/MoltenVK path.
10. **MegaLights** — [Epic official docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/megalights-in-unreal-engine), rendered as UE 5.8 on access. Fixed ray budget, importance sampling, denoising; quality degrades with lighting complexity. Current docs describe hardware/software RT paths, a hardware-RT recommendation, and incompatibility with the Forward Renderer. This is independent industrial support for budgeted stochastic lighting, not proof MegaLights is identical to ReSTIR or that its performance transfers to this engine. Do not repeat obsolete version-specific “experimental/no translucency” claims as current facts.
11. **Practical Clustered Shading** — [Emil Persson / Avalanche, SIGGRAPH 2013 PDF](https://www.humus.name/Articles/PracticalClusteredShading.pdf). Spatial light-list culling, forward/transparency considerations; historical Just Cause 2 four-lights-per-tile cap. Cluster lists reduce typical candidate counts but do not guarantee a light-count-independent receiver loop under overlapping lights. A fixed cap is deliberate omission, not exact aggregation.
12. **LTC, SIGGRAPH 2016** — [Heitz et al. author page](https://eheitzresearch.wordpress.com/415-2/). Efficient polygonal BRDF integral approximation. Does not itself eliminate arbitrary visibility work or the loop over multiple lights.
13. **Lightcuts, SIGGRAPH 2005** — [Cornell author page](https://www.cs.cornell.edu/~kb/projects/lightcuts/). Hierarchical light aggregation and error-controlled cuts. Does not supply an unconditional constant receiver-work bound.
14. **Stochastic Lightcuts** — [Cem Yuksel author page](https://www.cemyuksel.com/research/stochasticlightcuts/). Hierarchical sampling replaces correlated approximation artifacts with noise; another established sampling family, not proof of turnkey project integration.
15. **Cycles Light Tree** — [Blender 4.2 manual](https://docs.blender.org/manual/en/4.2/render/cycles/render_settings/sampling.html), [v4.2.0 source](https://github.com/blender/blender/blob/v4.2.0/intern/cycles/kernel/light/tree.h). Production-renderer implementation; sampled hierarchy and distance/intensity selection. The inspected file is Apache-2.0, not the RTXDI license. This does not clear every dependency automatically. Balanced-tree selection is approximately log(L), not strict O(1), and Cycles is not evidence of real-time grass performance.
16. **Volumetric Lightmaps** — [Epic official docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-lightmaps-in-unreal-engine), rendered as UE 5.8. Precomputed indirect lighting, spatial interpolation and increased samples near geometry. Not a ready fixed-32 dynamic direct-light solution.
17. **idTech 8 GI, SIGGRAPH 2025** — [Tiago Sousa official course PDF](https://advances.realtimerendering.com/s2025/content/SOUSA_SIGGRAPH_2025_Final.pdf), pp. 12–24, 29, 32. Shipped Indiana Jones / DOOM examples; world-space cascaded light lists, radiance cache, irradiance volumes and final gather have different responsibilities. The listed 64-ID cell cap and clustered per-cache-entry shading are not proof of an exact constant-cost many-light grass receiver. Its published GI timings are not re-flora direct-light timings.
18. **NRD** — pinned `1b6c1865cb59cd14081f2e2eecd02e37b8ca6853`, [README](https://github.com/NVIDIA-RTX/NRD/blob/1b6c1865cb59cd14081f2e2eecd02e37b8ca6853/README.md), [license](https://github.com/NVIDIA-RTX/NRD/blob/1b6c1865cb59cd14081f2e2eecd02e37b8ca6853/LICENSE.txt). Denoising needs per-pixel normal/roughness/viewZ/motion guides; RELAX is designed for RTXDI. Current license is NVIDIA RTX SDKs LICENSE, not presumed MIT. Official RTX 4080 denoising timings are deliberately not used to predict M4 Pro cost.
19. **Apress companion repository negative check** — [official repository](https://github.com/Apress/Ray-Tracing-Gems-II). Root says code is generally MIT unless chapter exceptions apply. Its fetched directory listing did not contain `Chapter_23`; therefore this research did **not** establish an MIT ReGIR implementation there. Search-generated claims that `Chapter_23` is available were not accepted as evidence.

## Decision boundaries and required future evidence

- Fixed M candidates per output and K selected connections per receiver. Build/update work may scale with L; receiver random access to at most bounded sampled records is allowed, enumeration is not. Never run all twelve finite-emitter rays after selecting one light.
- Empty/unready/out-of-grid sampling uses bounded global sampling. Full original integration remains an explicit A/B/reference mode or sampled audit, not a concealed production fallback.
- Preserve DDGI spacing 32, indirect response, exposure/intensities, authored emitters, geometry and save ownership. A ReGIR sample-distribution grid is not additional irradiance probes, but its cell sizes/memory still require explicit disclosure; do not use spatial densification as the quality remedy.
- For current eight lights, compare uniform/power/shared-presampling RIS before adding a potentially expensive ReGIR grid. The source's 16³ × 512 × 8-byte slots are 16 MiB of payload, and eight build candidates mean 16,777,216 cheap candidate evaluations/frame if all slots are rebuilt. Additional compact-light/history/flight resources are excluded. These are arithmetic estimates, not local measurements or recommended settings.
- The inspected packed DI reservoir is 24 bytes. Two tight screen-sized arrays would be 168.75 MiB at 2560×1440, or 6.75 MiB at 512×288. SDK block-linear pitch and any extra arrays, guides, denoiser and frame/history duplication add cost. Do not apply the low-resolution terrain figure to full-resolution grass automatically.
- Statistical energy agreement is different from the exact visibility cache's same-frame RGB equality. Validate all-light/high-sample references, two-sided color/energy errors, noise over time, motion/wind/disocclusion, near-lantern failures, thin blockers and add/move/remove/photometric edits. Check stale-history removal separately from convergence lag.
- Real Release validation must include eight-light current scene and actually uploaded higher light counts, grass receiver scaling, build costs, memory and continuous edits. Use the real uninstrumented production program and include cold/update costs. No performance forecast from a paper or SDK sample is a local acceptance result.
- Baseline seed-7 Glass DDGI non-finite-record failure remains independent; this research does not fix or clear it.
