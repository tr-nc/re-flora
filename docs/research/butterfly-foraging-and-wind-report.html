Butterfly / Foraging / Wind

让蝴蝶
有自己的打算。

不是把随机飞行调得更复杂，而是让它看见一朵花、想去那里、停一会儿，再因为新的机会或一阵风改变主意。

7 项研究 / 机构资料 对照当前 Rust / Shader 实现 只交付报告，尚未改动游戏行为

源码基线：new-bird @ 256b77c4。现状来自静态代码审阅，不是实机观感、性能或生物学拟合验证。全文标注的时间与调参范围均为游戏设计建议，除非明确注明为研究结果。

01 / THE RECOMMENDATION

最值得先做：从“围着出生点飞”变成“在花之间生活”

保留已有的扑翼、急转、惯性和风漂移，在上面加一个小型访花行为层。最有价值的变化不是更多蝴蝶，而是单只蝴蝶的一段行为变得可读。

FIRST · 花有吸引力

喜欢一些花，但不只认一种花

花的种类、外观与可取食程度形成偏好；每只蝴蝶略有不同。优先访问附近合适的花，不总是锁定最近一朵，也不全体追同一个点。

SECOND · 飞行有目的

跨花飞行，靠近时明显减速

远处是带轻微曲折的转移，近处是犹豫、对齐、落稳。随机机动服从意图，而不是持续把它从目标旁边弹开。

THIRD · 停留有区别

取食停驻 ≠ 空中徘徊 ≠ 休息

先做好花上取食的停驻，再扩展石头、叶面上的休息。停下来时翅膀与身体也要改变，不能只是速度变成零、原动画照播。

FOURTH · 改主意有原因

风吹偏、花不合适、目标消失

小风中保留目标并纠偏，大风中可以放弃或暂歇；一次取食不理想后更愿意尝试另一类花。不是每帧重新抽一次目标。

一句话路线：

先完成“选花 → 接近 → 停驻 → 起飞去下一朵”的闭环，再让风与短期记忆改变这个闭环。不要先做完整昆虫生态、气味流体或空气动力学。

02 / REAL BEHAVIOR, USEFUL ABSTRACTIONS

现实里的六条规律，够用就好

以下将“研究发现”与“游戏转译”分开。物种、实验材料和环境会改变结果；没有一个适用于所有蝴蝶的万能花色或固定停留秒数。

研究 · 颜色与奖励

吸引它的，不只是“漂亮”

Leptophobia aripa 的人工花实验中，未训练个体更偏好红色；它也能学习颜色与糖奖励的关系。Papilio xuthus 的另一组实验则较多访问蓝、紫色人工花，视觉与气味都会影响访问。[1][2]

游戏转译：用“花的吸引标签 + 蝴蝶个体偏好”，不要硬编码“所有蝴蝶都爱紫花”。初版以种类与可见外观为线索；香味先作为抽象吸引参数，不做气味扩散场。装饰用翅膀配色不必直接等同真实物种。

研究 · 访花恒常性与学习

有偏爱，也能重新学会喜欢

绿脉粉蝶 Pieris napi 在人工双色花实验中，个体会连续偏向一种颜色。仅一种颜色有花蜜的三天训练能改变偏好，再训练也能反转这种偏好。[3]

游戏转译：最近几次取食成功，会让它更愿意去相似的花；但留一点探索机会。游戏里用秒级短期记忆，是节奏压缩，不是把三天实验改写为自然时间规律。

研究 · 离开与换花

上一朵不理想，下一次更可能换种类

Thymelicus flavus 的野外研究发现：上一朵花奖励低于平均水平后，更常发生花种切换；换种后花朵处理时间平均增加约 0.85 秒，而且没有因此缩短飞行时间。[4]

游戏转译：停留长短与“这次是否值得”相关，离开后偶尔试别的花。0.85 秒是该研究的处理时间差，不是通用停驻时长；也不要让每次路线都像最短路径算法。

研究 · 风与飞行活动

强风不只带来漂移，也会减少飞行

Colias 的风洞 / 野外研究中，风影响散热与飞行：风洞里偏好 0.5–1.5 m/s 的气流，达到 2.5 m/s 时未观察到飞行；野外主动起飞发生在不超过约 1.4 m/s 的条件。[5]

游戏转译：弱风轻微吹偏，中风需要修正，强风允许放弃目标或寻找遮蔽。上面是特定物种 / 条件的结果，不能当全体蝴蝶阈值；游戏风场强度也不是 m/s。

机构实践 · 休息与微环境

花不是唯一值得停下来的地方

Butterfly Conservation 建议花园同时提供富含花蜜的花、幼虫食草、阳光下的石头 / 裸地，以及挡风树篱等遮蔽。成蝶补充花蜜、晒太阳与幼虫取食，是不同需求。[7]

游戏转译：以后可以让它偶尔落在暖石头、叶片或避风角落。成蝶访花目标与“从哪种植被生成”应分开，不能把所有草和树叶都当成花蜜来源。

研究 · 时间记忆，留给以后

有些蝴蝶会记住什么时候去哪儿

Heliconiini 实验显示，部分物种能学习早晚不同的颜色奖励关系；Heliconius 的固定访问路线与它们特殊的花粉取食生态有关。[6]

游戏转译：成熟版本可出现熟悉的花簇与回访路线。但初版只需“刚去过哪里、取食是否成功”；不要强迫所有蝴蝶按同一条循环航线飞。

证据边界

上述研究支持偏好、学习、换花和受风限制。报告中的“飞到一半改目标”“小回旋”“有限抗风控制”是游戏设计推演，不是这些论文直接证明的通用行为。也没有用蜜蜂的实验替代蝴蝶结论。

03 / CODE AUDIT

现有底盘值得保留，缺的是行为意图

当前行为链：植被提供生成机会 → 发射器创建个体 → 固定步长飞行 → 统一姿态发布 → 模型渲染。
环节当前已有与期望的差距
生成与植被源码 C1草、人工花卉、树冠按供给分组；人工植被的蝴蝶生成偏重为 1.5，草与树冠为 1。低频更新机会，已有总量 / 局部密度限制。这是“在哪出现”的权重，不是“飞向哪朵花”。生成点来自植被根部或树叶，并未提供可访花的实时花头目标。
个体与目标源码 C2ActiveButterfly 持有粒子句柄、噪声状态、离地阶段和飞行状态。没有花头句柄、访花阶段、取食 / 休息计时或最近访问记忆，因而还没有花到花的闭环。
飞行动力源码 C3120 Hz 固定步长；巡航 + 有种子的随机机动；限制加速度 / jerk；地形与边界保护；偏离出生栖息中心后软拉回。水平栖息半径常量为 0.32 世界单位，中心不是当前花目标。直接加一股“花吸力”会与旧恢复力、随机机动争夺控制。
风响应源码 C4按所在位置读取水平风场，平滑独立漂移速度，自飞速度与风漂移分别调节。已有被吹走的基础，不需重写风。缺少目标保持、到达失败 / 放弃的条件、强风暂停策略；此 CPU 风采样本身没有花旁几何遮蔽信息。
展示与停驻源码 C5位置、速度和扑翼在同一展示 tick 发布；已有扑翼耦合 A/B。模型朝向由发布的速度决定，零速度返回固定朝向。不能只把速度设零：停驻需要独立的稳定朝向、花头法线与翼姿。受风时身体朝向也可能需要与地面位移方向分离。
120 Hz飞行积分，不由展示 FPS 驱动
8 FPS仓库配置：位置 / 朝向 / 翅膀展示
50–60 s仓库配置：个体生命周期
0.25× / 1.0×仓库配置：自飞 / 风漂移

这里是 config/gui.toml 的已保存值：Darting，扑翼耦合开启，maneuver_tempo = 2.75，离地高度 0.08。构造器兜底值不同，例如生命周期 10–15 秒、耦合关闭；用户本地配置还可能覆盖它们。不能拿旧文档默认值当作当前效果。

一个值得实机检查的比例，不是已经复现的缺陷

按当前 0.25× 自飞配置，基础巡航约 0.025–0.040 世界单位 / 秒，自飞速度上限 0.075；风强度为 1、漂移为 1× 时，漂移目标为 0.060。由此可知风可能与自飞同量级甚至超过巡航。下一步应检查“有意图地被吹偏”是否变成“持续被拖走”，而不是盲目再加大风。以上是常量换算，没有测量实际轨迹。

04 / A SMALL GARDEN STORY

一段十几秒的小故事，比一串随机急转更有生命感

片段 1 · 约 0–2 秒

发现一朵喜欢的花

朝它转向，带一点侧倾；绕过后再靠近，而不是直接贴上去。

片段 2 · 约 2–6 秒

减速，落稳，取食

脚落在花头合适位置，身体跟着花轻摇。翅膀进入停驻姿态，偶尔轻开合。

片段 3 · 约 6–9 秒

离开，去下一朵

先离开花面，再沿略带弯曲的路径转移。短期内不立刻回同一个接触点。

片段 4 · 约 9–14 秒

被风打断，再作决定

先产生侧向位移，随后修正；如果前进受阻，就放弃，改去附近另一朵花。

这是一次视觉审阅用的编排，不是每只蝴蝶都必须遵守的时间表。花间距离、取食结果与风会改变节奏，不能所有个体同时停驻、同时起飞。

05 / THE LIGHTWEIGHT MODEL

一个小状态机，加一点记忆，就能解释大多数动作

探索 / 选花找局部可见候选
→
转移飞行目标主导，轻微曲折
→
接近 / 落稳减速、对齐花头
→
停驻取食跟随宿主，不巡航
→
起飞 / 离开释放接触，再选花

打断分支：飞行中被明显吹偏 → 恢复控制 → 返回原目标或重新选花；目标被删 / 不再有效 → 立即释放引用，安全离开；后续再加“休息 / 避风”。风偏移首先是运动结果，不必每次都跳状态。

选哪朵 · 不是全局最优

只比较附近少量候选

先过滤真实存在、可见生长状态足够、具有可接近花头的候选。按附近花簇搜索，再在少量较优候选中做有种子的加权选择。

吸引分 = 个体花类偏好 + 可见花头吸引力 + 记忆中的预期收益
− 距离 / 逆风代价 − 最近访问惩罚 − 接触点拥挤代价

这是示意评分，不是自然界公式。未访问过的花用初始收益估计，真正奖励在停驻后确认；不要让蝴蝶远距离“读到”所有花的实时花蜜。拥挤惩罚是防穿模的游戏规则。

何时换目标 · 有承诺，也有例外

保留原计划，直到有充分理由

  • 定时低频评估，而非每个积分步抽目标。
  • 有效目标有短暂承诺期；新目标明显更好才考虑切换。
  • 接近时更少换目标，避免“就差一点又折返”。
  • 目标消失、路径失败或强风阻止前进时，可立即解除承诺。
  • 落空 / 收益低后降低相关花类估计，但不永久拉黑。

记住最近 2–4 个花头即可起步；决策 2–4 Hz、承诺约 1–3 秒可作为首轮调参起点，均是设计建议。个体错开决策时刻。

怎么停 · 接触不是“暂停粒子”

靠近会慢，停下会稳，离开会起飞

  • 以相对花头的距离和速度判断是否落稳，不只看世界坐标距离。
  • 抵近时衰减随机机动和巡航支撑，避免在花边一直弹跳。
  • 停驻使用花头局部接触点、法线和独立朝向；选择合适的收翅 / 半开翼姿态。
  • 取食计时有长短变化；先可用 2–6 秒的有界分布试观感，不必模拟每滴花蜜。
  • 起飞先清空接触，再离开花面；不把位置瞬间切到下一朵花。
风怎么参与 · 有限能力，而非抵消一切

弱风纠偏，强风允许失败

  • 继续使用现有局部风漂移，不另加第二套风力。
  • 控制器以花目标误差请求有限的空气相对推进；保留最大速度和加速度约束。
  • 一段时间没有接近目标，才判定逆风到达失败。
  • 大阵风中允许明显偏移，随后恢复或改选，不瞬时把它拉回航线。
  • 花上停驻时跟随宿主约束，不把自由飞行漂移继续叠上去。强风若触发离开，应有起飞过程。

纠偏与放弃是游戏控制设计；这次资料没有验证花园访花时的具体补偿率。不要宣称它是实测抗风模型。

06 / FITTING THE EXISTING ARCHITECTURE

正确接入，比直接增加“花的吸引力”重要

花源观察层
提供事实，不控制蝴蝶

从已提交植被维护局部花头目录，发布稳定身份、生长 / 可见性、花类与接触点。借鉴现有 ecology 的分组与 token 思路，但访花资源独立于出生机会调度。通过增删 / 生长更新失效，避免每只蝴蝶逐帧扫描所有植物。

访花意图层
选什么、什么时候离开

建议新增独立的 ButterflyBehavior，由发射器拥有个体状态；只输出飞行目标、接近模式、停驻请求及原因。记忆、偏好与承诺在这一层，不塞进模型 renderer，也不把动物状态塞入共享 ecology 调度器。

运动与接触层
怎么到达、如何安全停驻

在 DartingFlightState 加受意图控制的 steering，按状态调整随机机动与高度策略；保留 120 Hz、有界积分、风漂移与地形保护。目标有效时，不再被原出生点恢复力持续拉回。停驻后以宿主约束取代巡航，失效时安全脱离。

姿态与展示层
让动作可读，不反驱模拟

快照增加停驻 / 起飞姿态语义与显式朝向，渲染消费它。保持完整姿态同帧发布。延续当前飞行扑翼与像素节奏，不把 8 FPS 展示或 6 Hz 随机垂直意图误当生物拍翼频率。

最容易被低估的工程点：真实花头的位置

当前 ecology 取到的是根部坐标；flowerPlantPose 的实时花头还受层数、尺寸、生长、生成动画、朝向、风响应等共同影响。现有 socket 是花茎与花头的接合平面，不是蝴蝶脚下可直接使用的花瓣表面。需要单独定义花头上的安全接触点，并共享同一姿态事实。见源码 C6。

  • 不复制一套会漂移的花头公式。发布可复用的花姿态 / 附着契约，或共享纯姿态求值；若采用 GPU 小批量异步发布，需要 revision、时间戳和失效规则。目录可低频刷新，已锁定宿主姿态需足够及时。
  • 不把稀疏 GPU 读回扩大为热路径。现有 sample_ecology_root 每次读取 8 字节实例，只在少量机会下使用；不能把它放进“所有蝴蝶 × 所有花 × 120 Hz”循环。要先确定 CPU 可见的已提交花源数据如何维护。
  • 花会摇，附着不能锁旧世界坐标。明确接触态的共同展示时间 / 宿主变换：避免花每帧摇动、蝴蝶保持旧位置而脚下滑动，同时不能破坏位置、朝向与翅膀的一致发布。
  • 目标需要稳定身份，不依赖数组 slot。slot 只能是定位提示，须验证 root token、花头编号与世界 / 发布代际。拔花、剪草、重载世界或 GPU 实例重排都不能误绑到另一朵花。
  • 不要把避风当成已经存在。当前 CPU 水平风场不表达石头、树篱后的局部遮蔽。初期只做风偏移 / 失败 / 恢复；真正的避风点需新增经验证的遮蔽资源，不能只因靠近树就声称风已经减弱。
  • 不要只改 renderer 假装落花。世界模拟与接触状态必须一起成立。当前地形射线保护也不等于完整的花头 / 茎叶碰撞，需要有界接近与脚点验证。
未来开发时，预计影响的文件边界

访花目录与身份：src/builder/surface/、src/flora/，必要时为花姿态提供小型共享发布接口。个体意图：新增 src/particles/butterfly_behavior.rs，接入 emitters.rs；动力改动限制在 butterfly_flight.rs。停驻姿态触及 system.rs、butterfly_presentation.rs 与 src/tracer/butterfly_mesh.rs；若已有模型没有停驻姿态，再补相应动画数据。配置沿用 SavedCustomSettings / SavedControls，不手改生成文件。

07 / PRIORITIES & ACCEPTANCE

先做一个可看的候选，不一次性做完整生态

P0 · 基础闭环两簇花、一只蝴蝶，先证明它真的在访花

以真实可用花头目录为前提，实现选花、转移、接近、停驻与再次起飞。保留原模式；不改蝶模型风格，不扩大全局数量。需要看到它能够离开原出生圈、稳定落在实际花头上、停留之后去另一朵。若宿主姿态暂不能可靠共享，标明“接近花”的未完成候选，不能把花上方悬浮冒充落花。

P1 · 风与改主意同一个体，同一阵风，让打断有因果

加入有限纠偏、无进展放弃、目标失效与短期访问记忆。应看到被吹偏的位移先发生，然后才出现修正 / 改选；去掉花时应安全离开。此阶段先用抽象取食成功率 / 有界停留，不上全局花蜜守恒系统。

P2 · 生活感与生态联系在视觉结果确认之后，再加个性与微环境

扩展不同花类偏好、叶面 / 石面休息、真实遮蔽、回访路线；如果花期与日照系统值得支持，再接入它们。之后可让开花、适度浇水与花簇布局影响访花机会，但遵循花园的温和后果，不做饥饿惩罚或玩家离线时的不可逆损失。

效果已获认可，访花固定启用

访花闭环已实现并经用户认可，现移除访花行为的 A/B 复选框及保存开关，日常引导飞行固定使用访花行为。搜索半径、停留时长、个体偏好与风阈值仍可调整并保存；旧配置中的启用 / 关闭值不再影响行为。现有 Wingbeat-coupled flight 调参独立保留。上方源码审计与分期路线是原始调研基线，当前实现及历史对照验证见 实现与验证记录。

按仓库设置规则绑定保存字段，不加 App-only slider 或独立 save hook。按调整目的组织“访花 / 停驻”“风响应”，而非把同一关注点散到每种植物面板。状态 / 目标 / 失败原因记入日志，不堆在 Debug 面板。见 Debug 设置接入规则。

观察场景视觉 / 正确性验收避免的假成功
无风、两簇花能去不同花头；接近明显变慢；停驻后有起飞过渡；能跨原出生圈。仍在出生点附近随机游走，只是偶然路过花。
局部阵风先吹偏，再有限纠偏；强风无法前进时可放弃；风散后恢复。完全抵消风，或无限逆风扑向同一个目标。
花摇、花被删 / 世界重载接触点跟随正确宿主；引用失效即释放；不穿地、不误绑新实例。悬在花上、脚滑，或仍锁定已删除花的坐标。
无花 / 多只蝴蝶无花时自然探索；个体偏好与停留错开；接触点不严重重叠。无花卡死，或所有个体同步往同一朵花飞。
不同展示 FPS2 / 8 / 16 / 60 FPS 不改变行为 / 飞行结果；接触态展示一致；调参不重置个体。视觉采样频率反过来改变决策或动力。

验证分两步：实机访花观感已获用户认可；密集花簇 / 个体上限的 Release 性能验收仍单独进行。花源更新、候选查询、GPU 读回与 CPU 轨迹成本的有限场景测量见实现记录，不承诺“低频决策就一定便宜”，也不将视觉认可等同完整性能验收。

后续 Rust / shader 实现应执行 cargo fmt --check、cargo check、快且确定性的状态 / 身份 / 配置兼容测试、cargo build --release，以及 cargo run --release -- --hidden --mute --auto-exit 0.5 并检查日志。隐藏启动只验证运行安全，不证明访花观感；视觉批准与性能验收分别记录。

当前结论：

保留已认可的“真实花头之间飞行与停驻”，固定开启，不再保留访花 A/B 开关。后续按反馈再扩展学习、遮蔽与生态互动。
