DDGI / Continuous editing / Field notes 01

不是算得更快，
而是不再白等。

让已经算出的新光照，真正进入画面。
这次修复的核心，是持续编辑时的响应正确性，不是 FPS。

THE TAKEAWAY / 一句话结论

小幅调整生产策略，
消除明显的交互等待。

核心职责更清晰。新增复杂度主要在测试设施，让“版本在更新，光照却没动”不再轻易蒙混过关。

另一个长期收益：测试开始检查“光照真的变了吗”。
不再只看版本号和发布次数。真实 RGB、探针支持、开关灯响应与关灯残留，共同构成可被证伪的测试。

02

为什么能改善这么多？

因为消除的是“额外等待”，不是突然把同一份运算加速几十倍。原先的计算已经做了，但过滤策略把一部分新结果丢掉了。

BEFORE / 错误的保留

有新版本，未必有新光照。

编辑范围外，过滤器直接复制旧间接光。连续编辑又反复重启局部恢复，于是接收点一直不变，直到停手后才逐渐更新。

  1. 采样：新光照已经算出
  2. 过滤：范围外仍原样保留旧值
  3. 发布：完整场更新，部分光照却冻结
AFTER / 分开两类策略

算出的新光照，必须参与更新。

几何可见性仍可按局部范围保留。间接光则在整个场中吸收新采样，并按场的恢复轮次和历史权重进行替换或融合。

  1. 采样：沿用原来的射线预算
  2. 过滤：间接光在全场消费新结果
  3. 发布：仍只发布安全、完整的光照场

关键区别：“这里的几何没变”不能推出“这里收到的光没变”。远处开灯、开洞或反射路径变化，都可能影响这里。

03

复杂度：增加了，但要分清加在哪里。

A / PRODUCTION LOGIC

生产策略，小幅增加。

核心新增一个小的间接光历史策略函数。没有新增 DDGI 调度状态机、队列、场缓存或 GPU 同步等待，也没有放开不完整场的发布。

改职责，而不是堆调度机制。
B / VALIDATION

测试设施，增加较多。

主要增量是 GPU 读回、独立场景、分析器与负对照。正常游戏不执行诊断采样／读回，但会初始化少量诊断资源，也增加了维护成本。

用额外代码，换可靠的证据。
C / COMPUTE COST

过滤计算，略有增加。

不再丢掉新结果，所以需要真的过滤它们。本机 spacing 32 的采样均值约从 7–10 µs 增至 23–24 µs；射线预算没有增加。

响应改善，不是零成本提速。

总帧时的采样结果接近，但每个窗口只有约 9–10 个 GPU scope 样本，不能据此宣称所有场景性能完全不变。密集模式仍有约 1.37 秒的完整场等待，不是“即时更新”。

04

模块：核心职责比以前更清晰。

把两种不同的知识，
放回各自的策略里。

可见性策略回答：哪些几何信息可以保留？
间接光策略回答：怎样吸收新的光照？

过滤器负责执行，调度器负责安排工作与完整场发布。此次修复没有把光照判断塞进调度器，也没有在显示层补一个假亮度。

间接光策略接口不再接收“这个探针是否位于局部脏区”。从接口上，减少再次套用错误假设的机会。

策略
shader/slang/ddgi_filter_policy.slang

分别决定间接光与可见性的历史行为；可直接做确定性的逻辑测试。

观测
src/tracer/ddgi_response_sample.rs

走生产查询读取 GPU 值，并核对请求与接收点身份。

场景
environment_lighting_test_scene/
indirect_response.rs

驱动开灯、关灯和连续编辑，不等待 DDGI 就绪才编辑。

判断
scripts/check_ddgi_indirect_response.py

根据观测判断响应、稳定参考与残留；不介入渲染算法。

并非毫无接线成本：管线注册、资源初始化和读回时序仍要接入现有 Tracer。若未来继续增加类似诊断，应复用共同设施，而不是不断复制；目前没有为一次测量先搭一套庞大的通用框架。

05

哪些已经证明，哪些还没有。

这轮验证站得住的结论

  • 开灯和关灯都能在持续编辑期间响应。
  • 静态对照通过，GPU 全黑负对照被正确拒绝。
  • 关灯后的残留通过了固定场景的 5% 门槛。
  • 对照双方的稳定亮度参考相差不到 0.1%。
  • Rust、Slang、Python 测试与主要烟雾回归通过。

没有偷换成“已经完成”的部分

  • 首次跨过阈值，不等于完全收敛。
  • 单个接收点，不能代表整个场景的视觉质量。
  • 不再冻结历史后，场景起伏／闪烁仍需视觉检查。
  • 长时间编辑、多区域和其他硬件仍需继续验证。
  • 旧捕获模式的既有断言错误，没有被绕过。
展开：测量口径、已知问题与复现记录

怎么测：太阳与天空光关闭，固定接收点和法线；通过生产 DDGI 查询读取不含直接光、材质、曝光或显示变换的线性间接光。开灯、关灯之后各执行 40 次真实地形编辑，相邻至少 100 ms，不等待光照计算结束。

为什么不是凑出来的快：先修正了合法全黑光照场被拒绝的旧断言，再建立仪器化 baseline；两组使用相同的测试、配置与验收阈值。原始 baseline 为 4b8951aa，测量设施为 c5feaa94，间接光策略修复为 5c4ecf6a。

曲线来源：target/ddgi-response-loop/baseline32-run1/ 与 fixed32-final1/ 的真实 JSON 观测。每个完整场取首次有效值，并保留最后一个观测作为线条终点；只显示前 14 秒，按各自静态参考归一化。线条不向采样结束之后外推。数值为展示做了舍入，微小正数可能显示为零。

验证：1174 个主程序 + 4 个库测试通过，4 个忽略；21 个 Slang CPU 测试、84 个相关 Python 测试通过。启动、树测试加窗口缩放、连续地形／灯光交叉测试，以及静态 RFIRR 捕获通过。全局 pyright 不可用，未宣称类型检查通过。

已知 baseline 问题：旧的 terrain-edits-inflight-capture 在 e2 捕获时报 DDGI visibility sample evidence owner version is inconsistent。保存的 baseline 用相同命令也会报同样的错，因此完整旧捕获验收矩阵没有被标为通过。
