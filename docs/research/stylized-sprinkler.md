# 园艺喷水器：模型表面采样与连续水雾

## 目标与调研

喷水器使用圆润的园艺工具造型，并像苹果、蝴蝶和花头一样拥有独立的 **N×N 模型采样分辨率**。这不是全屏像素大小，也不只是离散相机角度。

一手来源：

- [共享模型几何](../../src/tracer/model_geometry.rs)、[表面缓存](../../src/tracer/model_surface_cache.rs)：CPU 按视角预烘焙占用、位置、法线和材质；运行时重建小面片，保留实时光照和深度。
- [场景像素采样契约](../scene-pixel-sampling.md)：模型表面采样之后仍经过统一的场景后处理，两层设置互不替代。
- [已有割草机](../../src/tracer/mower_resources.rs)：沿用鼠尾草绿、奶油色和暖色配件的工具配色。
- [Haws 官方材料说明](https://haws.co.uk/pages/choosing-the-perfect-metal-indoor-can-for-you)：涂漆钢、铜、黄铜及可拆喷头提供形态参考，不复制品牌或模型。
- [GARDENA 官方喷水器](https://www.gardena.com/int/products/watering/sprinklers/comfort-circular-sprinkler-vario/900967401.html)：借鉴低位稳定底座和清楚的出水结构，不照搬产品外观或灌溉参数。

造型和水雾仍是视觉候选，最终观感需要玩家确认。水雾目标是表现空气中悬浮的湿气，而不是能逐颗辨认的水珠或白色烟团。

## 原先的接线缺口

- **影响范围**：`73c64384` 实现了新模型，但喷水器仍走直接三角形路径，没有苹果／花头那样的对象采样控件。
- **根因**：误把复用全屏后处理当作复用对象级表面预缓存；没有注册缓存 kind，也没有把模型送入共享缓存绘制。
- **引入时间**：新园艺造型提交 `73c64384` 已存在这个范围遗漏；更早的方块喷水器本来也不在对象缓存中。
- **干净修复**：保留造型，接入现有几何、异步缓存、逐帧资源和绘制所有者；只增加喷水器自己的设置，不改场景像素参数。

## 当前实现

- [作者网格](../../src/tracer/sprinkler_mesh.rs)：卷边绿底座、奶油色柱身、黄铜套环、圆顶分水头、铜管、喷嘴内孔及顶部调节螺钉，约 1.3k 个三角形。
- [几何注册](../../src/tracer/model_geometry.rs)：按运动拆成六个刚性部件（固定底座、升降头、四根喷嘴），各自烘焙全部表面，避免把随后会露出的表面永久遮掉。六部分共用整件模型的取景中心、半径和网格尺寸；N 指整件喷水器的采样密度，不是每个小零件各自放大到 N。
- [缓存](../../src/tracer/model_surface_cache.rs)：喷水器是独立第五类，复用方向库和异步任务。修改喷水器分辨率只使这一类缓存失效；缓存未就绪或关闭时走同一模型的原生三角形回退。
- [顶点路径](../../shader/slang/sprinkler.vert.slang)：缓存及回退共享视角选择，部件升降和活动喷嘴伸缩实时计算；部件平移同时作用于缓存表面位置和面片投影。没有烘死动画或新增离线 RGB 贴图。
- [实例发布](../../src/tracer/sprinkler_resources.rs)：放置操作只暂存姿态，等待帧槽 fence 完成后才写对应 GPU 缓冲；逐帧描述符由共享模型绘制路径管理，避免删除／重放时覆盖飞行中的数据。
- [尺寸与姿态](../../src/sprinkler.rs)、[GPU 动画](../../shader/slang/sprinkler_animation.slang)：保留 tick、每实例相位和每秒交替一对喷嘴。CPU 浇水轴与 GPU 硬件动画保持姿态契约；视角量化和粗采样不会改变物理浇水范围。
- [浇水](../../src/app/core/placeables.rs)：`SprinklerMoistureSource` 独立提供灌溉，不再建立喷水器粒子发射器。关闭水雾或普通粒子不关闭浇水，也不改变其他粒子效果。
- 保留实时照明、阴影接收、编辑预览染色和场景深度。仍是 **Raster Consumer**：没有新增太阳投影、DDGI 遮挡或碰撞体。

## 连续水雾：替代可见水珠

- **影响范围**：旧喷水器喷雾能被看成独立水粒，尤其在近距离和场景像素化后；模型、放置及实际灌溉不是本次问题。
- **根因**：旧路径把湿空气表达为有尺寸、颜色和独立轮廓的 `WaterDroplet` 粒子。只改颜色或缩小粒子不能消除这种表现机制。
- **引入时间**：`73c64384`（2026-10-17）仍沿用并调整这条粒子路径；它不是首次引入粒子的证据，更早的引入提交未在本轮确认。
- **干净修复**：[局部介质积分](../../shader/slang/sprinkler_mist.comp.slang) 和 [光学数学](../../shader/slang/sprinkler_mist_math.slang) 在合成后、普通后处理前运行，复用硬件的逐帧实例缓冲，不增加第二份发射器登记表。

原版（取消方向性水雾 A/B）每个喷水器覆盖半径 0.28、垂向半径 0.105 的柔和椭球，近地面平滑淡出，整体随作者风场轻微偏移，密度只有缓慢的大尺度起伏。没有粒子、广告牌、高频随机亮点或浓烟纹理，也不随喷嘴换向突然消失。

沿相机射线先与介质相交，再被现有 raster／compute 场景深度裁剪；12 步积分复用太阳颜色、统一太阳阴影查询和 DDGI 环境光。归一化双瓣散射（60% 的 HG 前向瓣 g=0.65，加 40% 宽角度瓣）使逆光仍明显，同时保留普通侧光／顺光的湿空气线索；指数透射压低背景对比度，而不是叠加固定白色。不发光的黑暗环境不会出现自发白雾，零密度严格保留原画面并跳过该 pass。重叠体积以光学薄介质近似可交换地合并，避免实例顺序导致接缝。

边界：

- 水雾是连续的世界空间介质，不从模型缓存分辨率或 `scene_pixel_ratio` 推导密度／形状。与其他世界内容一样，最终画面仍经过统一场景采样和后处理。
- 读取第一层玻璃深度时只积分相机侧空气；不支持玻璃后方的折射水雾传输。本轮未做玻璃专门场景验收。
- 这是轻薄局部介质的单次散射近似，不是多次散射、完整光线追踪或影响 DDGI 的体积遮挡体。
- 不把视觉水雾作为浇水成功与否的判据；实际湿润刷仍由 gameplay 所有者提交。

## 游戏内控制

Debug → **Model Pixel Pre-cache**：

- **Sprinklers: use model pre-cache**：缓存开关；关闭使用原生三角形。
- **Sprinklers: pre-cache resolution (N x N)**：8–32，默认 32。降低会使喷水器明显粗粒化，细喷嘴可能只剩几个采样格。

Debug → **Mist & Scattering**：

- **Sprinklers: directional terrain-aware mist (A/B)**：默认勾选新方向性雾带；取消勾选回到原柔和椭球。保存并保留两种模式，方便玩家比较。
- **Sprinklers: mist optical density**：0–3，默认 1；0 只隐藏视觉水雾，3 用于检查较强效果。

Debug → **Soil Wetting**：

- **Sprinklers: coherent soil wetting (A/B)**：默认勾选柔边、片内相关的湿斑；取消勾选保留原来的独立体素受湿。
- **Sprinklers: wet patch scale (voxels)**：2–32，默认 12。调整局部相关尺度，不是固定斑块直径，也不增加喷水覆盖半径。
- **Sprinklers: wetting speed multiplier**：0–3，默认 1。单独调整实际浇水速度；0 停止喷水器灌溉，不关闭空中水雾或手动 Water 笔刷。

设置来自 `config/gui.toml` 的声明式字段，可随 Debug 设置保存；旧配置缺字段时补默认值，读取不写盘。不改苹果、蝴蝶、花头、工具袋的分辨率或 `scene_pixel_ratio`。花头保存尺寸仍为用户的 1.11。

### 探针层暗线修正

- **影响范围**：初始水雾在低角度观察、查询点经过 DDGI 探针层时可能出现细横向暗带；先前偏俯视／逆光的截图夹具没有覆盖这个边界。喷水器硬件和实际灌溉不受影响。
- **根因**：对相机射线中点做 +Y／-Y 两个表面光照查询，再平均，不等于体积光照。两个查询都以表面法线筛选探针；位于查询点水平面上的探针，两侧 alignment 都为零，因此都被排除。查询点穿过探针层时，环境散射可能突然丢失支持。关闭雾的太阳阴影查询仍复现；临时固定环境光后消失，排除了直接阴影积分本身。
- **引入时间**：`acd6af69`（2026-10-18）增加水雾时引入；不是旧模型或地形的缺陷。
- **干净修复**：DDGI 查询所有者新增 `sampleDdgiVolumeEnvironment`。空气查询不使用表面侧门限或法线偏移；用连续的名义三线性权重、同一份 probe metadata／矩可见性／支持度归一化，平均六轴 irradiance/pi 近似入射环境辐亮度。保留 ready、失效区、无可信探针时 fail-closed 的契约，不用固定白光、屏幕模糊或关阴影掩盖问题。表面调用者保留原有权重行为。
- **复现与回归**：自然起伏地形的 `mist-level`／`mist-level-off` 同视角相减，检测喷头上方的细横向亮度缺口。旧实现连续两次失败，缺口分别为 2.678／2.697 个显示亮度级、约 39%；修复后同一命令连续两次未再检出该条带。检测阈值为局部下降 >25% 且 >1.8 个亮度级，而非只检查退出码。新增 Slang 测试覆盖共面／上下探针的体积支持及旧表面权重兼容。
- 本修正通过 `cargo fmt --check`、`cargo check`、Release 构建、全量 Rust（1639 app + 4 collision + 1 integration）、40 个 Slang CPU 测试和 14 个隐藏静音 Release 场景的 Khronos 同步验证；图像暗线断言通过，配置／相机哈希不变。
- 原始复现、隔离探针和修正截图在 `target/sprinkler-mist-edge/`。临时常量光与取消阴影的 shader 探针已经移除；不是最终方案。

### 普通视角可读性调整

初始相函数 g=0.72 将绝大部分太阳散射集中在很窄的逆光方向；单纯增密会优先把这个峰值堆白，而普通视角仍缺少光照线索。当前改成归一化的前向／宽角度混合：增加侧光和顺光散射，同时压低正对太阳的峰值，不添加常量白光。单位长度消光系数由 1.0 调至 2.2，保存的密度仍为 1.0（范围 0–3）；缓慢大尺度密度变化增强，没有增加高频颗粒。

在固定顺光画面、同区域零密度对照中，显示 RGB 的平均绝对变化由约 11.14 提高到 17.82 个级别（该场景约 1.6 倍）。这只是本夹具的可见传递量，不等于所有视角都提高相同比例，也不是玩家外观认可。截图保存在 `target/sprinkler-mist-visibility/`。

光学测试继续检查能量归一、零光不发白、平滑边缘及稳定合成，并额外约束普通角度散射不再消失、逆光峰值不过强，以及默认密度的中央路径仍透过至少一半背景。新增 `mist-front-off` 配对截图；加强后的版本继续跑自然地形暗线回归，防止增密重新暴露同类条带。浇水、模型采样、其他粒子及用户保存的花头尺寸不变。

本版通过 `cargo fmt --check`、`cargo check`、全量 Rust（1639 app + 4 collision + 1 integration）、40 个 Slang CPU 测试、15 个 RTX 3060 Ti 隐藏静音 Release 场景的 Khronos 同步验证及图像暗线断言；重新 Release 构建和标准 0.5 秒 smoke 退出正常。保存文件哈希不变。最终观感仍需玩家确认，最大 256 实例性能验收仍未进行。

## 方向性雾带与地形交互（当前候选）

用户已反馈前版散射明显改善；本轮保留该散射，替换原椭球的形态模型。详见[方向性传播与低成本地形交互](sprinkler-mist-transport.md)的“已实现版本”。每个喷嘴的年轻雾保留外喷方向，换向保留旧雾；动量衰减后随风、沉降，宽度增大而浓度按体积降低。高处为弧段／非均匀环带，悬崖外能向下延伸，不再按基座高度整片截断。

4×12 个年龄区间在 GPU 上从同一姿态重建，复用真实已发布的体素几何做有界扫掠、切向接触及有限核的局部面裁剪。不是逐滴碰撞，也不做完整流体求解。新模式使用紧支撑核的解析射线积分、每核照明与屏幕 tile 剔除；原版仍由运行时 A/B 复选框保留。未知几何不作空地，正常路径不做 CPU／GPU 碰撞回读。

全量 Rust（1640 app + 4 collision + 1 integration）、41 个 Slang CPU 测试、增强后的 300 组姿态／出水口对照、Release 构建与 smoke 通过。21 次新传播、15 次光学、9 次模型／采样隐藏静音 Release 检查在 RTX 3060 Ti／X11 上通过 Khronos 同步验证；包括实际 GPU 悬崖下垂、单体素墙／墙角／悬空板阻挡、拆墙恢复、A/B、live resize、浇水独立和暗线／悬崖图像断言。配置和相机文件哈希不变，花头仍为 1.11。

当前仍是局部、保守的视觉地形交互，不宣称所有动态对象、细叶碰撞、精确绕流或玻璃后折射雾。实际外观待玩家确认。新增截图与报告：`target/sprinkler-mist-flow-review/`。

关闭验证层的独立 Release 初测及完整限制见[传播记录的性能一节](sprinkler-mist-transport.md#独立-release-性能初测2026-10-18)：RTX 3060 Ti，单实例新雾总计中位数约 0.34–0.35 ms，比同机位原椭球多约 0.19–0.20 ms；分散完整取景的 256 为 1.386 ms，但 256 个近景高度重叠为 25.802 ms（P95 40.357 ms），仍明显昂贵，**不宣称极端人口性能已接纳**。单实例与人口组分辨率不同，各组内部记录真实尺寸；整帧数字不等于雾的净开销。

另对分散／重叠两种 256 各跑 60 秒默认 Release Khronos 同步验证，实际缓存绘制／发布断言均为 256、无同步错误且正常退出，累计 47 次隐藏正确性检查。已恢复默认 Release 构建与标准 smoke，保存文件哈希不变；没有自动启动可见游戏。

## 连贯土壤湿斑（当前候选）

- **影响范围**：原喷水器的受湿区域由细碎、独立的体素变化组成；放大整体覆盖范围不能解决局部颗粒感。原灌溉半径 0.30（约 77 voxels）不变；空气水雾和模型采样不参与本次修改。
- **根因**：[原受湿刷](../../shader/slang/terrain_moisture_brush.slang)逐体素独立随机取整，再写入只有 0–3 的湿度状态。一级跳变因此可见；既有扩散调度只沿垂直方向，不能把表面散点自动连成湿斑。对最终颜色做模糊不会修复植物实际读到的湿度。
- **引入时间**：该机制在方向性水雾之前已存在，`ce99e136..b7938f33` 没有修改这些湿度核心文件；最早的行为引入提交未确认，不能归因于新水雾。
- **干净修复**：[受湿数学所有者](../../shader/slang/terrain_wetting.slang)生成世界空间连续的相关阈值，现有湿度刷仍负责真实土壤写入、近表面吸收、方向覆盖、湿度上限及保留材质/状态位。手动 Water 和未勾选的原版分支保留旧算法，不新增一套灌溉注册表或湿度存储。

设计契约：

1. 平滑插值局部独立高斯值，按插值权重的平方和恢复单位方差，再用正态 CDF 得到每个接收点边际均匀的阈值。每次剂量改变随机场，世界坐标保证跨 chunk/workgroup 连续，随机平移避免固定网格印记。不是插值均匀随机数，也不把斑块面积直接乘进水量。
2. 相关尺度只改变受湿位置的空间关联；剂量仍是原速度 × 独立速度倍率 × dt × 覆盖衰减 × 吸收率。截断到既有上限的 Poisson 增量使独立时间区间可组合，避免大 dt 的 Bernoulli 近似改变受湿分布；小剂量使用稳定的生存概率，避免浮点相消造成消失或异常 +3 跳变。
3. 保留四档湿度、原覆盖边界、环境干燥及垂直扩散，没有更换全局存储或增加横向流动。柔边来自连续场和受湿概率，不是新的连续色阶或最终图像模糊。扩大斑块保持**期望**水量，不承诺每一帧、每一次随机实现都写入完全相同的体素总量；大斑块的局部/整片波动会更明显。

[数学契约测试](../../shader/tests/terrain_wetting_contract.slang)覆盖 2/4/12/32 的边际水量、完整四档分布、空间连贯性、1/9/18/36/86 个时间区间、零/大/极小剂量。固定剂量 0.4 时，四种尺度的平均增量为 0.39691 / 0.40125 / 0.39764 / 0.39999，接近受上限影响后的理论值约 0.3992。

`--wet` 真实 GPU 夹具关闭草叶绘制以观察土壤，并只在专用夹具中关闭环境干燥/扩散；普通游戏仍保留它们。13 个场景覆盖原版、4/12/24 尺度、30/120 Hz 剂量分割、零/双倍速度、运行时控件、水雾开关、手动 Water/tiller、粒子关闭和 resize。每组从真实 atlas 读取 161×1×161 土壤切片，七次独立受湿实验之间仅清除采样层湿度，不改几何或其他状态位；最终截图显示最后一次真实状态，不是平均图。比较平均量采用配对实验的标准误差，而不是把一张随机图的差异误判成固定剂量偏差；数学测试另行约束边际无偏性。

最终通过 `cargo fmt --check`、`cargo check`、Release 构建、全量 Rust（1640 app + 4 collision + 1 integration，保留既有显式忽略）、42 个 Slang CPU 测试。RTX 3060 Ti / X11 的 **13 个土壤场景 + 21 个水雾回归**均完成 180 帧、Khronos 同步验证及正常退出；暗线/悬崖图像断言和标准隐藏静音 0.5 秒 smoke 通过。配置/相机哈希不变，花头尺寸仍为 1.11；生成文件仅包含新声明式 GUI 字段。

真实 GPU 七次实验的相邻湿度不一致率：原版 **45.09%**，4/12/24 尺度为 **20.75% / 7.72% / 4.97%**。相应平均湿度为 0.38794 / 0.37805 / 0.32770 / 0.44485，说明少量连贯斑块实验的整片均值确实会波动，不能宣称每次写入量完全相同。配对差异未超出预设的 `4 × 标准误差 + 0.02` 容限；边际期望另由上述 32768 次数学抽样约束。默认/30 Hz/120 Hz 分割为 0.32770 / 0.31625 / 0.32048，双倍速度为 0.68323，零速度为 0；这验证受湿剂量分割，不是宣称整套世界在任意帧率下逐体素一致。

已查看原版、12 和 24 尺度的实际土壤截图：细散点变成较大、相连的湿区，增大尺度后湿区进一步扩大；仍有体素轮廓和四档颜色，最终外观待玩家试用。对照裁图在 `target/sprinkler-wetting-review/comparison.png`；完整图像、逐次均值、湿度直方图和日志也在该目录，编译/数学/全量测试日志位于 `target/sprinkler-wetting/`。

一次启动曾在 90 MiB Contree 缓冲分配时报 GPU 内存不足，另一次并行 CPU 测试期间 6 秒夹具未完成；均未计作通过。未关闭其他应用，重新以足够时长运行后通过全部 34 项；显存失败的具体触发原因未确认，记录保存在 `target/sprinkler-wetting/startup-oom.log`。本轮不把正确性检查当作新版受湿的人口性能验收，也不消除上文已记录的极端水雾重叠开销。

## 复验

```sh
cargo fmt --check
cargo check
cargo test
cargo test sprinkler_shader_pose_matches_water_outlets -- --ignored --nocapture
python3 scripts/run_slang_tests.py
cargo build --release
cargo run --release -- --hidden --mute --auto-exit 0.5
node scripts/validate-sprinkler-model.mjs
node scripts/validate-sprinkler-model.mjs --mist
node scripts/validate-sprinkler-model.mjs --flow
node scripts/validate-sprinkler-model.mjs --wet
cargo run --release -- --tail-latest-log 25
```

脚本默认九场景：near、garden、orbit、lifecycle、near-dense、pixels-8/16/32、controls。
`--mist` 另选十五场景：逆光、顺光、零密度、镜头在雾内、墙体、夜晚、实时密度、关闭粒子、关闭 god rays、关闭阴影、resize、lifecycle，自然起伏地形的低角度开／关雾对照，以及顺光开／关雾对照。该组另需 ImageMagick（`magick`）做暗线图像断言。它强制启用 Khronos 同步验证，检查实际缓存绘制／回退、完整夹具、PNG、退出和保存文件哈希；水雾组另启隐藏 `--perf` 验证实际 GPU pass，但不是性能基准。用 `--help` 查看依赖及运行时长恢复方式。

手动体验用 `cargo run --release`，按 **X** 放置，再到上述 Debug 分组调节。不会自动启动可见游戏。
