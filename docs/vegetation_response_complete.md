# 完整附着植被惯性响应 C

2026-09-06，完整附着植被惯性响应 C。代码、GPU 回放和同条件性能验证完成；用户已运行游戏确认观感无问题，并要求将风响应及其保存的 GUI 参数一起提交推送。

用户保存的启动参数为：速度 ×3、阻尼 ×1、偏转增益 ×1、显示姿态 10 Hz，C 开启。下面的原候选默认值和性能数据保留各自验证时的参数，不冒充此保存配置的性能测量。Reset Inertia 仍恢复原候选默认 ×1.5/×1/×1/5 Hz；Original C Rhythm 仍恢复 ×1/×1/×1/5 Hz。

## 刚才体验了什么，现在覆盖什么

“改造”指惯性响应，不包括其他材质、碰撞、树龄、蝴蝶任务，也不意味着已证明更快。

| 真实类别 | 刚才的草花 C | 当前完整 C |
| --- | --- | --- |
| 普通高草、矮草 | 共享草响应 map | 保持草 map，进入统一求解/滑杆 |
| Lavender | 独立植株 C | 独立生命周期状态，统一求解 |
| `ember_bloom`，GUI 名 Purple Allium | 独立植株 C | 同上 |
| Kochia | 独立植株 C | 同上，保留自身响应参数及形态 |
| 其他特殊植物 | 当前没有其他已注册种类 | 注册表是 2 类草 + 上述 3 类特殊植物 |
| 挂树叶 | 旧直接风 + 解析 paddling | 独立树叶响应 map；近/远景和照明缓存接入 |
| 挂树苹果 | 旧解析角摆 | 独立果实响应 map，结果转换为悬挂角摆；近/远景接入 |
| 树叶/苹果阴影代理 | 旧风动 | 对应类别的同一响应采样及形变，保留原代理/阴影历史策略 |

| 已脱落叶、已脱落苹果 | 自由飞行/碰撞物理 | 不适用附着场，不替换已有物理语义 |

证据入口：`src/flora/species.rs`，`flora_vertex.slang`，`vegetation_response_sample.slang`，`leaves_shadow.vert.slang`，`src/tracer/mod.rs`。正常启动仍通过 `flora_inertial_response` 开关进入 C。

## 同一求解，不同状态和形变

`shader/slang/vegetation_response_solver.slang` 是唯一的惯性积分实现。生产 compute pass 和 GPU 验证均调用它；没有另一份 CPU 风响应积分器。

方程为 `q'' + 2 ζω q' + ω² q = ω² gain × wind`，使用恒定输入的解析阻尼振子步进。网格节点和独立对象都保存连续响应/速度以及四份已发布姿态/对应速度；每份状态 80 字节。内部通常以不超过 1/120 秒采样风，显示刻意保持离散，不在两个姿态间插帧。

| 类别 | 基础频率 Hz | 基础阻尼比 | 状态归属 |
| --- | ---: | ---: | --- |
| 高/矮草 | 1.00 | 0.24 | 草 map |
| Lavender | 0.65 | 0.30 | 逐株 |
| Purple Allium | 0.52 | 0.34 | 逐株 |
| Kochia | 0.85 | 0.40 | 逐株 |
| 挂树叶 | 1.40 | 0.28 | 树叶 map |
| 挂树苹果 | 0.75 | 0.45 | 苹果 map |

这些是有效机械响应参数，不声称测量了真实植物质量。全局倍率保留类别差异。

当前 GPU 权威 `sampleProceduralWind` 只读取世界 XZ，不使用 Y，因此三张独立 XZ 场有依据：同样风输入，不同最终运动历史。每张场覆盖完整 512×512-voxel 世界，间距 16 voxels、33×33 节点。树叶按叶片实际世界 XZ 采样，再按离附着点的权重形变；不是每个渲染顶点一份状态。若未来风随高度、遮蔽或局部窄风源变化，需重新评估这个假设，不能声称当前场支持这些情况。

树增删和树龄重建不拥有或回收环境场状态，不会误用某片被删除叶的历史；重新出现的组织采样当前环境响应。特殊植物仍按独立 lifetime ID 迁移，删除/同位置重种不继承旧对象速度。固定世界之外/无限流式世界未验收。

苹果没有强塞成草的平移。共同求解的广义响应经过 `appleInertialOffset` 转成有最大角度、固定悬挂长度的角摆；沿用已有悬挂长度和最大角度。全局结果周期与离散 voxel 半径保持独立。

落果时只在事件上读回苹果场的最后已发布位置和相应速度，再建立碰撞刚体；CPU 只做空间采样/悬挂几何转换，不重新积分风。17 个苹果一次读回 87,120 字节，实测约 1.7–1.8 ms（另一次 2.45 ms）；同步读回可能等待 GPU，不是逐帧成本。大量高频落果事件的尾延迟仍需进一步测试。再次结果/同位置新果实采样环境场，不复用旧刚体；掉落后由既有物理负责，玩家/苹果过滤关系未更改。

旧振动、paddling、苹果解析摆动只保留在关闭 C 或专门旧路径对照中，不叠加到 C 的最终运动。

## 慢、顿：测得事实与仍需人工判断的部分

实际生产 GPU 回放：单位风力阶跃、停风、快速反向、改控制值、改发布频率并读回状态。约一秒量级运行；断言能抓漏发布、无回弹、错误衰减、轨迹被显示频率改变、改参数重置状态等问题。它不能自动判断“观感令人满意”。

固定 60 Hz 回放中，原节奏同一桶每 12 帧更新，即每个对象 **0.20 秒一个姿态/5 Hz**，没有检测到漏更新。原基础机械响应达到 90% 阶跃偏移：

| 类别 | 原速度 ×1 | 候选速度 ×1.5 |
| --- | ---: | ---: |
| 草 | 0.283 s | 0.183 s |
| Lavender | 0.450 s | 0.300 s |
| Purple Allium | 0.567 s | 0.383 s |
| Kochia | 0.367 s | 0.250 s |
| 新树叶类 | 0.217 s | 0.150 s |
| 新苹果类 | 0.433 s | 0.300 s |

检查顺序及预测：机械速度提高应缩短受力后的反应时间；显示发布频率提高只应缩短姿态保持时间；如果是真实帧耗时卡顿，Release 整帧计时应出现长帧。前两项单变量实测符合预测，机械轨迹在 2.5/5/10 Hz 对照中一致（原回放精度内最大差 0）。阻尼 ×2 减少全部类别的超调，增益 ×2 线性放大响应而不改变到达比例目标的时间。改值但 dt=0 时全部 GPU 状态逐位不变。实际 GUI 配置快照也记录了 `[1.2,1.3,0.8] / 8 Hz` 生效，恢复后 reset_count 仍为 1。

因此本轮先把回摆速度默认设为 **1.5 倍**，仍保留 **5 Hz** 的故意离散美术，不修改全局 World Tick，不增加噪声/解析摆动掩盖问题。该默认不是“主观顿感已解决”的结论。建议用户先用原节奏按钮对照速度，再仅把姿态频率调至 8 或 10 观察。机械频率控制受力/余摆响应，**不会凭空改变风源的阵风变化频率**；原风输入保持不变，未将风源变化归因为已定位的 bug。

本轮 Release 固定场景的最大 CPU 帧约 15 ms、最大 GPU 帧约 4.43 ms，不支持该场景存在 0.20 秒真实性能停顿。但先前交互运行是 debug、不同显示分辨率且未开逐帧性能记录；不能据此排除它在编辑、加载或其他工作负载下的卡顿。

## GUI

位置：Debug → **Attached Vegetation Inertia (C)**，关闭为原风动视觉对照。对照开关仍后台推进 C，以保证再开启连续；它不是性能基线开关。

| 控件 | 原候选默认 / 范围 | 含义 |
| --- | --- | --- |
| Inertia: Return Speed (x) | 1.5 / 0.25–3 | 所有类别基础频率倍率 |
| Inertia: Oscillation Decay (x) | 1 / 0.25–2 | 阻尼倍率；越高回摆衰减越强，并非直接“空气阻力” |
| Inertia: Wind Deflection (x) | 1 / 0–3 | 风力目标增益；苹果经有界角摆映射，不是任意放大半径 |
| Inertia: Discrete Poses / Second | 5 / 2.5–20 | 独立显示节奏，不改变积分时钟或生长系统 |

**Reset Inertia** 恢复上述默认；**Original C Rhythm** 恢复 ×1/×1/×1/5 Hz。按钮仅调这四项，不动风源、树形、材质或相机。频率/阻尼在求解入口有数值界限；高机械频率配很低的姿态频率仍可能有刻意的离散/混叠观感，应由用户选择。旧模式不使用这些新滑杆。

## 同条件性能：九次独立进程

RTX 3060 Ti，驱动 580.159.04，Release，hidden/mute，1600×1000，自动 MAILBOX；固定相机、风、1/60 秒模拟步。高草 9,541、矮草 7,873、三种特殊植物各 20、树叶 14,572、挂树苹果 17。背景仍有地形、DDGI、阴影、湿度等真实系统；关闭自由粒子作为所有模式共同条件。不包含编辑期或大批落果尾延迟。

每次预热 600 帧，随后 2,000 帧；明确排除区段前 8 帧以隔离在途查询，每次 **1,992 帧**，每模式 3 次即 **5,976** 个有效 CPU/GPU 帧。顺序为 all/surface/legacy、legacy/surface/all、surface/all/legacy。三种模式参数均固定 ×1/×1/×1/5 Hz，隔离覆盖范围成本；不是候选默认 ×1.5 的整场景性能证明。

- **legacy**：不运行新 solver、不整理逐株状态、不分配完整状态场；旧风动分支实际执行。仍有共用管线/分支、CPU 空网格预留及 224 字节 GPU 描述兼容缓冲，不是完整零开销的旧二进制。
- **surface**：复现刚体验的草花 C 行为（单草场 + 独立花，树叶/苹果旧运动），使用同一份统一求解/渲染管线。不是上次二进制逐位复刻，因此控制参数/兼容分支开销仍在。
- **all**：三场 + 独立花，全部附着风动 C。

以下为全部有效样本**均值**；CPU frame 是整帧墙钟时间（含等待），不等于纯 CPU 忙时。render.record 是 CPU 记录渲染工作的时间。
