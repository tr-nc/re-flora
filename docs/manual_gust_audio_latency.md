# 手动风树声延迟复查（2026-09-13）

## 已确认并修复的错误

`CanopyAudioVoice::sampled_response` 原先先平均所有树冠采样点的风强，再执行 Min/Max 曲线。
这会让局部风等到整棵树平均风强越过 Min 才能发声。现在对每个采样点执行曲线，再按原权重汇总；仍使用同一个共享风场、树冠描述和声音实例，不增加生成器或绕过风传播。

回归：同一非均匀风场中，两片叶子的平均归一化风强为 0.375，Min 为 0.4；其中一片已经超过 Min，旧实现却返回零。
`cargo test canopy_response_samples_the_shared_field` 修改前失败、修改后通过。原 Min=0/Max=1 的线性默认映射不变，静风保持无声。

## 不能再仅用平滑解释全部迟缓

确定性回放使用试玩日志里的手势起点 `(0.82689226, 0.42759848, 0.7031249)`、方向 `(0.6090692, 0.79311705)`、速度 `108.042145 vox/s`，其余风阵形状为默认值。树冠为测试拥有的两片叶子，**不是用户场景的完整重放**。

`cargo test manual_gust_replay_reports -- --nocapture`：

- 局部叶子过 Min=0.135：释放后 1.183333 秒。
- 旧整树平均值过阈值：1.250000 秒。
- 修复后音量目标首次非零：1.183333 秒，同一次更新。

在这个案例里额外阈值错误贡献约 67 ms；前面的 1.18 秒属于风源渐入、空间传播、积分及阈值，不能声称本次修复消除了全部迟缓。

## 仍保留的机制

- 默认 3 秒风阵的源包络用前 15% 渐入，约 0.45 秒；不是按下工具时直接覆盖树冠风强。
- 风阵在释放手势后才真正发出，随后进入共享传输场。
- 用户 Min=0.135 对应局部风强超过 1.08 才开始响；视觉叶片在更弱的风下已经会响应。
- Fast=1 仍是 8/s 指数响应：125 ms 到达阶跃目标的 63%，375 ms 到达 95%，不是即时响应。

本次只修局部阈值聚合错误，没有擅自改变用户阈值、放大风强、删除传播或改成即时音量。若要求释放时就明显发声，需要明确调整风阵注入/渐入或音频响应标定，不能靠这次 bug 修复承诺即时反馈。
