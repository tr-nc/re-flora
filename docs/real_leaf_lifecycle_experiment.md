实现位于 `pretty-leaves`，现已合入 `main` 的 `6522e8d1`，恢复其体素派生树干与树上体素叶显示。连续树干、树干像素化、树上模型叶/旋转比较及模型表面缓存/通用 GPU 分页实验已退出当前路径，完整历史保留于 `archive/pretty-leaves-experiments-ae8cdf21`。详见[迁移与验证记录](evidence/pretty-leaves-retirement.md)。

规则来自 [风致脱落调研与设计讨论](research/wind_leaf_detachment.md)。用户已确认：**足够强、足够持久的风允许把树吹秃，不加最低保叶量、概率豁免或发射限流来避免此事。**

外观切换作用于已有及新落叶，不重置冠层、再生时钟、来源身份或飞行物理。

以下 A/B 说明及测量是原实验的历史记录，不代表当前仍可切换生命周期。

## 使用与模式语义（历史）

Debug → **Falling Leaves** → **Real Detachment + Regrowth (B; Unchecked = Original)**，默认关闭。

- A：现有叶簇装饰性发射器，树上原叶不减少。旧 sprite/shared-model 和 display size 设置保留。
- B：停用装饰性叶发射器。每个实际可见叶体素是一片叶子，附着叶移除和对应落叶诞生一起发布。落叶保留源体素几何、颜色、尺寸和发布姿态；不使用装饰叶的 4 倍显示放大或独立 3D 叶模型。
- 两个方向切换均清理落叶、重置叶位，不清除蝴蝶、水滴、地形采收等其他粒子。B 再次进入从确定性完整冠层开始；退出恢复 A。
- 开关和四个参数由 `config/gui.toml` 声明，可用统一 Save 保存。**冠层生命周期仅保留在当前运行期**，未加入存档或离线生长。B 的参数只在 B 开启时可编辑，旧装饰外观参数仅在 A 可编辑。
- 世界更新暂停、叶子隐藏或粒子模拟停用时，不推进 B；模式复位仍可用。树的几何/拓扑替换为该树重新建立叶位，旧落叶继续自己的飞行；删除树不会召回已脱落的叶子。

参数（初始视觉候选，不是生物学标定）：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| Connection Strength Multiplier | 1 | 连接强度整体倍率，不是落叶速率 |
| Connection Weakening Half-life | 120 s | 成熟后向正的强度下限缓慢弱化 |
| Empty Socket Recovery | 8 s | 脱落后重新开始长叶的等待，个体有稳定差异 |
| New Leaf Growth | 20 s | 小叶逐渐长大所需时间，个体有稳定差异 |

## 生命周期与所有权

- `src/leaf_lifecycle.rs`：不依赖 GPU、App 或粒子的规则模块。每代叶子有 `(tree, topology, socket, generation)` 身份；该身份随交接保留在落叶粒子中，粒子槽位复用会清除旧来源。每代固定的初始连接强度由稳定种子产生。`plan` 只读，交接成功后才 `commit`，拒绝重复/过时代数。
- 瞬时指标为局部风向量模长平方乘生长面积 `growth²`。连接强度为 `multiplier * [0.09 + (initial_strength - 0.09) * 2^(-mature_age/half_life)]`。正下限只保证完全静风不会自行脱落，并不是保叶机制；大风可立即吹掉全部叶子。
- 叶位经历有叶→空置→长叶；旧落叶在独立的粒子生命周期中飞行/消亡。补叶不等待旧落叶消失；新一代重新赋予连接强度。
- `src/app/core/vegetation/leaf_lifecycle.rs` 是发布 owner。它收集当前树的脱落请求，预留整个粒子批次，批量交接源姿态，再提交缺叶和再生状态。没有累计落叶数量、每帧抽签或分帧延后脱落。

## 交接、渲染和消费者

`src/tracer/leaf_handoff.rs` / `shader/slang/leaf_handoff.comp.slang` 通过共享的挂树顶点函数，从上次已发布 GPU 风响应与树姿态获取实际位置、光学法线、底色、尺寸、几何旋转及运动。一次脱落批次只有一次同步交接，而非每片一次 GPU 等待。刚创建但尚未发布的叶拓扑，先正常发布后才允许转移，避免使用不存在/错误代数的 GPU 状态。

真实落叶仍使用已有的耦合落叶飞行模型，但初始化不再随机创造位置/姿态。额外的几何旋转保留源 cube；光学与几何随同一飞行旋转演进。装饰 sprite 和其他粒子路径保持原行为。

- 可见叶实例仍为 **8 bytes**。占用/生长在独立的 4-byte/slot 流中，主视图与 LOD 读取同一事实，不因每片脱落重建整棵树。
- 阴影代理使用存活成员面积/响应；空代理不再投影。部分缺叶仍是现有粗代理的面积近似，不是重新构建逐片精确阴影。
- 生态供给为可用活叶数，新出生候选从活叶索引选择；已有栖息对象按稳定 slot 验证，空叶位不能继续作为宿主。再生代数进入 token，旧宿主身份不能误认新叶。
- 树叶沙沙声的功率按活叶面积比例缩放，并与原树代际 crossfade 相乘；秃树没有叶片功率。声源空间布局仍使用原有冠层采样，没有逐片重建声场。
- 共享 CPU 粒子存储及渲染实例缓冲按真实批量需求扩展；超过旧 16,384 容量不会静默丢叶。内存仍有限，不承诺任意规模可实时运行。
- 叶状态和普通/透明/真实叶粒子实例使用已取得 fence 的 frame-slot 缓冲发布，避免新增的每帧变化覆盖在飞 draw 的存储。装饰模型叶/蝴蝶的按需输入仍由 main 的 `ModelPixelFrame` 拥有；计算/绘制成对发布，同帧按 tile 存储量与 Z-dispatch 限制分批，不恢复缓存/分页协议。
- 旧 main 设置补齐生命周期控件；实验设置移除已退出的显示控件，并保留风、生命周期与落叶外观参数。迁移不自动写盘，统一 Save 可往返保存。

## 验证

运行：

```sh
cargo fmt --check
cargo check
cargo test
cargo run --release -- --hidden --mute --auto-exit 0.5
scripts/check_real_leaf_lifecycle.sh
```

脚本以 `RE_FLORA_REAL_LEAVES_VALIDATE=1` 启用有界 app replay，再检查同 worktree 的 `--latest-log`：

1. 正常发布初始树；开启 GUI 对应的 B 设置。
2. 给生命周期与挂树 GPU 响应输入同一个恒定强风场，首个可交接帧全部脱落。此 fixture 同样拥有测试场景，自动藤蔓演示不会修改其地形或相机。
3. 静风下加速生命周期时钟，验证经历渐长而非瞬间弹回。
4. 第二阵同等强风吹掉完整新一代，同时保留上一代落叶，覆盖扩容路径。
5. B→A→B→A，检查源叶占用、生态数量、GPU 状态缓冲和无关粒子保留。

这是确定性正确性 fixture，**不是自然风表现或帧率基准**。GPU 状态检查是读取实际发布的占用缓冲，并经过真实 draw；未声称做了图像像素对比。

已运行结果：

- `cargo fmt --check`、`cargo check` 通过。
- 合并后的 `cargo test`：主程序 **1224 passed / 4 ignored**，collision bench **4 passed**。包含人工/自然风通过实际 `WindField` 传播后首个局部阈值帧触发、无风不脱落、不同连接强度、弱化、再生代数、过期事件、源姿态/外观传递、容量扩展、无关粒子隔离和配置保存。
- 隐藏 Release A smoke 正常退出；B replay：**14,572 sockets → 0 attached → 14,572 regrown → 0 attached**；两代 **29,144** 个真实落叶，粒子容量扩至 **32,768**。
- 合并后日志 `target/re-flora-logs/re-flora-20260927-161623.508-910012.log`：`[LEAF_LIFECYCLE][VALIDATE] PASS`、`[SHUTDOWN] phase=complete failures=0`，无 ERROR/panic/VUID。
- main 原有严格落叶 RGBA/覆盖/深度 oracle、苹果 stage-one、蝴蝶 oracle、体素派生树/resize smoke 均通过；没有放宽诊断阈值。
- 未自动启动可见游戏；手动视觉体验与听感尚未验收。

## 测量与已知范围

以下是生命周期最初实现阶段（本次合并前）的历史测量，不是此次合并的性能结论：Release replay 中，14,572 片同时脱落的两次批量交接为 **9.425 / 5.334 ms**；CPU 判定为 **0.704 / 0.577 ms**；整个生命周期更新（含交接及第二次扩容）为 **11.449 / 9.593 ms**。较早一次同样的 replay 交接为 6.479 / 5.742 ms，显示同步等待时长会随运行状态波动。这是特定树、机器和极端同步脱落下的实测事件耗时，**不是全场景帧耗时、A/B 性能回退结论或 Release 性能验收**。可见效果先供用户比较，后续根据实际场景再优化。

目前阈值判定在 CPU，采样每片可见叶体素的 **rest root**，与已有挂树风响应采用相同采样坐标，不是旧叶簇中心。物理交接使用实际已发布姿态，但尚未将判定升级为随叶子/树枝位移后的瞬时空间采样；现有风场本身仍为 32×32 水平场，无逐叶遮风。当前实现不声称完整植物气动或生理模型。大规模 CPU 遍历、同步 GPU 交接以及大量空叶位仍参与风响应/绘制调度，是后续可在模块内替换的优化点；不会用保叶上限或延迟队列掩盖它们。
