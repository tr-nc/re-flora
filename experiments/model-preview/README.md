# Re:Flora 模型像素化预览台

这是持续维护的美术预览工具，不是一次性原型。目录位于既有 `experiments/` 工作区内，以复用本地资源和启动方式。**唯一的新模型接入点是 `models/index.js`，不要再复制一个 HTML demo。**

## 启动

仓库根目录：

```sh
node scripts/serve-model-preview.mjs
```

打开 <http://127.0.0.1:8765/model-preview/>。

- 落叶：`?model=leaf`
- 蝴蝶：`?model=butterfly`
- 苹果（网页红苹果／青苹果配色；红苹果造型可在游戏 Debug 中 A/B 切换）：`?model=apple`
- 游戏共用花草（8 种）：`?model=wild-geranium`、`forget-me-not`、`oxeye-daisy`、`cosmos`、`corn-poppy`、`bellflower`、`coneflower`、`tulip`；顶部下拉框均可选择。
- **仅网页花草（2 种）**：白花老鹳草 `?model=white-geranium`、星草莓（白色草莓花）`?model=star-strawberry`。前者复用老鹳草造型、采用白瓣淡粉瓣根；后者有五片圆白瓣、黄色花心／雄蕊和三出锯齿叶。均支持花头像素化、造型参数和茎部 A/B，未加入游戏或正式资产。
- 布局：`&variant=compare` / `model` / `pixel`

原有游戏共用花草的名称、在线参考与设计见 [8 种花草调研](../../docs/research/stylized-flower-model-study.md)。它们使用原创参数化低模，不下载第三方模型；同一配方现已发布为游戏资产，8 种均可通过第二个物品栏 Grow／种植工具（快捷键 2）右侧可滚动的 Plant Brush 植物栏选择并种植。游戏集成的历史 A/B、实拍与验证见该调研文档的原生集成章节；当前已固定仅花头像素化。

统一工具不使用界面版本编号，也不保留带编号的旧比较页面。`/leaf-prototype/` 与 `/butterfly-method-comparison/` 这两个不带编号的书签入口仍会跳转到对应模型。旧查看器、历史边框实验和旧验证脚本均从当前树移除；历史源在提交 `86b4b81c`。已批准模型资源的内部路径不改动。

需要支持 WebGL 2 的浏览器及 Node 24；不要使用 `file://`。运行无需 npm 安装或构建步骤。服务只监听本机，既提供预览目录，也提供 `assets/models/` 中的正式游戏资源；不再只服务 `experiments/`。Three.js 0.183.0 与许可证继续使用本地 vendor。

苹果从 `assets/models/apple-source.mjs` 共用造型配方；`node scripts/publish-apple-model.mjs` 发布游戏渲染数据 `apple-preview.json`。游戏 Debug → Flora → Apple Appearance (A/B) 未勾选时仍用原始体素苹果，勾选时树上和掉落的苹果都使用固定 N×N 像素绘制的新造型／红色配色，`Pixels per New Apple` 可独立调整 8–64（默认 32），不改变蝴蝶或落叶分辨率。青苹果及网页颜色拾取器仍仅用于网页预览，碰撞和落地物理继续使用原始体素形状。蝴蝶的游戏与网页直接读取同一份 `assets/models/butterfly.glb`；叶片预览读取 `assets/models/leaf.glb`，游戏落叶另从同一 `leaf-source.mjs` 配方生成的 `leaf-variants.glb` 中按每片落叶的稳定种子选择形态（64 个变体，不改物理飞行）。叶片造型滑杆只是临时预览，正式造型从唯一制作配方发布；`cargo check` 会拒绝过期产物。共享接口、发布步骤、游戏 A/B 和跨运行时顶点对照见 [正式模型资源](../../assets/models/README.md)。

## 使用

- 顶部选择模型；两个画布同步观察方向、均可拖动和方向键旋转。仅左侧原始模型可滚轮缩放／透视推拉，用于检查细节；右侧始终按各模型声明的固定范围取景，不继承左侧缩放（蝴蝶／落叶为 3.4 单位，花草整株为 3.7 单位）。支持正交/透视、正背侧视角、原始线框和独立的相机转台。
- 左侧保留模型原始材质；通常右侧是真正的 8–128 像素边长缓冲，最近邻放大。花草的合成尺寸见下文。右侧固定取景范围不随左侧缩放或动画姿态重新适配，避免像素尺度变化；这对齐游戏模型瓦片的几何取景比例，不代表浏览器可以复现游戏里的世界距离、光照和最终屏幕尺寸。
- 动画统一支持片段选择、播放/暂停、相位拖动、前后逐帧、2–60 FPS 姿态采样与播放速度。左右总是同一采样时刻。模型切换后默认暂停，方便比较。无动画模型的时间轴禁用、采样时间固定为 0。
- **通用保守覆盖（关闭 = 旧八邻接补点）**复选框用于实时 A/B，默认勾选。勾选时，对所有投影三角形保守覆盖，再做几何约束的八邻接连接；不勾选时，仍做原有八邻接连接，但不补完全漏采样的几何。两个模式均不覆盖原有中心采样 RGBA。颜色量化暂不使用：叶片光照连续计算，不再有色阶滑杆或额外的基色采样 pass。
- 保守覆盖可以让细部稍厚，保护漏采样的叶柄、叶尖和翼缘；状态区区分几何覆盖与连接补点，并显示覆盖前后的八邻接区域数。某处原本已连通仍可能因其轮廓未采样而增加像素。
- 模型专属控制：叶子的宽度、长度（0.65～1.2 倍）、最宽处位置（0 靠叶柄、1 靠叶尖）、主脉折起、叶尖卷曲（-1.8～1.8；卷起时缩短 Y 投影，不拉长主脉）、叶面／叶脉／叶柄／叶背的独立颜色与透光；蝴蝶的统一翼色及光照/自阴影。叶脉使用颜色选择器，不再提供强度滑杆。五种叶片配色预设一次覆盖四个颜色，不改变形状、透光等参数；也可继续用 HSV/HEX 自定义。
- PNG 导出保存当前原生 RGBA 像素，不含背景/UI；文件名标记模型、覆盖模式（`coverage` 或 `bridge-only`）、分辨率和动画采样时刻。花草额外标记 `heads-512px-composite`，表示花头与低模茎叶的透明合成。
- 参数只在当前页面内存中，不提供 JSON 导入／导出，也不自动同步游戏配置。发布后的默认叶片造型会同步游戏；覆盖模式复选框、颜色选择器与配色预设目前仅属于网页预览，游戏仍固定使用通用保守覆盖及自己的调色／光照。

## 花草：仅花头像素化

网页和游戏均固定仅花头像素化，不再提供整株 / 花头范围 A/B。保守覆盖复选框独立保留。

- 每个完整花冠＋花心＋花萼各自进入 N×N，而不是每瓣一张图；茎叶保持原低模。右侧为固定 **512×512 透明合成**，花头最近邻采样，按原锚点接茎。
- 每个花头采用固定世界包围球裁切同一相机的投影；不另建朝向花心的相机，透视不产生视差。裁切只改变投影 X/Y，中心样本携带实际 GPU 深度，保守新增像素用既有投影几何深度，合成时逐像素深度测试，避免花头总盖住前方茎叶／另一朵花。
- N 是每朵花头的像素预算。形状编辑会更新花头范围，旋转／左侧检查缩放不会逐帧按轮廓自动撑满。
- 每种模型有花茎高度、花头大小、起伏／下垂／张开、仰角、叶大小、弯茎和五个颜色控制。全是本会话临时预览设置；切换模型／恢复默认值也始终只处理花头。花草静态无伪造动画，转台仍可用。
- 网页在浏览器中合成；游戏用同一发布几何原生绘制茎叶，并复用游戏像素管线绘制完整花头。游戏 Debug → Flora → Ground Plants → Model Flowers 保留分辨率与造型控制；旧存档的范围开关不再生效。32px 时保守覆盖仍会加粗／合并很窄的瓣间缝；未为花草改动补点算法。真实游戏视觉与大量实例性能仍需分开验收。

## 茎和分枝颗粒 A/B（仅网页）

花草的「模型参数」中提供 **颗粒茎和分枝 · B（关闭 = 原低模 A）**，默认关闭。

- A 保留原始连续低模；B 将同一制作配方中的茎、分枝和叶柄转换为真实三维方块，只输出外露面。不是给整株做低分辨率投影，也不是屏幕像素滤镜。
- 方块**边长为游戏草颗粒的 1/2、体积为 1/8**。游戏草边长为 `1/256` 世界单位，花草制作单位映射为 `10/256`，因此网页方块边长为 `0.05` 制作单位；不缩小整株模型。网格固定在植株根部，不随相机重采样。
- **叶片、完整花头（包括花萼）、花头锚点及其像素预算均不变**。茎的颜色仍由原控制调节；高度、弯曲等控制在两种模式中都有效。两种模式都使用现有共享深度合成，近处茎可遮住花头。
- 拖动两侧旋转；左侧滚轮放大检查三维方块，可切换透视。A/B 改变左右两侧的茎形态，右侧仍是花头像素化 + 三维茎叶。恢复默认或切换植物回到 A。
- 这是**不保存的网页美术实验**，尚未改变游戏；材质和灯光沿用网页预览，不声称复现游戏草的光照、风动或 LOD。保守体素覆盖会使细茎比原低模更粗，远处亚像素颗粒仍可能闪烁，先比较观感。

### 新模型的接口

在 `models/` 提供一个定义，注册到 `models/index.js`。定义包含：

- `id` / `label`：稳定 ID 与显示名。
- `defaults` / `controls`：专属参数与声明式控件（数值范围/步长、复选框、颜色）。所有可编辑控件必须对应默认值；`type: 'note'` 为只读说明，不产生设置字段。
- `preview`：默认 `resolution`、`background`。
- `async create()`：返回下面的模型对象。加载失败必须释放自己已建立的资源；切换竞态中的过期加载由 viewer 释放。

模型对象包含：

- `scene`、`meshes`：模型及其光源；meshes 不含辅助线框或背景。
- `view: {span,target,offset,axisDistance?,near?,far?}`：固定观察范围、默认目标与相机偏移。
- `clips: [{name,duration}]`：任意数量动画；静态模型为空数组。
- `apply(settings)`：应用专属设置，不触及相机或渲染循环。
- `sample(time,clipIndex)`：取当前姿态；必须可以直接跳到任意时间，而非仅增量推进。
- `preparePass('source'|'pixel')`：可选材质行为通过这个固定接口实现。所有模型都提供该方法；不需要差异时为空操作。
- `shadows`：是否启用场景阴影。
- `repairGroups: [{id,label,meshes}]`：明确允许修复连接的几何组，ID 为非零 RGB 整数、不能重复。未支持修复的模型可返回空数组。一个 mesh 只能属于一个组；本工具所有模型都满足此约束。
- `pixelParts?: [{id,label,meshes,center,span,anchor}]`：当前仅静态、不透明、双面花卉使用。每个完整花头对应一个同 ID 的 `repairGroup`；`center` 为世界坐标 `Vector3`，`span` 为旋转安全的固定包围球直径（含余量），造型编辑后更新。未列入任何 part 的网格按连续低模合成，不自行建 renderer。`anchor` 记录建模连接点，不是另一个可独立移动的姿态权威。
- `description`、`dispose()`：状态说明及完整资源清理。

模型只能提供资源/姿态/材质，不能自己创建 renderer、OrbitControls、requestAnimationFrame 或像素处理分支。需要新后处理时只改共享管线。

### 修复分组与颜色

- 叶片与叶柄是一组；蝴蝶左右翼是两个独立组，不通过全局连通性把两翼强行缝起来。
- 几何支持改为动态多字位集，不再限制 32 个三角形；当前蝴蝶实际为 156 面。每个候选步仍需共同的源三角形支持。
- 使用与原始采样相同深度测试的 ID pass 识别可见像素属于哪一组，别组已经占据的像素不可作为桥接路径。补点候选之间若竞争一个空像素，取候选几何的近侧深度。
- 新增像素颜色在桥接端点间以线性光插值重建，复用原始采样的实际材质结果；不是为每种材质再实现一套着色器。这是相对于旧叶片原型的明确变化：**已有像素不变，新增像素颜色可能与旧原型不同。**
- 连接阶段保留原来斜向接触的关系；逐条选补点数最少的桥，最后删除可移除的桥接像素。随后几何覆盖补回漏掉的投影区域，因此最终结果可能比最少桥接路径更厚。不是多区域连接的全局最优解保证。

## 边界与游戏验收

- 预览台负责单模型造型、材质、动画和像素规则的美术比较；游戏仍负责场景尺度、真实环境光、遮挡融合及实例规模下的 Release 性能验收。
- 浏览器和游戏的共享模型都固定使用**通用几何覆盖 + 八邻接补点**。浏览器用小图回读、ID pass、投影几何和高分辨率材质采样；游戏用当前姿态的几何／射线判定生成稀疏补点计划，GPU 对几何补点从所属模型三角形取实际材质／光照，不做生产图像回读。叶面／叶柄／叶背基色控制仍只在网页预览中，尚未同步到游戏着色。当前 **140 个网页样本的最终新增像素位置与 Rust 计划逐一对照通过**；游戏端 8/16/64 叶片与 8/22/64 蝴蝶真实 GPU 夹具通过。跨运行时只对齐形状覆盖，不承诺网页与游戏灯光颜色相同；实现与验证命令见[正式模型资源](../../assets/models/README.md)。大量实例性能仍需单独 Release 验收。
- 补点当前支持这里的**不透明几何**。未来透明贴图/alpha discard、GPU 自定义顶点变形需要扩展可见 ID 与几何投影约定，不能假装与现有通用流程自动等价。当前动画为 GLB 节点变换；几何采集使用 `getVertexPosition`，但没有另外验收蒙皮/形变资产。
- 所有投影三角形都允许保守覆盖，不覆盖已采到的像素或被其他组占据的中心格。浏览器新增颜色优先取同视角高分辨率材质采样，极细、连高分辨率采样都未命中的情况退回同组邻近颜色或模型基色；游戏 GPU 使用相应源三角形的材质、法线和环境光着色，不是精确的子像素材质积分。补点没有时间稳定滤波，旋转或动画时仍可能跳像素。亚像素缝隙与完全遮挡的判定不能只靠低分辨率几何投影精确重建。
- 不是建模编辑器、资产管理系统或任意文件上传查看器。新 GLB 通过一个模型定义接入；当前接入落叶、蝴蝶、苹果、8 种游戏共用花草和 2 种仅网页白花候选。

## 验证

快速确定性检查（Node 24，无依赖）：

```sh
node --test experiments/model-preview/tests/*.test.mjs
```

浏览器检查不进入 Cargo 测试套件。安装/使用已有 Playwright 后运行；脚本自建并关闭本地静态服务，Chrome 始终 headless：

```sh
# 若 Playwright 在其它位置，设置 NODE_PATH 指向该 node_modules。
node experiments/model-preview/tests/browser.cjs
node experiments/model-preview/tests/flowers-browser.cjs
node experiments/model-preview/tests/stems-browser.cjs
```

支持 `CHROME_EXECUTABLE`、`PREVIEW_ARTIFACT_DIR`。设置 `CHECK_REDIRECTS=1` 一并检查已迁移的旧入口跳转。默认工件在 `target/model-preview-validation/`。

花草专项验证输出到 `target/flower-study/validation/`（可用 `PREVIEW_ARTIFACT_DIR` 覆盖）：十种源模型 / 花头合成对照图、透明 PNG、桌面／手机截图、`summary.json`。覆盖全部花草的花头姿态样本、正交／透视、正背侧、8/32/64/128px、参数端点、源 RGBA 保留、GPU 深度、8 个前后遮挡夹具、重置与反复切换的资源计数。茎部 A/B 的十种植物对照图另由 `stems-browser.cjs` 输出到 `target/stem-preview/`。SwiftShader 深度核对按其 `SUBPIXEL_BITS` 对齐栅格顶点，避开三角形边界所有权歧义，不把 CPU 未量化投影误当 GPU 插值。

既有模型验证：

- Node 纯逻辑：对角接触不变、单像素斜线、156 面支持无 ID 回绕、不同组不互相缝合、原像素 RGBA 保持、静态/动态时间和所有 2–60 FPS 采样。
- Chrome / SwiftShader：模型切换与异步加载竞态、32/156 面、双向鼠标旋转/缩放、正交/透视、8–128 缓冲、分组补点与通用几何覆盖、共享动画、逐帧、HSV/HEX、无光照精确颜色、自阴影、线框不污染像素图、PNG。正面 32 像素叶柄、运动中的蝴蝶翼缘都检查漏采样后的结果，同时检查无补点开关、重置／切换模型都不能关闭覆盖。
- 1440×1000、1280×720、390×844 截图与无横向溢出；无页面异常、控制台 error、失败请求或外网资源。已查看两模型与手机截图。
- 迁移的原始中心采样曾与 **16 个叶片 + 24 个蝴蝶历史样本**逐字节核对一致。现在验证已有 RGBA 不变，并由所有可见三角形补全几何覆盖，不再只补指定叶柄。
