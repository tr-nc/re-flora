# 蝴蝶 v2：像素艺术检查与工程复验

2026-09-06。这是一次保留局限的原型交付，不是批准替换正式素材。图集、GLB、转台和本记录均来自本目录保存的同一份 `.blend`。原手绘与 v1 未修改。

## 结论

v2 的大色块、整体轮廓与协调升沉/俯仰比 v1 更清楚，主要运动不再只是固定身体上的双翼摆动。每侧前后翼已经合成连续的双叶外轮廓，消除第一轮模型内部重复的黑色分界，减弱“四片独立花瓣”的感觉。

但这并非所有艺术目标都达标：腹段跟随在三维源模型里成立，在最终 16px 的多数姿态中则被遮挡或量化掉；正面一个过渡姿态仍只有 3px 高。原手绘在小尺寸上的形状取舍和节奏仍有参考价值，本次没有以“模型可复现”取代对这些局限的判断。

## 实际看过的结果

- `atlas-128-rgba.png`：五角度、五共同相位的真实三维渲染。体态与前后翼始终来自同一几何和同一动画，非按角度重画。
- `atlas-16-blue-indexed.png` / `atlas-16-gray-indexed.png`：80×80，原生16px，查看原尺寸和最近邻放大。主体颜色是少量连续色块，没有用微型纹理补身份。
- `diagnostic-body-only-80.png`：身体升沉/俯仰在孤立渲染里改变轮廓，但黑色小身体在深背景上不醒目，不能仅凭存在五个三维姿态宣称身体每段都明显。
- `diagnostic-wing-only-80.png` / `diagnostic-no-abdomen-lag-80.png`：同一个模型、相机、调色板，真实禁用相应动画层后渲染，不是修改最终 PNG。导出时临时移除对应 animation action，防止 Blender 的渲染求值把手动置零覆盖；并断言诊断图确实不同。
- `turntable-frames/`：同一保存工程导出的真实三维帧。`blender-source-turntable.webm` 为256×256、VP9、15fps、4秒，60帧完整转台且拍翅四次；全部帧至少有12px外边距。

页面的原手绘 / v1 / v2 对照由主任务维护在 `../comparison-v2.html`。本执行者的浏览器工具没有可用的 IAB，未改用 Chrome；主任务负责该页面的实际浏览器交互验收。

## 动作层贡献：既看图，也测最终像素

以下是每格 16×16 完整 RGBA 像素的改变数，不是艺术评分。

| 方向 | 加入 body bob/pitch 后，5帧分别改变的像素 | 额外加入腹段 lag 后，5帧分别改变的像素 |
| --- | --- | --- |
| 0° | 18, 14, 56, 17, 26 | 0, 0, 0, 0, 0 |
| 45° | 19, 21, 47, 20, 29 | 0, 0, 0, 0, 0 |
| 90° | 20, 20, 42, 24, 34 | 0, 1, 2, 2, 0 |
| 135° | 18, 17, 41, 26, 37 | 1, 0, 1, 0, 0 |
| 180° | 16, 12, 34, 24, 40 | 0, 0, 0, 0, 0 |

因此，改善主要来自整个身体/翼组共同俯仰与升沉。腹段 lag 在侧向少数帧产生1–2px差异，不能宣称在所有方向都看得见。特别是当前游戏对应的45°/135°观察行，这部分收益很有限。保留两个可编辑的跟随段方便后续艺术决定，但本次不再为证明“有收益”无限增大振幅。

固定世界参考投影始终是画布(8,8)，有意运动的身体参考 y 为 8.1918、8.3452、7.5781、7.6932、8.3068；范围约0.767px。这个值来自模型的实际 flight 节点，而不是把翅膀面积造成的 alpha 质心移动误报成身体升沉。俯仰同时改变全体投影，所以最终轮廓动作大于这段单独升沉。

## 轮廓和循环的局限

- 每个方向都是5张不同的最终帧。前向最薄过渡姿态为30个不透明像素、3px高；后向最小42像素。相较 v1 最小8像素有所改善，但没有达到原手绘正/背最小53/54像素的丰满程度。两种输出的镜头和采样法不同，这不是等条件艺术评分。
- 侧向可能出现一侧翼面接近侧刃、另一侧翼面展开的姿态；这是固定镜头、同一三维模型的真实遮挡，不是丢帧或自动居中。是否需要进一步夸张，应由最终小图动势决定。
- 源动画在 t=0 与 t=1 的真实128px/16px输出完全一致，没有跳回另一姿态；五帧环回的像素变化也被记录。但5fps本身仍是离散节奏，不应拿25fps GLB连续播放掩盖它。
- 16px 仍有像素跳变。直接小分辨率采样减少了高分辨率下采样产生的半透明轮廓，但不会自动变成手工像素艺术。本次未进行逐格手工像素清理。

## 可复现验收

实际执行 `/usr/bin/python3 run.py`：重建源文件 → 保存 → 重新打开后导出GLB与原渲染 → 再次打开保存工程独立重渲染 → 拼图与验证 → 转台视频。

- 保存源工程复跑：128px、native16、native32，五角度×五帧共75张，全部逐像素一致。
- 外边界：上述75张四条最外边均全透明，没有裁剪；所有角度/帧使用同一2.95尺度，不做逐帧/逐方向重定位。
- GLB：一个0–1秒共享clip，5个动画节点、6条通道，包括 flight translation/rotation、两段 abdomen rotation、左右 wing rotation。
- 最终蓝色/灰色图集在16px/32px两套尺寸均为 indexed PNG，实际使用5个索引且 PLTE 恰5项（透明+4不透明），alpha值仅0/255。
- v1 `.blend`、GLB、创建脚本、运行脚本、蓝/灰16px图集的6个SHA-256与准备阶段记录逐项一致。
- 源文件/脚本/图集哈希、每格数据、回放结果见 `validation.json`；源参数见 `source-manifest.json`。

工程门槛通过，艺术结论为“整体动势和色块改善的候选，腹段可读性与最薄姿态仍待艺术取舍”，不是“尺寸正确即可上线”。
