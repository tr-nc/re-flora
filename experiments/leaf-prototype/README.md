# 落叶模型 / 像素画原型（throwaway）

## 要回答的问题

一片低面数、具有真实叶片轮廓与弯曲的模型，经过低分辨率采样后，是否值得替换游戏里的飘落叶片？先评审形态与像素效果，不接入游戏，不改落叶运动。

本原型保留在 `pretty-leaves` 实验分支。当前结论只是“交互候选可运行”；美术方向、像素密度与是否接入游戏均等待用户判断。不是生产渲染实现。

## 启动

在仓库根目录运行（需要 Python 3，浏览器支持 WebGL 2）：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory experiments
```

打开 <http://127.0.0.1:8765/leaf-prototype/>。不要直接以 `file://` 打开 HTML。

无需 npm 安装或联网；复用相邻蝴蝶实验已经纳入仓库的 Three.js 0.183.0 与 OrbitControls，其许可证见 `../butterfly-method-comparison/vendor/three-0.183.0/LICENSE`。静态服务应以整个 `experiments` 为根，而非仅本目录。

## 怎么看

- 左右画布共享模型、相机与光照。拖动任一画布旋转，滚轮或双指缩放；聚焦画布后方向键也能旋转。
- 正面、背面、侧面与重置按钮；可选自动转台。
- 28 个叶面三角形 + 4 个叶柄三角形，共 32 面、29 顶点。双面薄片，无体积厚度。线框仅显示在左侧。
- 可调宽度、主脉折起、叶尖卷曲、青绿到秋黄的颜色、叶脉强度、光源方位与近似透光。
- 右侧实际渲染缓冲为 8–128 的任意整数边长，默认 32 × 32，关闭 MSAA，整数 CSS 倍率最近邻放大。这个数指整张画布，不是叶子实际覆盖的像素数。
- 「保留细部覆盖（B）」为运行时 A/B 复选框：默认未勾选，A 保留原始中心采样；勾选后 B 采用三角形与像素格相交覆盖。只影响右侧，模型、相机、光照和分辨率不变。刷新或恢复默认会返回 A；临时设置不保存。
- 明暗色阶只量化右侧的受光明度，不是严格的全图调色板颜色数量；0 表示连续明暗。程序色差与微弱高光仍可产生额外颜色。
- 导出透明 PNG 保存当前原生 N × N 像素结果，不含背景或界面，文件名包含 `A-center` 或 `B-coverage` 以标识当前模式。
- 三个观察布局：`?variant=compare`（并排对照）、`?variant=model`（模型优先）、`?variant=pixel`（像素画放大）。底部箭头切换；参数仅保留在内存，不保存用户配置。

## B：保守覆盖实现

`coverage.js` 为每个源三角形生成屏幕空间包围矩形，在原生 N × N 缓冲中通过分离轴检验判定三角形与像素正方形是否相交。这不是先放大再缩小，也不是对已有像素图膨胀或补洞。仅用 0.0001 像素的容差处理边界接触；包围矩形向外取整，避免硬件子像素栅格提前漏掉候选片元。

新覆盖像素取三角形上距离像素中心最近的位置，以重心坐标获取 UV、法线、世界位置和深度，再调用与 A 相同的叶片着色函数。输出为硬边、不透明的覆盖像素；发生亚像素遮挡时按这个采样位置的深度竞争，不做面积混合。高清左图始终使用原始网格渲染。底部的 1/2/3 仅为观察布局，与覆盖模式 A/B 无关。

当前实现限于此原型的正交相机和固定近远裁剪范围；不要直接当作支持任意透视、近裁剪面穿越的通用游戏管线。绘制时有 32 个辅助矩形（64 三角形），并没有提高叶片模型的细分面数。尚无原生 GPU 或游戏 Release 性能数据，当前只做视觉对照。

## 已知边界

- 这是程序建模与程序材质，不是扫描叶片；透光为美术近似，不包含自阴影或真实散射。
- A 保留细叶柄与侧面叶尖可能断开、消失的原始表现；B 保留亚像素几何覆盖，代价是轮廓略粗，也可能合并小于像素的真实缝隙。B 不保证运动时完全不跳像素，没有做时间稳定滤波，也不会修补模型本身的真实缺口。
- 尚未模拟飘落、风、触地，也不代表 Rust/Vulkan 中的性能或最终色彩。
- 缩放允许放大到超出画布；可用“重置视角”恢复。

## 验证

- `node --check experiments/leaf-prototype/leaf.js` 与 `node --check experiments/leaf-prototype/coverage.js` 通过。
- A/B 临时脚本 `node /tmp/leaf-prototype-qa/coverage.cjs`：独立 CPU 多边形裁剪 oracle 与 B 的 GPU 覆盖遮罩做了 186 组逐像素对比（8/12/22/32/64/128 的正背侧视角，以及 22 像素下三组卷曲/折起参数各旋转一整圈），零差异。修复了初版辅助矩形在硬件子像素栅格上向内舍入导致的单像素漏覆盖。
- A 的 16 个预先保存视角/分辨率 PNG 与修改前逐字节一致。默认形态下 24 个分辨率/视角组合的 B 遮罩均为单个八邻接连通区域；默认 32 像素斜视角由 A 的两个区域变成 B 的一个区域。
- A/B 左侧高清模型截图一致，覆盖切换不改变相机或缩放；已验证返回 A、恢复默认、刷新重置、B 模式 PNG 文件名与导出，以及手机无横向溢出。A/B 验证无页面、控制台或资源请求错误；截图 `/tmp/leaf-coverage-{A,B,mobile}.png`。
- 通过临时 Playwright 脚本运行 Chrome headless / SwiftShader 检查：两个画布的鼠标旋转与滚轮缩放、8/12/16/22/32/64/128 原生缓冲尺寸、形态与材质滑块、左侧线框不污染右侧、正背侧视角、自动转台、三种布局与 URL、22 × 22 PNG 导出。
- 1440 × 1000、1280 × 720、390 × 844 页面截图与无横向溢出检查通过；检查了默认视角、侧面、手机布局截图。
- 上述独立浏览器验证无页面异常、控制台 error 或失败请求。最初浏览器工具的自动软件渲染回退发生过 WebGL context lost，截图工具也失败；改用显式 SwiftShader 的独立 Chrome 验证后未重现。原型在上下文丢失时提示刷新。
- 验证脚本与截图是本机临时工件（`/tmp/leaf-prototype-qa/`、`/tmp/leaf-prototype-*.png`），没有加入正常测试套件。
- 只修改实验 HTML/CSS/JS/说明；未修改 Rust、游戏 shader、生成文件或 `config/gui.toml`，故未运行 Cargo / 游戏验证。
