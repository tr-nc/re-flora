# 落叶模型 / 像素画原型（throwaway）

## 要回答的问题

一片低面数、具有真实叶片轮廓与弯曲的模型，经过低分辨率采样后，是否值得替换游戏里的飘落叶片？先评审形态与像素效果，不接入游戏，不改落叶运动。

本原型保留在 `pretty-leaves` 实验分支。当前结论只是“交互候选可运行”；美术方向、像素密度与是否接入游戏均等待用户判断。不是生产渲染实现。

## 启动

在仓库根目录运行（需要 Python 3，浏览器支持 WebGL 2）：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory experiments
```

打开 <http://127.0.0.1:8765/leaf-prototype/>。不要直接以 `file://` 打开 HTML。

无需 npm 安装或联网；复用相邻蝴蝶实验已经纳入仓库的 Three.js 0.183.0 与 OrbitControls，其许可证见 `../butterfly-method-comparison/vendor/three-0.183.0/LICENSE`。静态服务应以整个 `experiments` 为根，而非仅本目录。

## 怎么看

- 左右画布共享模型、相机与光照。拖动任一画布旋转，滚轮或双指缩放；聚焦画布后方向键也能旋转。
- 正面、背面、侧面与重置按钮；可选自动转台。
- 28 个叶面三角形 + 4 个叶柄三角形，共 32 面、29 顶点。双面薄片，无体积厚度。线框仅显示在左侧。
- 可调宽度、主脉折起、叶尖卷曲、青绿到秋黄的颜色、叶脉强度、光源方位与近似透光。
- 右侧实际渲染缓冲为 8–128 的任意整数边长，默认 32 × 32，关闭 MSAA，整数 CSS 倍率最近邻放大。这个数指整张画布，不是叶子实际覆盖的像素数。
- 「八邻接最少补点（B）」为运行时 A/B 复选框：默认未勾选，A 保留原始中心采样；B 仅修复几何支持的断点。斜向接触已经算连接，不补成拐角，不铺满保守覆盖区域。只影响右侧；已有像素 RGBA、模型、相机、光照和分辨率不变。页面显示连通区域数与补点数。刷新或恢复默认会返回 A；临时设置不保存。
- 明暗色阶只量化右侧的受光明度，不是严格的全图调色板颜色数量；0 表示连续明暗。程序色差与微弱高光仍可产生额外颜色。
- 导出透明 PNG 保存当前原生 N × N 像素结果，不含背景或界面，文件名包含 `A-center` 或 `B-connectivity` 以标识当前模式。
- 三个观察布局：`?variant=compare`（并排对照）、`?variant=model`（模型优先）、`?variant=pixel`（像素画放大）。底部箭头切换；参数仅保留在内存，不保存用户配置。

## B：八邻接最少补点实现

用户否定了 `70f54716` 中「所有相交像素格都填上」的旧 B：这会把合理的斜向连接变成粗拐角。新目标是保留原始像素轮廓，只连接真正断开的可见片段。

1. 先照常绘制 A，读取原生 N × N 缓冲的 alpha。已有的八邻接区域（包含斜向）就是连接起点；已经连通时不增加任何像素。
2. `connectivity.js` 对投影三角形做像素格相交检验，记录每格的三角形支持位集。保守覆盖只是候选范围，不是最终填色范围。路径的相邻两格必须有共同的源三角形支持，不能仅因两个独立形状的覆盖格挨着就跨过去。
3. 多源广度搜索寻找补点数量最少的一条八邻接桥接路径，合并区域后重复；再删除任何可以单独移除而不影响连通性的新增像素。这里的「最少」指逐条最短桥接与最终局部不可再删，不声称求出了多个区域的全局最优 Steiner 树。
4. 把仅含新增像素的遮罩传给 `coverage.js`。沿用保守栅格化着色，但只绘制遮罩内的补点；不清除原图，也不重画 A 的已有像素。新像素在三角形最近位置采样 UV、法线、世界位置和深度，使用相同的叶片着色函数。

默认 32 像素斜视角：A 为 131 个像素、两个连通区域；旧 B 填满 159 个像素；新 B 只补 1 个像素便连接叶柄，合计 132 个像素。

**原型成本边界：**当前连接判定在 CPU 执行，每次 B 更新同步读取一次小尺寸 GPU 缓冲，必要时额外绘制一次补点。这是明确标记的视觉实验实现，不是已验证低成本的游戏管线；接入大量落叶前需重新设计/测量 GPU 实现和同步成本。没有原生 GPU 或游戏 Release 性能结论。

当前实现限于本原型的 32 个源三角形、正交相机和固定近远裁剪范围。补点绘制仍使用 32 个辅助矩形（64 三角形），未提高叶片模型的细分面数。高清左图始终使用原始网格；底部的 1/2/3 仅为观察布局，与覆盖模式 A/B 无关。

## 已知边界

- 这是程序建模与程序材质，不是扫描叶片；透光为美术近似，不包含自阴影或真实散射。
- B 只连接已经被 A 采到的片段，不恢复完全没有采样点的叶柄末端、尖端或整片叶子；输入完全为空时也保持为空。这是避免全面加粗的明确取舍。
- 没有几何支持的桥接路径时保留分离区域，不强行粘合。小于一个像素的真实间隙、投影重叠和遮挡仍存在表示歧义；三角形位集不是通用三维拓扑/遮挡分析器。
- B 没有时间稳定滤波；运动过程中采样点与最短路径仍可能跳变，不保证完全消除闪烁。
- 尚未模拟飘落、风、触地，也不代表 Rust/Vulkan 中的性能或最终色彩。
- 缩放允许放大到超出画布；可用“重置视角”恢复。

## 验证

- `node --check` 检查 `leaf.js`、`coverage.js`、`connectivity.js` 通过。
- `node /tmp/leaf-prototype-qa/connectivity-fixtures.mjs`：9 个确定性案例通过，包括两个方向的对角接触完全不变、缺一个像素的斜线仅补中央格、长斜线保持一像素宽、独立几何不粘合、空输入、单像素、沿弯曲几何绕行及多三角形支持。
- `node /tmp/leaf-prototype-qa/connectivity-browser.cjs`：186 个视角组合通过（8/12/22/32/64/128 正背侧视角，以及 22 像素下三组卷曲/折起各旋转一整圈）。逐像素确认 A 的 RGBA 不变，所有新增像素都在独立多边形裁剪 oracle 给出的几何覆盖内，最终新增像素均无法单独删除而保持相同连通性；有断点的案例均修复为单个区域。
- 其中 139 个原本连通或空的案例，B 的 PNG 与 A 完全一致；16 个 A 基线 PNG 与最初版本逐字节一致。默认 32 像素仅补 1 个像素；22 像素侧面三个片段仅补 4 个像素连成一体。
- 左侧高清截图保持一致；已验证切换不改相机/缩放、默认关闭、重置/刷新、`B-connectivity` PNG、自动转台及手机无横向溢出。无页面、控制台或资源请求错误；已查看默认 B 截图，工件 `/tmp/leaf-connectivity-{A,B,mobile}.png`。
- 通过临时 Playwright 脚本运行 Chrome headless / SwiftShader 检查：两个画布的鼠标旋转与滚轮缩放、8/12/16/22/32/64/128 原生缓冲尺寸、形态与材质滑块、左侧线框不污染右侧、正背侧视角、自动转台、三种布局与 URL、22 × 22 PNG 导出。
- 1440 × 1000、1280 × 720、390 × 844 页面截图与无横向溢出检查通过；检查了默认视角、侧面、手机布局截图。
