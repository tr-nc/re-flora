一个屏幕像素，应该取什么颜色？

先拖动采样点，拆开看 Bilinear 的四个权重；再让同一张纹理移动、旋转、缩小，对照五种采样，并拆开看 Trilinear 的 mip 层混合。

01 / 拖动白色十字：Bilinear 怎么算？

圆点是纹素中心。A/B/C/D 是参与插值的四个邻居。也可用方向键或右侧滑块调整。

不是四格一律取平均：越靠近某个中心，它的权重越大。先横向混合两行，再纵向混合，就是双线性插值。

这里用纹素中心坐标：整数就是中心。GPU 常用 UV 时，x = u × 宽度 − 0.5，y = v × 高度 − 0.5。

02 / 同一张纹理，五种取样方式

Nearest / 最近邻

选最近的 1 个纹素。保留原色和硬边，但跨过边界时会突然换色。

Bilinear / 双线性

附近 2×2 共 4 个纹素加权。过渡连续，但边缘变软；缩小时仍可能闪。

Trilinear / 三线性

相邻两个 mip 层各做 Bilinear，再按 LOD 的小数部分混合。第三个线性方向是层级，不是时间。

Bicubic / 双三次

这里用 Catmull–Rom，附近 4×4 共 16 个纹素。有负权重，可能更锐，也可能出现亮边/暗边（过冲）。

面积采样 / 8×8

在每个输出像素覆盖的纹理区域内取 64 个点求平均。缩小时更稳，但细枝会变淡；这是近似抗混叠，不是另一种点插值。

重点试第③项：一个输出像素覆盖很多纹素时，Bilinear 依然只看附近四个，不会自动统计整个覆盖区域。实际 GPU 通常还需要 mipmap；斜视时常结合各向异性过滤。

03 / Trilinear：两层各算一次，再混合

十字对应第①区的同一个采样点（相同 UV），框线标出每层 Bilinear 的四个邻居；这不是第②区对照图的平移控制。试着把 LOD 从 0 拖到 1，再到 2，观察两层的权重交换。

Trilinear 结果

手动 LOD 只改变 Trilinear，对照中的 Bilinear 始终采样原图 L0。自动模式下，本页均匀缩放的 LOD = clamp(log₂(1 / 缩放), 0, 4)。放大时退回 L0；真实 GPU 通常由纹理坐标的屏幕导数估计 LOD。这里没有各向异性过滤，也不保证完全无闪烁。

它回答什么，不回答什么？

这是 CPU 数学实现的二维纹理重采样，不是 GPU 性能测试，也不是茎的 3D 稳定性方案。这里的旋转是纹理平面旋转，不是相机原地转头。让表面颜色更平滑，不等于保证细茎几何轮廓不会消失。

所有方法共用同一坐标变换和 96×96 输出，再用最近邻放大展示，避免浏览器二次平滑掩盖差异。“放大中心”仅裁出中心 24×24 输出像素，不改变采样计算。纹理为不透明线性 RGB，在线性空间计算后编码为 sRGB 显示；边界使用 clamp-to-edge。Bicubic 的过冲只在最终显示时截断。面积采样不是精确积分。Trilinear 使用真实生成的 mip 链，但全页没有实现各向异性过滤。
